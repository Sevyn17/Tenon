# 05 定位与命名方案

> 状态：已执行（2026-11-04，3.2 目录与包、3.3 标识符、术语统一）。3.2 中 `ext/`、`modules/internal/*` 与 3.4 的逻辑性归属调整随审查 P1 修复做，未在搬迁里做。与提案的出入：`appapi` 放在模块根 `appapi/` 而不是 `apps/internal/appapi`——SDK 在模块根，Go 不允许它 import `apps/internal/` 下的包。依据：[01 总览与边界](<框架设计/01 - 总览与边界.md>)、[04 核心与扩展模块清单](<04 - 核心与扩展模块清单.md>)、[计划/04 设计质量审查](<计划/04 - 设计质量审查（2026-11-04）.md>)。

## 一、定位：框架，内核是运行时

两者不是二选一。YBase 是**智能体框架**，它的不可替换部分是一个**智能体运行时**：

| 层 | 是什么 | 类比 | 谁调用谁 |
|---|---|---|---|
| **运行时内核**（Runtime） | 定义 → 会话 → 信封 → 步进 → 检查点 → 恢复；守卫、租约、发件箱、工具与模型调度 | Erlang VM / Temporal Server | 不被应用直接拼装，只通过扩展点和 SDK 暴露 |
| **扩展模型**（Extension model） | 组件接口、点位、服务、`[use.*]` 配置 | Spring 容器 / Django app 协议 | 组件向内核登记 |
| **标准模块**（Standard modules） | 官方组件：模型适配、上下文、权限沙箱、工具、协作、钩子 | Django contrib / Spring Boot starters | 只走公开扩展点，可选、可替换 |
| **SDK** | `ybase.New / Default / With / Ask`，测试套件 `ybasetest` | FastAPI 的 `FastAPI()` | 应用调用 |
| **应用**（不属于框架） | CLI、桌面、Web 服务 | 用框架写的产品 | 引用 SDK |

一句话：**YBase 是一个 Go 智能体框架；它的核心 YBase Runtime 负责让有状态的智能体会话可靠地跑、崩了能接着跑；能力由可插拔的标准模块提供。**

判断"它是框架"的依据（代码里已经成立）：控制反转（应用写组件和定义，框架驱动循环）、装配期依赖注入（`Requires/Provides`）、预设（`Default/Minimal`）、测试套件。判断"核心是运行时"的依据：会话 actor、租约 fencing、检查点事务、至少一次发件箱、崩溃恢复都在 `core/`，且不依赖任何模块（`core/runtime/deps_test.go` 强制）。

## 二、现在名字的问题

| # | 问题 | 证据 |
|---|---|---|
| N1 | 同一层四种叫法：内核 / 核心 / 框架 / 框架 | 框架设计各篇混用；README 叫"本地智能体内核与 CLI" |
| N2 | 目录叫 `plugins/`、包叫 `plugin`，但设计已定"内置的叫组件，插件专指外部 Node/Python 进程"（A11，00 索引"和现有文档的对应"） | `plugins/**`、`core/plugin`、`component.Register` |
| N3 | 模块名 `ybase-kernel`、目录 `kernel/`，实际装的是整个框架（内核 + 模块 + SDK + 应用） | `go.mod:1` |
| N4 | `core/runtime` 包名与标准库同名，25 处靠 `kr` 别名导入，hooks/shell/sandbox 还同时导入标准库 runtime | 审查 ASM-L1 |
| N5 | SDK 是库却放在 `apps/ybase-sdk`，包名 `ybase` 与目录不一致；`ybasetest` 也是库却在 `apps/` | 审查 ASM-M8 |
| N6 | 组件名 / 包名 / 文件名不一致：`code-mode` / `codemode` / `ptc.go` / `Package ptc`；`compact-basic` / `compactbasic` / `// Package compact` | 审查 MB-C2、MA-C5 |
| N7 | 几个包放错层：`appapi`（CLI/桌面的命令协议）、`pkgs` 里写死 4 个模块的配置形状、`modelhub/providers.go` 的厂商目录与 Ollama 探测都在 `core/` | 审查 ASM-M12、ASM-L5 |

## 三、命名方案

### 3.1 术语（文档与代码统一）

| 用这个 | 不再用 | 含义 |
|---|---|---|
| **框架**（YBase） | 框架 | 整个产品：运行时 + 扩展模型 + 标准模块 + SDK |
| **运行时**（YBase Runtime），行文简称**内核** | 核心、框架内核 | `runtime/` 目录下的不可替换部分 |
| **组件**（Component） | 标准模块、插件 | 编进同一程序、实现组件接口的单元 |
| **模块**（Module） | — | 组件的分组单位 / 目录（一个模块可含多个组件），如"上下文模块" |
| **标准模块** | 标准模块 | 官方提供的模块 |
| **插件**（Plugin） | — | 只指外部进程扩展（A11，v1 未实现） |
| **扩展点**：点位（Point）/ 服务（Service）/ 插槽（Slot） | — | 不变 |

### 3.2 目录与包

```
kernel/  → 仓库目录暂不改（脚本、演示、外部引用都指向它）；go.mod 模块名改 ybase
  ybase.go, app.go …        package ybase        ← apps/ybase-sdk/*
  ybasetest/                package ybasetest    ← apps/ybasetest/
  runtime/                  运行时内核            ← core/
    session agent host mail store toolhub modelhub
    inject callctx bus reqlog agentdef useconf pkgs
    component/              package component    ← core/plugin（组件登记、装配、Profile、Registrar）
    assemble/               package assemble     ← core/runtime（会话构造器、点位与服务常量）
    ext/                    package ext          新：点位 / 服务 / 插槽常量与类型化键（ASM-M2/M3）
  modules/                  标准模块              ← plugins/
    model/ context/ security/ tools/ collab/ extend/ storage/
    internal/proc           新：argv 选择、进程树、商店版 pwsh 检测（shell/hooks/mcp 共用，MB-X2）
    internal/cmdline        新：命令拆分与安全前缀（shell/permission 共用，MB-S3）
    internal/xpath          新：projectRoot / clipUTF8 / fileExists（instructions/skills/permission 共用）
  apps/
    ybase/ desktop/ server/
    internal/boot/
    internal/appapi/        ← core/appapi（CLI/桌面/服务的命令协议，不属于内核）
```

`modules/internal/*` 是 Go internal 包：同一棵 `modules/` 下的组件都能用，不算"组件之间互相 import"，不违反 `deps_test.go` 的规则（规则要同步改成允许 `modules/internal`）。

### 3.3 标识符

| 现在 | 改为 | 备注 |
|---|---|---|
| `plugin.Plugin` / `component.Register` / `plugin.Meta` | `component.Component` / `component.Register` / `component.Meta` | SDK 的 `ybase.Component` 直接别名它 |
| `component.Registrar` / `plugin.Scope` / `component.Assembly` / `plugin.Profile` | `component.Registrar` / `Scope` / `Assembly` / `Profile` | 只换包名 |
| `kr "ybase-kernel/core/runtime"` | `ext`（常量）+ `assemble`（Builder） | 去掉 `kr` 别名 |
| profile.toml `[[plugin]]` | `[[component]]`，旧键继续认一个大版本 | 用户文件兼容 |
| 组件名 `code-mode` | 不改（是外部可见的配置键）；包 `codemode`，删掉 `ptc` 叫法 | 外部名不动，内部名统一 |
| `compactbasic` 包注释 `Package compact` | `Package compactbasic` | |
| 各插件注释"（核心，缺省开）" | "（标准模块，缺省开）" | 与清单一致 |

外部可见的名字（组件名、`[use.<组件>]`、事件名、appapi 命令名、存储表名）**一律不改**，避免破坏已有定义包和数据库。

### 3.4 归属调整（随重命名一起做的只有搬目录；逻辑改动进审查修复）

| 东西 | 从 | 到 | 理由 |
|---|---|---|---|
| `appapi` | `core/` | 模块根 `appapi/`（已搬） | 应用协议，不是内核（07 7.7 已定"薄适配"）；SDK 要 import 它，不能放 `apps/internal` |
| `modelhub/providers.go`、`builtin.toml`、`DiscoverOllama` | `core/modelhub` | `modules/model/models` | 唯一使用者是 models 组件 |
| `host.ExplainTrace` | `core/host` | `appapi/` | 纯渲染，与宿主无关 |
| `host` 里的"批准"中英词表 | `core/host/human.go` | 应用 / UI | 产品策略 |
| `pkgs` 里 mcp/hooks/skills/prompt 的配置形状 | `core/pkgs` | 各自模块解码 | 内核只解析包目录和通用元数据 |
| 缺省授权层（"一律询问"） | 无 | `runtime/toolhub` 插槽缺省 | 修 `Minimal()` 起不来（审查 P0-7） |

## 四、执行方式

1. 一次提交只做机械搬迁：`git mv` + 改 import 路径 + 改包名，`go build ./... && bash scripts/ci.sh` 全绿，行为零差异。
2. 第二次提交改术语：文档全文替换（框架→框架、标准模块→组件）、包注释、README。
3. 归属调整中涉及逻辑的（缺省授权层、pkgs 解码下放、类型化键）放进审查修复，不和搬迁混在一起。
4. 搬迁前确认没有其他会话在改这些目录（重命名会让并行改动全部冲突）。

估算规模：约 190 个 Go 文件改 import，约 40 篇文档改术语；纯机械，回滚就是 `git revert`。

# 多轮与流式

接着上一篇：同一个会话接着聊、逐字输出、处理确认。

## 多轮

```go
s, err := app.NewSession(ctx, "", tenon.Meta{"user": "u1"}) // 名字为空按缺省规则选
r, _ := s.Send(ctx, "我的订单 A1 到哪了？")
r, _ = s.Send(ctx, "那 A2 呢？") // 同一个会话，模型记得上一句
```

- `NewSession` 只是准备，第一次 `Send` / `Stream` 时才真正建会话；`s.ID()` 现在就能取到，可以先存下来。
- `meta` 写进会话的业务 meta，工具里用 `tenon.CallInfoFrom(ctx).Meta` 读。
- 找回已有会话：`s, err := app.Session(ctx, id)`，找不到返回 `tenon.ErrNotFound`。
- 同一个会话同时只跑一轮，后来的 `Send` 排在前一轮之后。
- `s.History(ctx)` 读全部条目，`s.Cancel(ctx)` 取消进行中的一轮。`ctx` 取消也会取消这一轮。

`app.Ask(ctx, name, text, meta)` 等于 `NewSession` 加一次 `Send`。

## 流式

```go
for ev := range s.Stream(ctx, "帮我退掉 A2") {
    switch ev.Kind {
    case tenon.EventText:
        fmt.Print(ev.Text)
    case tenon.EventReset: // 模型重试：丢掉这一步已经打印的正文
    case tenon.EventToolCall:
        fmt.Printf("\n[调用 %s %s]\n", ev.Tool, ev.Args)
    case tenon.EventToolResult:
        // ev.Text 是结果预览，ev.Failed 表示失败
    case tenon.EventConfirm:
        ev.Approve(true) // 见下一节
    case tenon.EventDone:
        // ev.Reply.Text 是完整回答
    case tenon.EventError:
        log.Print(ev.Err)
    }
}
```

最后一个事件一定是 `EventDone` 或 `EventError`。提前 `break` 会取消这一轮。

事件和前端看到的是同一份：都来自协议层发到总线上的流式事件。

## 确认

标了 `.Dangerous()` / `.Writes()` 的工具、`shell` 这类内置工具，按权限档位可能要人确认。

- `Stream`：交出 `EventConfirm`（带 `Tool`、`Args`、`Reason`），用 `ev.Approve(true/false)` 回答。不回答就一直等到 `confirm_deadline`。
- `Send` / `Ask`：调用方没法回答，所以没有 `WithProtocolUI` 也没有 `WithUI` 时确认立即拒绝，模型会收到"用户拒绝了这次调用"，这一轮正常结束。给了其中一个时由它回答。

要在 `Send` 里也让人确认，改用 `Stream`。

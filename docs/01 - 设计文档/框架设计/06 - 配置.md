# 06 配置

> 状态：草案（2026-11-01）。相关：[03 智能体定义](<./03 - 智能体定义.md>)、[04 扩展模型](<./04 - 扩展模型.md>) 4.2。

## 6.1 三层配置

| 层 | 写在哪 | 谁写 | 管什么 | 何时生效 |
|---|---|---|---|---|
| 装配 | `tenon.New(...)` 的 Go 代码 | 应用开发者 | 装哪些组件、用哪个存储、哪个模型供应商、覆盖哪些服务 | 启动时，改了要重启 |
| 组件配置 | 配置文件 `tenon.toml` 的 `[<组件>]` 段，或环境变量 | 运维、部署者 | 组件在整个进程里的默认行为：连接串、并发数、默认限额 | 启动时；组件声明可热更的字段除外 |
| 使用配置 | 定义包 `agent.toml` 的 `[use.<组件>]`，再叠租户、用户配置（6.3） | 写定义的人；租户、用户只能改标了 `tenant` 的字段 | 某个会话对这个组件的用法 | 创建会话时算好存进会话；定义变了只影响新会话；会话迁到定义新版本时按新定义重算（03 3.4） |

装配只能用代码，不提供"用配置文件选组件"。原因：组件是代码依赖，用配置文件选会让"写了但没编进来"在运行时才暴露。

## 6.2 组件声明配置结构

组件用 Go 结构体声明两份结构，框架据此生成 JSON Schema、校验、生成文档：

```go
type MemoryConfig struct {                       // 组件配置：[memory]；数据走框架存储（05），不自带连接串
    TTL     time.Duration `toml:"ttl" default:"720h"`
    MaxSize int           `toml:"max_size" default:"1000" hot:"true"`
}

type MemoryAgentConfig struct {                  // 使用配置：[use.memory]
    Store string `toml:"store" required:"true"`
    By    string `toml:"by" enum:"user,tenant,session" default:"user"`
}

func (m *Memory) Setup(r *tenon.Registrar) error {
    r.Config(&MemoryConfig{})
    r.AgentConfig(&MemoryAgentConfig{})
    return nil
}
```

标签：

| 标签 | 含义 |
|---|---|
| `default` | 缺省值 |
| `required` | 必填，缺了加载失败 |
| `enum` | 可选值 |
| `env` | 可由环境变量覆盖 |
| `secret` | 不进日志、不进 `explain` 输出、不进请求记录，显示为 `***` |
| `hot` | 运行中可改，改后组件收到通知；没标的字段改了要重启 |
| `tenant` | 允许租户层和用户层覆盖（6.3） |
| `limit` | 限制类字段：`limit:"min"` 各层取最小值，`limit:"intersect"` 各层取交集，不按覆盖算（6.3） |

不认识的键一律报错，防止拼错键名后"以为生效"。

键名优先取 `toml` 标签；没有时退回 `cfg`（历史组件的写法）。过渡期两者都认，新组件一律写 `toml`：定义包里写的就是 TOML，标签和文件用同一个名字，少一层翻译。

使用配置的字段表由 `runtime/useconf` 从原型读出（`SchemaOf`），链式合并与取严在 `Resolve`，落到会话行的形态是 `{"<组件>": {...}}`（`EncodeAll`）。组件在装配期用 `r.AgentConfig(&MemoryAgentConfig{})` 登记，运行期用 `*Ctx.Config("memory", &cfg)` 取自己那份（04 4.4）。

## 6.3 覆盖顺序

配置分两条链，互不混合（D8）。从低到高：

```
组件配置：组件缺省值 < tenon.toml < 环境变量                 启动时算好，定义和用户都改不了
使用配置：组件缺省值 < 定义 [use.*] < 租户配置 < 用户配置      创建会话时算好，存进会话
```

- **组件配置**管组件在整个进程里的行为（连接串、并发数、默认限额），只由部署者写。定义、租户、用户都不能改它，避免一份定义改掉全进程的连接或上限。
- **使用配置**管某个会话怎么用这个组件。创建会话时按链算好存进会话，组件通过 `*Ctx.Config()` 读取（04 4.4）。会话运行中不再重算，定义或租户配置变了只影响新会话。唯一的例外是应用把会话迁到定义的新版本（03 3.4）：迁移时按新定义把整条链重算一次。
- 租户和用户配置由应用通过 `ConfigSource` 接口提供（例如从应用自己的数据库读），只能覆盖标了 `tenant` 的字段，两层用同一个标签。用户层取**会话创建者**，不是本轮触发者，所以同一个会话的配置不随发送者变化。
- 用户层不能设置定义的内核字段，`resident` 也不行；用户层定义同样不能声明 `resident = true`（03 3.5）。
- **限制类字段不按覆盖算，按取严**：预算、权限、工具白名单、可联系名单，各层取交集或最小值。定义写 `tokens_per_day = 1000000` 也超不过租户上限。哪些字段算限制类由组件用 `limit` 标签声明（6.2）。会话里存的是创建时的取严结果。守卫每一轮再按本轮触发者的上限取一次：`limit:"min"` 取最小，`limit:"intersect"` 求交（08 8.3）。
- `[use.permission]` 是上限，不是授权。它只能把会话能用的权限再收窄，每轮实际生效的权限是它和本轮 `caps` 的交集（08 8.3）。permission 组件登记了这份使用配置（`mode`），2026-11-02 起与会话档位、`caps` 一起生效（08 8.3）。
- 最终值和每个值来自哪一层，`explain config <智能体>` 能列出来。

```go
type ConfigSource interface {
    Tenant(ctx context.Context, tenant, component string) (map[string]any, error)
    User(ctx context.Context, tenant, user, component string) (map[string]any, error)
}
```

## 6.4 密钥

- 密钥只从环境变量或应用提供的 `SecretSource` 取，配置文件里写引用：`api_key = "secret:openai"`。
- 定义包里不能写密钥，加载时发现 `secret` 字段有字面值就报错。定义包会被复制、分享、存进数据库，不适合放密钥。

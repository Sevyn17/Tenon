# 03 智能体定义

> 状态：草案（2026-11-01）。索引见 [00 - 索引](<./00 - 索引.md>)。

## 3.1 原则

- 定义只回答三件事：用什么模型、按什么提示词、能用哪些工具。记忆、协作、预算、定时唤醒等能力都是"挂一个组件，给它一段配置"。
- 定义以 Go 结构体 `tenon.Agent` 为准（B5）。TOML 文件、数据库记录、应用代码只是三种加载方式，最后都变成这个结构体。只维护一套格式，类型检查、补全、单测都直接可用。
- 内核字段封闭，扩展位开放。内核只认 6 个字段；`use.*`、`x.*`、定义包里的文件是开放的。

## 3.2 三类字段

```go
type Agent struct {
    // ① 内核字段：固定 6 个，所有应用都一样
    ID          string
    Description string   // 别的智能体把它当工具用时，工具描述取这句
    Model       string   // 模型或档位：fast / strong
    Prompt      string   // 内联文本，或 "@AGENT.md" 指向包内文件
    Tools       []string // 工具白名单，支持通配；解析成具体工具集合后作为信封 caps 的上限
    Resident    bool     // 常驻：每个租户只有一个该智能体的会话（02 2.2）；T5 之前为 true 时加载报"未支持"

    // ② 组件字段：key 是组件名，结构由组件声明，装了该组件才能写
    Use map[string]any

    // ③ 应用字段：内核和标准组件都不看，原样保存，应用自己的组件读取
    X map[string]any

    // 由框架填写
    Format  string // 定义包格式版本，如 "tenon/v1"
    Version string // 整包内容哈希
    Files   FS     // 定义包里的其他文件
}
```

| 类别 | 谁定结构 | 谁读 | 写错了会怎样 |
|---|---|---|---|
| 内核字段 | 框架 | 内核 | 加载时报错 |
| 组件字段 `use.<组件>` | 组件声明配置结构（Go 结构体，自动生成 JSON Schema） | 该组件 | 组件没装、字段不在结构里、类型不对，都在加载时报错，防止"写了以为生效" |
| 应用字段 `x.<命名空间>` | 应用 | 应用的组件或界面 | 框架不校验；应用可以给自己的命名空间注册 Schema，让框架顺带校验 |

### 为什么只有 6 个

| 曾考虑的字段 | 现在怎么表达 |
|---|---|
| 版本号 | 整包内容哈希，框架自动算 |
| 记忆 | `[use.memory]`、`[use.compact]` |
| 对外接口 | `description` + agent 组件自动生成工具 |
| 可以联系谁、可以派生谁 | `[use.agent] spawn / contact`，由 agent 组件注册给守卫 |
| 生命周期（临时 / 会话级 / 常驻） | `resident` 一个布尔值 + 所属树回收 |
| 预算 | `[use.budget]` |
| 权限 | `[use.permission]`，由 permission 组件解释，是这个定义的权限上限，经 Guard 交给守卫与 `caps` 做交集（08 8.3）；不是内核字段。T1 只声明，T3 再与 `caps` 求交 |

规则：**配置写在组件里，强制执行在内核守卫里**。例如 `use.agent.contact` 由组件解释，但"不在名单里就不能投递"由守卫保证，模型绕不过去。

## 3.3 定义包

定义是一个目录（B4），不是单个文件：

```
agents/support/
  agent.toml     # 内核字段 + [use.*] + [x.*]
  SOUL.md        # 性格、口吻
  AGENT.md       # 工作规则
  faq/…          # 任意文件
```

```toml
format      = "tenon/v1"
id          = "support"
description = "回答订单和售后问题"
model       = "fast"
prompt      = "@AGENT.md"
tools       = ["order_query", "ask"]
resident    = false               # true：每租户一个会话，id 固定为 resident:<租户>/support（02 2.2）；T5 之前报"未支持"

[use.context]
files  = ["SOUL.md", "AGENT.md"]   # 按顺序注入
memory = ["USER.md"]               # 从记忆组件按当前用户取

[use.memory]
store = "memlib"
by    = "user"                     # 按本轮触发者分区（04 4.4）

[use.budget]
tokens_per_day = 200000

[x.shop]
display_name = "小布"
avatar       = "https://…"
```

要点：

- **内核不认识任何文件名**。哪些文件注入上下文、按什么顺序，由 context 组件的配置决定。以后加 `STYLE.md`，放进目录、在 `files` 里加一行即可。
- **属于定义的文件放包里，属于用户的数据放记忆组件**：

| 文件 | 属于谁 | 谁能改 | 放哪 |
|---|---|---|---|
| `AGENT.md` | 定义 | 写定义的人 | 定义包 |
| `SOUL.md` | 定义 | 写定义的人 | 定义包 |
| `USER.md` | 每个用户一份 | 智能体在对话中更新、用户可改 | 记忆组件，按用户分区 |

`USER.md` 不能进定义包：一个定义服务一百万个用户，每人一份，而且是运行中写的。分区用的用户由内核填进 `*Ctx`（04 4.4），模型改不了，也就读不到别人的。

## 3.4 版本

- `Version` = 整包（`agent.toml` + 所有文件）规范化后的内容哈希。改了 `SOUL.md` 就是新版本。规范化：文件按路径字典序；不含 NUL 字节的文件把 CRLF 换成 LF，含 NUL 的按原始字节；每个文件依次写入路径长度、路径、内容长度、内容，取 sha256（`runtime/agentdef.Hash`）。
- 会话创建时记下定义版本。已有会话继续用旧版本，新会话用新版本；应用可以显式把会话迁到新版本，迁移时按新版本重算使用配置。
- 存储里保留会话还在用的旧版本内容，没人用了再回收。
- `Format` 是定义包格式本身的版本（类似 Kubernetes 的 `apiVersion`）。格式升级时框架提供转换器，旧格式能读、能自动升级。

## 3.5 定义来源

应用实现一个接口，告诉框架定义从哪来：

```go
// 代码在 runtime/agentdef：Scope、Ref、Source
type SpecScope struct {
    Tenant string
    User   string // 为空时只看平台和租户层；用户层定义归属于租户，全名 user/<用户>/<名字> 的租户取自 Scope
}

type SpecRef struct {
    Namespace Namespace // Platform / Tenant / User
    Tenant    string    // 平台层为空
    User      string    // 只有用户层有
    Name      string
}

type SpecSource interface {
    List(ctx context.Context, scope SpecScope) ([]SpecRef, error)
    Load(ctx context.Context, ref SpecRef) (Agent, error)
    Watch(ctx context.Context, scope SpecScope) (<-chan SpecChange, error) // 可选
}
```

框架自带三种实现：

| 来源 | 适合 |
|---|---|
| `specs.Dir("agents/")` | 桌面版、本地开发 |
| `specs.Store()`：定义包存进 `definitions` 表 + blob | SaaS，用户在界面上自建智能体，不依赖文件系统 |
| `specs.Code(tenon.Agent{...})` | 应用在代码里直接写，便于单测 |
| 插件包的 `agents` 字段（T4d） | 指向包目录内一个 `agentdef.Dir` 布局的子目录，定义按目录布局归入上面三层，不新增命名空间。同名时用户级包优先于项目级包 |

定义按命名空间区分，**不叠加、不覆盖**（D7）：

| 命名空间 | 标识 | 谁写 | 谁能用 |
|---|---|---|---|
| 平台 | `<名字>` | 应用随程序发布；组件经 `Registrar.Template` 带来的定义也归这里 | 所有租户 |
| 租户 | `<名字>` | 租户管理员，经应用鉴权 | 本租户；与平台定义同名时以租户定义为准，整份替换，不做字段合并 |
| 用户 | `user/<用户>/<名字>` | 用户本人，经应用鉴权 | 只有本人；放在独立命名空间，覆盖不了平台、租户定义 |

`SpecRef` 带命名空间（平台 / 租户 / 用户），`List` 按 `SpecScope` 里的租户和用户返回可见的定义。

名字解析：

- 裸名 `agent:<名字>` 只按 租户 → 平台 解析，不查用户层。否则用户层的同名定义会遮住平台定义，违反 D7。
- 用户层定义必须写全名 `agent:user/<用户>/<名字>`，且只有本人能解析。模型只能解析本会话创建者自己的用户层定义。
- 全名只在 SDK 和地址里使用，界面可以显示短名。
- `Registrar.Template` 带来的定义与应用的平台定义同名时，启动报错。

**权限不靠合并收窄，靠拒绝和求交**：

- 用户新建或修改定义时，写定义接口检查 `tools` 和 `[use.permission]` 是否超出创建者自己的有效权限。超出就拒绝保存，报错列出超出项，不静默截断。
- 只在写定义接口上拒绝。已保存的用户层定义，在创建者之后被降权时加载不报错，由运行时求交兜底。否则一次降权会让这个用户的所有定义都加载失败。
- 运行时每轮再与本轮触发者的权限求交（08 8.3）。所以别人调用一个用户定义，也拿不到超出自己权限的工具。
- 预算、并发等限制类字段受租户和用户上限约束，超限时保存被拒绝。用户层定义不能设 `resident = true`。
- 创建者的有效权限要等使用配置链（06）算出来，所以越权拒绝排在 T1b，使用配置链之后。

`[use.*]` 的生效值不在定义来源里合并，而是按使用配置链 组件缺省 < 定义 < 租户 < 用户 计算，创建会话时算好存进会话（06）。

**谁能改定义**（B3）：

- 应用可以通过来源随时增删定义。框架照常校验。
- 写定义的接口由应用自己鉴权后调用。模型不能创建或修改定义：`Registrar` 不暴露 `SpecStore`，组件拿不到写定义的入口，因此也没有任何工具能写定义。这是结构保证，不靠守卫拦截。

## 3.6 校验流程

```
来源返回 → 解析成 tenon.Agent → 检查 format，必要时转换
        → 校验内核字段 → 每个 use.<组件>：组件已装？按其结构校验
        → x.<命名空间>：有注册 Schema 则校验
        → 工具名都能解析？模型档位存在？
        → resident = true：T5 之前报"未支持"
        → 计算 Version → 生效
```

任何一步失败都拒绝整份定义，错误信息指出文件、字段和原因。

用户层定义的越权检查不在这条加载流程里，只在写定义接口上做（见 3.5）：保存时 `tools` / `use.permission` 超出创建者权限、limit 字段超出上限、或设了 `resident`，都拒绝保存。`explain` 能打印一份定义最终生效的样子（选定命名空间、填入缺省、算好使用配置之后）。

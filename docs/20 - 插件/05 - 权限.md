## 结论（权限项注册表 + 档位表，2026-11-01 用户确认 m13123）

1. **三层词汇**：类别（`toolhub.Effect*` 九个，宿主写死，只用于查封顶表）→ 权限项（插件声明，宿主汇总成注册表，判定与配置的单位）→ 取值（档位给每项赋值）。
2. **注册表**（`core/toolhub/items.go`）：`Item{ID, Title, Type(switch/match/level), Class, Levels, Bounded, Subject, NoSessionAllow, Suggest, SuggestLevel, Owner}`，插件经装配级点位 `perm_items` 登记，工具用 `Items: []string{...}` 引用。装配期 `Hub.Validate` 拒绝：引用未注册项、既 `NoAuth` 又引用项、权限策略层不是恰好一个。未声明项的工具一律询问；不需授权的工具（todo、ask_user）必须显式 `NoAuth`。
3. **已声明的项**：`fs.read`（switch）、`fs.write`（match，路径，构成边界）、`shell.exec`（match，命令段，**不构成边界**）、`shell.job`、`web.fetch`（match，主机名）、`web.search`、`mcp.<服务>`（match，`mcp__<服务>__<工具>`，类别随 trust）、`subagent.spawn`、`codemode.run`、`team.spawn/send/board/view`、`skills.load`。
4. **封顶表**（`plugins/security/permission/caps.go`，4 档位 × 9 类别）：插件建议值必须等于或严于封顶，否则拒绝启动（`apps/ybase/items_test.go` 汇总所有插件做这项检查）。封顶不约束自定义档位。
5. **档位**：内置 read-only / ask / workspace（新会话缺省）/ full，取值 = 插件建议值（经封顶）。自定义档位 `~/.ybase/modes/<名>.toml` 与受信项目 `<dir>/.ybase/modes/`，用 `[items]` 段只写覆盖项：`"shell.exec" = { default = "ask", allow = ["go test:*"], deny = ["rm -rf:*"] }`。`base` 继承：Default/Level 覆盖，模式清单追加，链长 ≤ 8；档位没写的项沿继承链回落到内置建议值，不回落 allow。保留名 read-only / ask / workspace / full / custom / auto。
6. **判定**：公共 deny / ask 规则 → 申请更宽沙箱 → 会话 allow 规则 → NoAuth → 各项取值（任一 deny 拒、任一 ask 问、全 allow 放行；match 项每个匹配对象按 deny → ask → allow 模式，未命中取缺省）→ 未声明项询问。之后只收紧：不可信输入 allow → ask；MCP `destructiveHint` allow → ask 且不给“本会话允许”；申请比档位更宽的沙箱每次单独确认。
7. **取值 deny 的工具不进模型工具列表**（`Hub.SetVisible`）。切档位必然丢一次提示缓存，是已知代价。模型凭历史仍调用时由权限层拒绝。
8. **公共规则只能加严**：`permissions.toml` 只剩 `mode`、`deny`、`ask`。写了公共 `allow`（用户级或项目级）直接报错拒绝启动，放宽请写进自定义档位的 `[items]`。档位文件只认 `name` / `base` / `description` / `[items]`，旧段 `[effects]` / `[tools]` / `[sandbox]` / `[rules]` 报错；规则写法只有 `工具(模式)[@沙箱]`，旧写法 `工具[子串]` 报错。
9. **自定义档位可以比基础档位更宽**，但名字不单独出现：`/mode`、`ybase mode list`、横幅都显示放宽清单，如 `local（基于 workspace，放宽 2 项：shell.exec、web.fetch）`。项目级档位放宽本机权限时，首次需 `/mode <名> -confirm`，结果记入 `~/.ybase/trust.toml`。
10. **“本次会话内都允许”**（确认时输入 `a`）：只叠 allow，存会话 Ext `permission.allow`。shell 每个非安全段生成前缀规则；**启动器类命令**（sh/bash/cmd/powershell/node/python/npm/pnpm/make/xargs/env/eval/sudo/docker/ssh 等，`plugins/tools/shell/cmd.go` `Launcher`）不生成规则，因为 `npm run test:*` 实际授权 package.json 能写的任何东西。命令切段在 shell 插件，判定表在权限插件，两者在 `Subject` 处汇合。
11. **可视化**：`ybase mode list|show <名>|copy <源> <新名> [-project]`，`/mode [名]`、`/mode show [名]`、`/mode copy …`，`-mode <名>`（`-yes` = full）。`mode show` 逐项列取值与来源插件，非边界项标“匹配只按文本，不构成边界”。
12. **会话档位**：Ext `permission.mode`；每回合按 mtime 重读，变化提示“[权限] 档位 <名> 的配置已更新，本回合起生效”。不再迁移旧档位名（auto / custom 只是保留字）；会话记录里的档位不存在时按“每次询问”处理并提示。
13. **沙箱级别**：level 型项 `sandbox.level`（权限插件登记），内置建议 read-only → read-only，ask / workspace → workspace-write，full → danger-full-access；自定义档位写 `"sandbox.level" = { level = "..." }`；`-sandbox` 可固定。内置档位不再有文件，全部由插件建议值生成。
13. **缺省闸门已撤**：以前未装权限插件时工具管理器按工具自报的 read 效果放行，属工具层越权。现在装配必须恰好有一个权限策略层，否则拒绝启动。

## 缺口

- 插件自报的项与建议值采信不验证；隔离外置插件留给后续进程 / WASM 方案。
- shell 匹配只按文本，不构成边界；沙箱关闭时 `shell.exec = allow` 等于放行任意命令，`mode show` 如实标注。
- 档位按文件修改时间重读，同一秒内两次修改可能只看到第一次。
- 非 Windows 平台没有沙箱。

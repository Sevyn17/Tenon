# 工作组（M6.8）

参考：DSH Agent Teams（Lead + teammates + 共享任务板，send_message 走 inbox，任务 CAS 修订号）；review-1 F1（origin=member，映射存插件自有表）。

## 结论

- 成员是普通会话：`origin=member`，`parent_id=<领导会话 id>`，id = `<领导>/m-<名字>`（名字 `^[a-z0-9]+(-[a-z0-9]+)*$`），持久、可单独打开续聊。每组成员上限 8。
- 领导工具：`team_spawn {name, task}`（异步：成员回合在后台跑，立即返回；结束后把最终文本作为一条 input 投递回领导 inbox，领导空闲即开回合，忙则排队）、`team_send`、看板四件套。
- 成员工具：`team_send {to, text}`（to = `lead` 或成员名）、看板；没有 `team_spawn`、`subagent`（深度 1）。
- 消息全部走 inbox（Send，item id 幂等，Source agent）；目标会话未打开则先打开。消息不绕过 inbox，崩溃后由 inbox 重放。
- 看板：表 `p_workgroup_tasks(team, id, subject, description, owner, status, result, rev, …)`，按领导会话 id 分组；`task_create` / `task_list` / `task_claim`（pending 或自己已领）/ `task_complete`（负责人或领导）；写入带 rev 条件写，冲突返回 `ErrConflict`。
- 单个成员回合上限 `MemberTimeout = 30min`；同一成员回合进行中再派活 → 报错（不排队，避免领导误以为并发）。进程退出 `Group.Close()` 取消所有后台回合。
- 风险：team_spawn / team_send / 写看板 Write，task_list Read。

## 缺口

- 回交意图持久化在 `p_workgroup_runs`（开始记 running + 固定 item id，结束记 done + 结果，投递成功后删除）。启动时 `Group.Recover` 补投：已完成的投结果；进程退出时仍在跑的，告知领导"成员中断，可用 team_send 让它继续"。inbox 按 item id 准入幂等，重复补投不会重复送达。中断的成员回合不会自动续跑，需领导再发消息。
- 无成员间直接中断（interrupt）、无成员列表工具；领导通过看板与消息协调。

# todo_write / ask_user（M5.5 调研与结论）

## 参考
- DSH `dsh-tool-todo`：`todo_write {todos:[{content,status}]}`，status = pending / in_progress / completed；每次调用替换整个列表；结果固定 `Updated todo list: <p> pending, <i> in progress, <c> completed.`；错误：content 为空、content 重复、（可选）in_progress 多于 1 个。列表状态就是调用参数本身，会话事件只服务 UI。
- DSH `dsh-tool-ask-user`：阻塞式 `ask_user_question`，问题 + 可选选项；回答以紧凑 JSON 回给模型；等待期间不耗 token。
- DSH `dsh-plan-mode`：进入 / 退出计划模式会改系统提示词（破坏前缀缓存），属于策略插件。
- Codex `update_plan`、opencode `todowrite` 形状相同（整表替换）。

## 结论
1. **todo_write**：采用 DSH 形状。列表的唯一事实是最后一次调用的参数（日志里已有），不另存表（一个事实一处）；恢复时从日志取最后一次 todo_write 即可重建 UI。校验：content 非空、不重复、status 合法；in_progress 不限个数（并行调用场景）。Risk Read（只改模型自己的计划，无外部副作用），可并行 = false（同一批多次写以顺序为准）。
2. **ask_user**：`{question, options?}`，阻塞等人回答；回答回 `{"answer":"…"}`。宿主注入 `Asker`；无宿主（非交互）→ 回错误“当前无人可问，请自行决定并说明假设”。等待受 ctx 取消；超时用工具 Timeout（默认 24h，与确认挂起一致）。崩溃恢复：调用是 started → 结果未知，按 toolhub 统一规则回“结果未知”，模型可重新提问（不另开挂起路径，单一路径）。
3. **计划模式**推迟：它改系统提示词、属策略，P0 用 todo_write + 权限 read-only 模式即可表达“只计划不动手”；记入决策日志。

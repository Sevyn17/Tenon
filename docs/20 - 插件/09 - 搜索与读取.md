# 5.2 grep / glob / 行范围读（一页调研）

## 参照

- **pi-mono**（`packages/coding-agent/src/core/tools/{read,grep,find}.ts`）：
  - `read {path, offset?, limit?}`，1 起行号；默认截断 2000 行 / 50KB（先到为准）；截断时末尾提示 `Use offset=N to continue`；单行超限时提示改用 shell。
  - `grep {pattern, path?, glob?, ignoreCase?, literal?, context?, limit=100}`，底层 ripgrep（缺失时下载），遵守 .gitignore，单行截到 500 字符。
  - `find {pattern, path?, limit}`，底层 fd。
- **Codex**：不提供独立搜索工具，靠 shell 调 `rg`；读文件也走 shell。
- **DSH**：`ops_grep` / `ops_glob` / `ops_read_files`，结果带 `scanComplete` / `nextOffset`，排除隐藏文件与依赖目录。

## 结论

1. **纯 Go 实现，不依赖 rg / fd**。理由：单二进制、Windows 无需安装外部程序、行为可测；本地仓库规模下 Go 的 RE2 足够快。ripgrep 若存在也不调用（行为一致优先）。
2. **`read_file {path, offset?, limit?}`**：行号 1 起；默认上限 2000 行 / 50KB；截断时注明 `已显示第 a–b 行（共 n 行），用 offset=b+1 继续`。不加行号前缀（避免模型把行号抄进 `edit.old_text`）。二进制文件（含 NUL）拒绝读取。
3. **`grep {pattern, path?, glob?, ignore_case?, literal?, context?, limit=100}`**：输出 `相对路径:行号: 内容`，上下文行用 `-`；单行截到 500 字符；总量受 50KB 限制；结果超限时注明“结果不完整”。
4. **`glob {pattern, path?, limit=200}`**：`**` 跨目录，按修改时间倒序（最近改的最可能相关，同 opencode）。
5. **遍历规则**（三个工具共用）：跳过 `.git`、`node_modules`、`vendor` 之外再遵守各级 `.gitignore`（支持 `*` `**` `?` 前导 `/` 结尾 `/` 与 `!` 反选）；跳过二进制文件；不跟随符号链接；路径限制在工作目录内。
6. **风险档 Read**，可并行，不需确认。

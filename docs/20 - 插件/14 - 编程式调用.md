# PTC：`run_code`（M6.6）

## 参考

- DSH dsh-ptc-runtime：程序为异步函数体，按命名空间暴露绑定，错误分类 exception / timeout / abort / output-limit。
- ../10 - 框架模块/04 - 工具管理器.md D5：插件注册 `run_code`；子调用回到 tool-hub 调用栈（Guard / 幂等 / 产物）；子调用 id `<父调用 id>#<n>` 确定性；子结果只进工具结果存储，不进会话日志；Risk Dangerous。

## 结论

- 引擎：goja（纯 Go ES5.1+ 大部分 ES6），无 cgo，跨平台一致。不选 Node 子进程：需要外部运行时，且要另做进程沙箱与 IPC。
- 程序同步执行：`tools.<名字>(参数对象)` 直接返回结果文本；工具失败抛异常（`e.message` 为错误文本）。不做 async/await：goja 单线程，同步写法对模型更简单，子调用本来就逐个经过调用栈。
- 绑定：只有 `tools` 与 `console`（log/info/warn/error）。没有文件系统、网络、定时器、`require`；外部访问只能通过工具，权限与沙箱由工具各自的层负责。
- 可调工具 = 会话视图里的可用工具（`Toolset.Available()`），排除 `run_code` 自身（不递归）。
- 子调用：`hub.ExecuteIn(ctx, cx.Toolset, sid, [call])`，id `<父 id>#<n>`。崩溃恢复后同一程序重跑时，已完成的子调用按幂等记录直接返回，已开始未完成的返回 UnknownOutcome。需确认的子调用照常挂起等人。
- 结果：console 输出 + 最后一个表达式的值（对象 JSON 化），合计 ≤ 50 KiB；空输出回 "（程序没有输出）"。
- 上限：默认 120 s，最大 600 s（参数 `timeout` 秒）；子调用 ≤ 200 次；代码 ≤ 64 KiB。
- 错误分类：`[exception]`（JS 异常 / 子调用基础设施错误）、`[timeout]`、`[abort]`（回合取消）、`[output-limit]`、`[call-limit]`；已产生的输出放在错误前面一起回给模型。
- Risk Dangerous、不并行：程序可以做任意组合，确认粒度落在子调用上，整段程序本身在 ask 模式下也要确认一次。

## 推迟

- 内存上限（goja 无内置堆限制；进程级 ReadMemStats 监控不精确且会误杀并行调用，暂不做）。

子调用 span：每个子调用 `<父>#<n>` 经 toolhub 单独产生 tool span，父 span 为 `tool-<父 call id>`（agent/hubtools.go HubSpan）。

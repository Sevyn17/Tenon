# 04 核心与扩展模块清单

> 状态：首版（2026-11-03）。基于代码实际依赖与注册关系盘点，非设计文档搬运。

## 总体分层

```
┌─────────────────────────────────────────────────────┐
│  应用层  client/tenon · client/desktop · client/server    │  ← 你的产品
├─────────────────────────────────────────────────────┤
│  SDK     模块根（package tenon）                   │  ← 公开 API：New / Default / Ask …
│          apphost · transport/web · transport/bind  │  ← 应用宿主与传输：profile、信任、协议适配、工作区
├─────────────────────────────────────────────────────┤
│  扩展模块  modules/                                  │  ← 全部可选，通过 component.Register 登记
│  ┌───────────────────────────────────────────────┐  │
│  │ 标准预设（Default）  21 个组件                  │  │  ← tenon.Default() 一键装上
│  │ ┌─────────────────────────────────────────┐   │  │
│  │ │ 最小预设（Minimal）  9 个组件             │   │  │  ← tenon.Minimal() 嵌入场景
│  │ └─────────────────────────────────────────┘   │  │
│  └───────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────┤
│  核心    runtime/                                       │  ← 不可替换，永远存在
│  session · agent · host · mail · store(接口)         │
│  toolhub · modelhub · plugin · runtime · agentdef    │
│  inject · callctx · useconf · bus · reqlog · pkgs    │
│  appapi                                              │
└─────────────────────────────────────────────────────┘
```

划分原则（01 §1.2）：涉及并发、持久化、安全的放核心；策略性的放扩展模块。标准模块只通过公开扩展点实现，用户自己写的模块和官方模块拿到的能力相同。

## 一、核心（runtime/ — 不可替换，任何应用都包含）

核心包之间只依赖核心包，不依赖 modules/ 或 client/。

| 包 | 职责 | 关键类型 / 接口 |
|---|---|---|
| `runtime/session` | 会话状态机（纯函数式、无 IO） | `Core`、`Entry`、`ToolCall`、`Content`、`Snapshot` |
| `runtime/agent` | 驱动 session 的最小主循环（推理 → 工具 → 检查点） | `Agent`、`Committed()`、`Outbound()`、`Compactor` |
| `runtime/host` | 会话宿主：信箱、轮次、租约、信封投递、休眠/唤醒、守卫 | `Host`、`Deliver()`、`FlushOutbox()`、`Maintain()` |
| `runtime/mail` | 信封类型（from / origin / hop / caps / trace） | `Envelope`、`Address` |
| `runtime/store` | 存储接口（session / inbox / lease / sleep / corr / tool_results / outbox / prune / trace） | `Store`（组合接口）、`SessionStore`、`ToolResultStore`、`OutboxStore` 等 |
| `runtime/toolhub` | 工具管理器：注册、分层、确认/等待、幂等记录、崩溃恢复 | `Hub`、`Tool`、`Cx`、`Output`、`Record` |
| `runtime/modelhub` | 模型管理器：调度、熔断、提供者与模型目录 | `Hub`、`Adapter`、`Provider`、`Catalog` |
| `runtime/component` | 插件管理器：登记、装配（拓扑排序）、Profile、扩展点 | `Plugin`、`Meta`、`Assembly`、`Registrar`、`Profile` |
| `runtime/assemble` | 运行时构造器：把 Assembly 收集的贡献组装成每个会话的 agent；点位与服务常量 | `Builder`、`Collected`、`Kernel`、`ToolsEntry` / `LayerEntry` / `BlockEntry` |
| `runtime/agentdef` | 智能体定义与加载（TOML → 结构体） | `Agent`（定义）、`Source`、`Dir()` |
| `runtime/inject` | 上下文注入（框架设计 12） | `Item`、`Reg` |
| `runtime/callctx` | 一次调用的上下文（04 §4.4 的 `*Ctx`） | `Ctx`、`Session`、`Trace` |
| `runtime/useconf` | 使用配置链（定义里 `[use.*]` 的解析） | `Schema`、`Field`、`Source` |
| `runtime/bus` | 事件总线 | `Bus`、`Envelope`、`Sub` |
| `runtime/reqlog` | 结构化请求记录 | `Record` |
| `runtime/pkgs` | 插件包（外置插件第一级）；应用把加载结果作为 `service:packages` 注入 | `Package`、`Manifest` |
| `appapi` | 应用接口层：会话 CRUD、流式回复、pending、modes、trace explain | `App`、`UI`、`Error` |

**存储实现**（由应用通过 `tenon.WithStore` 提供，不算扩展模块）：

| 包 | 说明 |
|---|---|
| `runtime/store/sqlite` | 本地默认：单 SQLite 文件，WAL 模式 |
| `runtime/store/memstore` | 内存版（测试与 tenontest 用） |
| `runtime/store/storetest` | 一致性测试套件，sqlite 与 memstore 共用 |

## 二、SDK 公开接口（模块根，package tenon）

SDK 是应用引用框架的入口。它导入核心包和扩展模块，提供装配 API。

| 函数 / 类型 | 说明 |
|---|---|
| `tenon.New(opts ...Option)` | 装配并返回 `*App` |
| `tenon.Default()` | 标准预设（21 个组件） |
| `tenon.Minimal()` | 最小预设（9 个组件：模型 + 上下文） |
| `tenon.With(cs ...Component)` | 追加自定义组件 |
| `tenon.Without(names ...string)` | 从预设里去掉组件 |
| `tenon.WithStore(s store.Store)` | 提供存储实现 |
| `tenon.WithModels(hub, model)` | 自带模型管理器（不用 models 组件） |
| `tenon.WithAgents(srcs ...Source)` | 加载智能体定义 |
| `tenon.WithWorkdir(dir)` | 指定工作目录 |
| `tenon.WithUI(ui)` | 提供 UI 接口 |
| `tenon.WithProtocolUI()` | 界面经应用协议：提问登记成交互，由协议客户端回答（与 `WithUI` 二选一） |
| `tenon.WithConfig(组件, 键值)` | 设预设组件的配置键，等同 profile 的 `[plugin.<名>]` |
| `tenon.WithProjectTrust(b)` | 声明工作目录受信 |
| `tenon.WithSleepAfter(d)` | 空闲后自动休眠 |
| `tenon.Dir(root)` | 从目录加载定义 |
| `App.Start(ctx)` | 启动运行时 |
| `App.Ask(ctx, agent, text, meta)` | 向智能体发消息，等回复 |
| `App.History(ctx, id)` | 读会话历史 |
| `tenon.WithProfile(p)` | 按 profile 装配（各插件的 `Meta.Default` + 开关 + 配置 + `[kernel]`），与 `Default()` / `Minimal()` / `Without` 二选一；profile 里有存储插件时不必 `WithStore` |
| `tenon.WithService(键, 值)` | 给组件预置一项服务（如插件包列表） |
| `tenon.WithWorkspace(键)` | 会话记所属工作区、列表只列它的、拒绝打开别的工作区的会话 |
| `tenon.WithSessionHooks(f)`、`WithModeApprovals(a)`、`WithProtocolOptions(f)`、`WithReadyErrors(f)` | 会话钩子、档位确认记录、协议层选项、ready 点位出错时的处理 |
| `App.Open(ctx)` | 只启动组件（打开存储），不跑会话；只读的一次性操作用 |
| `App.Host()`、`Assembly()`、`DB()`、`Models()`、`Builder()`… | 给建在 SDK 上的应用宿主用的访问器 |
| `App.API()` | 应用协议层（`*appapi.App`），交给 `transport/web` 或 `transport/bind` 接框架的前端；Start 之前为 nil |
| `App.Close(ctx)` | 关闭 |

协议适配（模型列表、权限档位、追问、标题、文件列表、压缩、工件、删除清理）在 `tenon/adapters`，SDK 与 `apphost` 共用。只用 SDK 起网页工作台的完整示例见 `examples/web-server`。

```go
// 典型用法
app, _ := tenon.New(
    tenon.Default(),                             // 标准 21 组件
    tenon.Without("shell", "web"),               // 去掉不需要的
    tenon.With(&myPlugin{}),                     // 加自己的
    tenon.WithStore(sqliteStore),
    tenon.WithAgents(tenon.Dir("./agents")),
)
```

## 三、扩展模块清单（modules/ — 全部可选）

每个模块通过 `component.Register(name, factory)` 在 init 时登记。应用通过 Profile 或 SDK 预设决定启用哪些。

### 3.1 模型层（modules/model/）

为内核提供模型调用能力。Minimal 和 Default 都包含。

| 组件名 | 包 | 职责 | Minimal | Default | 依赖 |
|---|---|---|---|---|---|
| `models` | `model/models` | 模型管理器：密钥、目录、提供者注册 | ✅ | ✅ | slot:secrets |
| `adapter-anthropic` | `model/adapter-anthropic` | Anthropic Messages API 适配 | ✅ | ✅ | service:modelhub |
| `adapter-openai-chat` | `model/adapter-openai-chat` | OpenAI Chat Completions 适配 | ✅ | ✅ | service:modelhub |
| `adapter-openai-responses` | `model/adapter-openai-responses` | OpenAI Responses API 适配 | ✅ | ✅ | service:modelhub |

### 3.2 上下文层（modules/context/）

构建发给模型的上下文（系统提示、压缩、脱敏、技能）。Minimal 包含全部。

| 组件名 | 包 | 职责 | Minimal | Default | 依赖 |
|---|---|---|---|---|---|
| `prompt` | `context/prompt` | 系统提示词组装（定义的 prompt + 补充块） | ✅ | ✅ | service:workdir, ?service:packages |
| `instructions` | `context/instructions` | AGENTS.md 指令加载与注入 | ✅ | ✅ | service:workdir |
| `redact` | `context/redact` | 输出脱敏（层） | ✅ | ✅ | ?service:compactor |
| `skills` | `context/skills` | 技能目录发现与注册（工具 + 系统块） | ✅ | ✅ | service:workdir, service:ui, ?service:packages |
| `compact-basic` | `context/compact-basic` | 上下文压缩（超长对话自动摘要） | ✅ | ✅ | service:modelhub → 提供 service:compactor |

注：redact 没有声明 `Meta.Default`（即 false）。两种装配的规则（计划/07 阶段三，`presets_internal_test.go` 强制）：按 profile 装配（`WithProfile`，三个客户端经 `apphost` 走这条）时按各插件的 `Meta.Default` 加 profile 开关，所以 profile 不写 `enabled` 就是关闭；`Default()` 预设是"全部标准组件、存储除外"，所以装上它。

### 3.3 安全层（modules/security/）

权限与沙箱。Default 包含；Minimal 不含。

| 组件名 | 包 | 职责 | Minimal | Default | 依赖 |
|---|---|---|---|---|---|
| `permission` | `security/permission` | 工具权限评估（档位、策略、交互确认） | ❌ | ✅ | service:db, service:workdir, ?service:trust → 提供 service:permission |
| `sandbox` | `security/sandbox` | 进程沙箱（Windows 受限令牌） | ❌ | ✅ | service:workdir, service:permission → 提供 service:sandbox |

注：sandbox 的 `Meta.Default = false`。走 profile 装配（CLI / 桌面 / server）时，profile 不写 `enabled` 就是关闭；SDK 的 `Default()` 按清单显式装上它。

### 3.4 工具层（modules/tools/）

给智能体提供可调用的工具。Default 包含全部；Minimal 不含。

| 组件名 | 包 | 职责 | Minimal | Default | 依赖 |
|---|---|---|---|---|---|
| `fs` | `tools/fs` | 文件读写、编辑、搜索（junction 安全） | ❌ | ✅ | service:workdir |
| `shell` | `tools/shell` | 命令执行（PowerShell/Bash，沙箱感知） | ❌ | ✅ | service:workdir, ?service:sandbox, ?service:permission |
| `web` | `tools/web` | 网页搜索与抓取 | ❌ | ✅ | （无） |
| `mcp` | `tools/mcp` | MCP 客户端（连接外部 MCP 服务器） | ❌ | ✅ | service:workdir, service:ui, ?service:trust, ?sandbox, ?permission, ?packages |
| `ask-user` | `tools/ask-user` | 向用户提问工具 | ❌ | ✅ | service:ui |
| `todo` | `tools/todo` | 待办列表工具 | ❌ | ✅ | service:ui |
| `code-mode` | `tools/codemode` | 程序化工具调用：`run_code` 在 JS 沙盒（goja）里执行模型写的程序，程序内的工具调用回到同一 hub | ❌ | ✅ | （无） |

### 3.5 协作层（modules/collab/）

子智能体与工作组。Default 包含；Minimal 不含。

| 组件名 | 包 | 职责 | Minimal | Default | 依赖 |
|---|---|---|---|---|---|
| `subagent` | `collab/subagent` | 派生子智能体会话 | ❌ | ✅ | service:host |
| `workgroup` | `collab/workgroup` | 工作组（成员管理、回信路由），自有 SQL 表 | ❌ | ✅ | service:host, service:db, SQL, service:ui |

### 3.6 扩展层（modules/extend/）

面向高级用户的扩展机制。Default 包含；Minimal 不含。

| 组件名 | 包 | 职责 | Minimal | Default | 依赖 |
|---|---|---|---|---|---|
| `hooks` | `extend/hooks` | 用户钩子（会话前/后、回合后） | ❌ | ✅ | service:workdir, service:ui, ?service:trust, ?sandbox, ?packages |

### 3.7 存储插件（modules/storage/）

把存储实现包装成组件，供 Profile/装配用。应用也可以直接 `WithStore()` 绕过。

| 组件名 | 包 | 职责 | Minimal | Default | 说明 |
|---|---|---|---|---|---|
| `store-sqlite` | `storage/store-sqlite` | SQLite 存储组件：填四个存储槽位（同一个 DB），提供 service:db | ❌ | ❌ | 不在 SDK 预设里（SDK 用 `WithStore`）；profile 装配（`apphost`）里缺省开着；不再锁定，但装配时必须有一个组件提供 `service:db`，`plugins.set` 也不让关掉最后一个 |

## 五、扩展点（核心对外的接口）

模块通过这些点位向内核注册能力：

| 点位 | 常量 | 用途 | 典型注册者 |
|---|---|---|---|
| 会话工具 | `PointSessionTools` | 给会话注入工具 | fs, shell, web, mcp, ask-user, todo, code-mode, skills, subagent, workgroup |
| 会话层 | `PointSessionLayer` | 中间件层（守卫或处理） | permission, sandbox, redact, hooks, instructions |
| 系统块 | `PointSystemBlock` | 系统提示词块 | prompt, instructions, skills |
| 回合后 | `PointAfterTurn` | 一轮结束后的钩子 | hooks |
| 就绪 | `PointReady` | 会话构造完成后调用一次 | workgroup |
| 权限项 | `PointPermItems` | 登记权限评估项 | fs, shell, web, mcp, code-mode, skills, subagent, workgroup, sandbox |
| 会话删除 | `PointOnSessionDelete` | 会话被删除时清理（登记 `store.Cleaner`） | 当前没有组件登记 |

服务槽位（应用/存储/模型填充）：

| 槽位 | 填充者 |
|---|---|
| `slot:secrets` | 内核缺省 `EnvSecrets`（`SlotDefaults`），应用可覆盖；models 组件消费。其余插槽已删（审查 P1-50） |

组件间服务（Provides → Requires）：

| 服务 | 提供者 | 消费者 |
|---|---|---|
| `service:modelhub` | models | adapter-*, compact-basic |
| `service:compactor` | compact-basic | redact |
| `service:permission` | permission | sandbox, shell, mcp |
| `service:sandbox` | sandbox | shell, hooks, mcp |
| `service:host` | 应用层 | subagent, workgroup |
| `service:db` | store-sqlite（profile 装配）；SDK 用 `WithStore` 的存储注入 | permission, workgroup |
| `service:sql` | 存储的 SQL 出口（装配期检查 `Requires{SQL: true}`） | workgroup |
| `service:ui` | 应用层 | ask-user, todo, skills, hooks, mcp, workgroup |
| `service:workdir` | 应用层 | prompt, instructions, fs, shell, hooks, mcp, permission |
| `service:trust` | 应用层 | permission, hooks, mcp |
| `service:packages` | 应用层（`apphost` 注入 `runtime/pkgs` 加载结果；SDK 不注入） | prompt, skills, hooks, mcp（均为可选依赖） |

## 六、应用层参考（client/）

应用引用 SDK、应用宿主（`apphost`）与传输（`transport/web`、`transport/bind`），不属于框架本身，但说明分层。

| 应用 | 说明 |
|---|---|
| `client/tenon` | CLI（命令行智能体） |
| `client/desktop` | 桌面端 |
| `client/server` | Web 服务（WebSocket + HTTP，演示/集成用） |
| `tenontest` | 测试辅助包（`tenontest.New(t, ...)` 快速起 App） |
| `client/product` | 产品自己的配置：内置 profile（经 `apphost.Flags.BaseProfile` 传入） |

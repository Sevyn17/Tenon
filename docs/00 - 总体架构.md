# 总体架构

> 状态：定稿（2026-10-31，用户确认）。本篇汇总内核与插件的分层、插件全表、外置插件、前端与多端接入、目录规划和路线。各模块细节见 [10 - 框架模块](<10 - 框架模块/00 - 索引.md>)，内核与插件的分界原则和可调参数见 [03 - 约束清单](<03 - 约束清单.md>)。

## 一、三层定义

| 层 | 定义 | 能不能关 |
|---|---|---|
| **内核** | 只提供机制：定义接口、调度、落库和恢复的规则。不产生会话内容，不带具体工具，也不带具体协议 | 不是插件，不能关 |
| **内置插件** | 和内核同仓库、编译进同一个程序，由插件管理器装配。分三档：<br>• **强制**：缺了跑不起来，关不掉<br>• **核心**：缺省开，组成一个能用的编程助手<br>• **可选**：缺省关，按需开 | 强制的不能关，其余可以 |
| **外置插件** | 不和内核一起编译，在单独的进程里运行，通过协议接进来 | 由配置决定 |

外置插件现在只有 **MCP server** 一种；**hooks 里的用户脚本**也算外置扩展。内核不支持动态加载 Go 插件，内置插件只能编译进程序。外置插件的扩展方式见第四节。

判断一项功能放内核还是插件，按[约束清单](<03 - 约束清单.md>)里的分界原则：影响会话内容或系统提示词的，一律做成插件或配置；不影响会话的系统优化可以留在内核，但带数值的参数要能配置并登记。

## 二、内核负责什么

| 包 | 职责 |
|---|---|
| session | 会话状态机：回合、步、计划项，以及条件写入、fork、rewind |
| reqlog | 请求记录，恢复时按记录重组请求 |
| toolhub | 工具调用栈：调用层、并发调度、幂等记录、确认挂起、结果溢出、`tool_search` |
| modelhub | 模型调度：目录、重试、熔断、按 `prompt_cache_key` 保持缓存。**不含具体协议** |
| host | 会话宿主：命令、收件箱、确认流程、子会话的生成 |
| agent | 驱动循环：把 session、toolhub、modelhub 串起来 |
| bus | 事件总线：订阅、补齐、背压 |
| store | 存储接口与表结构契约。**不含具体后端** |
| plugin | 插件管理器：装配、依赖、配置、作用域、explain |
| runtime | 会话构造器：定义点位（工具、层、系统块、回合后、就绪），解析 `[kernel]` 配置节 |

按这个标准，原来内核目录里有三处不属于内核：`builtin/` 的三个插件（store-sqlite、models、compact-basic）、`compact/` 的压缩算法、modelhub 里的三个协议适配器。第六节的结构调整（2026-10-31 已执行）已把它们移到 `plugins/` 下。

## 四、外置插件

按接入成本从低到高分三档，按顺序做：

1. **插件包**：一个目录加清单文件 `ybase-plugin.toml`，把 MCP server、钩子、技能、提示词片段和缺省配置打包在一起，安装即用（参照 Claude Code 的插件包）。不需要新协议，先做这一档。（2026-11-01 已做第一版，见 [15 - 插件包](<10 - 框架模块/15 - 插件包.md>)。）
2. **扩展进程协议**：MCP 的超集，stdio 上跑 JSON-RPC 2.0，在 MCP 之外加 `ybase/*` 能力：系统块、回合后回调、事件订阅、调用层。调用层要声明超时和失败策略：Guard 失败按拒绝处理，Transform 失败按放行处理。提供 Python、Node、Go 的薄 SDK，用 `uvx` / `npx` 启动，进程放在沙箱里运行。现在只写设计，遇到第一个真实需求再实现。（设计见 [16 - 扩展进程协议](<10 - 框架模块/16 - 扩展进程协议.md>)，未实现。）
3. **WASM**：远期，暂不考虑。

外置插件接进来后和内置插件走同一套装配、开关、explain 和信任规则；项目目录里的外置插件只在项目受信时加载。

## 五、前端与多端接入

桌面端和网页访问都要支持（2026-10-31 用户确认）。

### 5.1 结构

```
内核（Go）
  └─ 应用接口层：命令 + 事件订阅（Go 接口，进程内）
       ├─ CLI：apps/ybase
       ├─ 桌面端：Wails v3，直接绑定应用接口层，不开端口
       └─ api-server（应用 apps/server，非插件）：HTTP / WebSocket，给浏览器、IDE、远程用
```

- **应用接口层**：把宿主命令（发送、引导、取消、确认、设置、压缩、回退、分叉等）和事件订阅（`Follow`：回放 + 补齐 + 实时）整理成一套稳定接口。CLI、桌面端和 api-server 都只调这一层，不直接碰内核包。内核已有的宿主命令、事件总线 `Follow` 和 `service:ui` 是它的基础。
- **前端传输层**：前端代码里加一个很薄的传输层，接口只有"发命令、收事件"。在桌面端走 Wails 绑定，在浏览器里走 WebSocket，两边共用同一套界面。
- **类型**：TS 类型从 Go 生成（Wails 自带绑定生成；网页侧从 Go 的 JSON Schema 生成），不手写。
- **前端外壳**：会话列表、对话、工具卡片、确认、提问、权限档位、插件配置、统计。
- **插件界面贡献**按数据驱动：配置表单由配置项的 `cfg` / `title` / `description` / `widget` 标签生成；结果按内容类型和工具属性选渲染方式；确认和提问用通用组件；需要自定义界面的插件最后才考虑沙箱化的 iframe。细则见 [09 - 前端插件体系](<10 - 框架模块/09 - 前端插件体系.md>)。

### 5.2 选型：Wails v3

[Wails v3.0.0 于 2026-10-26 发布正式版](https://v3.wails.io/changelog/)。选它的理由：

| | Wails v3 | Tauri | Electron |
|---|---|---|---|
| 外壳语言 | Go，和内核相同 | Rust，多一套工具链 | Node |
| 进程结构 | 内核和窗口同一进程，界面直接调 Go | Go 内核只能作子进程挂上 | Go 内核作子进程 |
| 体积 | 用系统 WebView2，安装包十几 MB | 相近 | 自带 Chromium，上百 MB |

不用 v2：v2 的 API 是旧的，以后迁到 v3 还要再改一次。v3 刚出正式版，实际开工在结构调整之后，到时已有几轮修复版。

### 5.3 安全

- 桌面端走 Wails 进程内通道，不开本机端口。
- api-server 缺省只监听 `127.0.0.1`，用随机令牌认证，检查 `Origin` 和 `Host`，不允许 CORS 通配。远程访问必须加 TLS 和 auth 插件。
  - 已实现（`apps/server`）：令牌 32 字节 crypto/rand、常量时间比较，HTTP 与 WebSocket 全部校验；Host 只认回环名 + 端口（防 DNS 重绑定）；WebSocket 的 Origin 须与 Host 同源；静态页带严格 CSP 头；非回环地址需 `-allow-remote` 且给 TLS 证书才启动。auth 插件未做。详见 [14 - 网页服务](<10 - 框架模块/14 - 网页服务.md>)。
- 防 XSS：Markdown 渲染禁止原始 HTML，设置严格的 CSP。
- 模型密钥只留在后端，不下发到前端。
- 控制 npm 依赖数量，锁定版本。

### 5.4 性能

延迟主要来自模型和工具，界面层不是瓶颈。需要注意三点：流式文本按 16–50 ms 批量推送，大结果只推预览（全文按需取工件），SQLite 只由后端一个写入方访问。

## 六、目录规划（结构调整，2026-10-31 已执行）

用户说开始后执行，执行前不改代码：

| 现在 | 调整后 |
|---|---|
| `kernel/` 根下的内核包 | `kernel/core/`：session、reqlog、toolhub、modelhub、host、agent、bus、store、plugin、runtime |
| `kernel/plugins/<名>` | `kernel/plugins/<分组>/<名>`，分组同第三节 |

| `ybase.exe`、`bin/` | 加入忽略列表 |

依赖规则不变：内核包不 import 插件，插件之间不互相 import，由 `runtime/deps_test.go` 检查。

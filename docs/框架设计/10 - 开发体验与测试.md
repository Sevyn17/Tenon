# 10 开发体验与测试

> 状态：草案（2026-11-01）。目标是让写应用像写 FastAPI / Django：声明一次类型，校验、文档、编辑器提示都有；装上预设就能跑；测试不需要真模型、真数据库。

## 10.1 一份类型，生成三样东西

组件的配置结构、`[use.<组件>]` 结构、工具参数都用 Go 结构体声明（04 4.2、06 6.2）。框架从结构体生成：

| 产物 | 用途 |
|---|---|
| JSON Schema | 加载定义和配置时校验；工具参数发给模型 |
| `tenon schema` 输出 | 编辑器给 `agent.toml` 补全和报错 |
| 文档页 | 每个组件的字段、缺省值、说明，取自 struct tag |

```go
type MemoryAgentConfig struct {   // [use.memory]，同 06 6.2
    Store string `toml:"store" doc:"记忆库名" required:"true"`
    By    string `toml:"by" doc:"分区键，内核从 *Ctx 取" enum:"user,tenant,session" default:"user"`
}
```

规则：没有手写 Schema。字段说明写在 tag 里，改结构体即改文档。

## 10.2 预设

`tenon.Default()` 装上标准组件组合（context、memory、agent、permission、budget、fs、shell、web、mcp 等），每个组件带合理缺省值。应用按需增减：

```go
tenon.New(tenon.Default(), tenon.Without("shell", "fs"), tenon.With(&shop.Orders{}))
```

预设内容随框架版本固定，变化写进发布说明。嵌入场景（只开业务工具）另给 `tenon.Minimal()`：只有内核和 context。两种预设都不含存储，存储由 `tenon.WithStore` 提供（07 7.2）；测试套件缺省用内存 `Store`。

## 10.3 测试套件 `tenontest`

```go
func TestSupport(t *testing.T) {
    app := tenontest.New(t,
        tenon.WithAgents(tenon.Dir("./agents")),
        tenontest.Model(
            tenontest.Reply("先查订单").CallTool("order_query", `{"id":"A1"}`),
            tenontest.Reply("已发货，明天到"),
        ),
    )
    ctx := tenon.WithUser(tenon.WithTenant(context.Background(), "t1"), "u42")
    reply, err := app.Ask(ctx, "support", "A1 到哪了", nil)
    require.NoError(t, err)
    require.Contains(t, reply.Text, "明天到")
    app.AssertToolCalled("order_query")
}
```

| 部件 | 作用 |
|---|---|
| 内存 `Store` | 每个测试一个，测试结束丢弃；和 SQLite 实现跑同一套一致性测试 |
| 脚本模型 | 按顺序返回预设回复和工具调用；调用次数不符时测试失败 |
| 假时钟 | 测休眠、超时、定时触发、`deadline` |
| 故障注入 | 在指定步之后"杀进程"，验证从检查点恢复（09 9.4） |
| 身份 | 设置租户、用户和会话创建者，以及创建者的权限集；用来测用户层定义越权拒绝（03 3.6）。创建者缺省为 `local`，不是空 |
| 断言 | 工具是否被调用、信封路径、守卫是否拒绝、预算记账 |
| 回归快照 | 把工具列表和历史条目序列存成快照文件，改动后对比；改造前先录一份基线 |
| 录制回放 | 用真模型跑一次录下请求和回复，之后离线回放 |

组件作者用同一套件测自己的组件，不需要起整个应用。

## 10.4 开发调试界面

`tenon dev` 起一个本地页面，数据来自现有请求记录和 trace（`reqlog`、`trace_spans`）：

- 按 trace 看一次任务经过的会话、信封、工具调用、模型请求。
- 看某个会话的历史、检查点、租约和休眠状态。
- 看装配结果：装了哪些组件、中间件顺序、每个定义合并后的最终配置（06 6.3）。
- 对某个定义改提示词后直接重跑一轮，对比前后回复。

只在开发模式开启，生产环境不暴露。

## 10.5 命令行

| 命令 | 作用 |
|---|---|
| `tenon check` | 加载全部定义和配置，一次性列出所有错误 |
| `tenon schema` | 输出 JSON Schema |
| `tenon explain <trace>` | 打印一次任务的路径（08 8.7） |
| `tenon dev` | 开发调试界面 |
| `tenon migrate` | 执行组件数据迁移（05） |

## 10.6 现状差距

- 现在没有测试用的内存存储和脚本模型，测试依赖 SQLite 文件。T1a 补：`Store` 接口、内存实现、和 SQLite 同跑的一致性测试；`tenontest` 最小版（脚本模型、身份设置、`AssertToolCalled`）在 T1b-2d 完成（`tenontest`，10.3 的例子可直接跑）。假时钟和故障注入随 T2a 补。
- 改造前没有可对比的基线。T1a 在 `tenontest` 之后、定义加载之前录回归快照（工具列表、条目序列），之后每步用它判断"行为无差异"。（已落地：两套回归快照）
- 配置和工具参数部分手写 Schema。使用配置 `[use.*]` 已从组件登记的结构体原型生成（T1b-2b）；组件配置链仍是 `cfg` 标签（T1b-2d 之后）。
- 框架不带命令行；`explain` 已随 trace 落地（`appapi.RenderTrace`，协议命令 `trace.explain`，T3 收口），命令行入口由应用提供。`explain` 的插件配置视图留 T4。
- SDK 已可用（模块根 `tenon` 包的 `tenon.New`，T1b-2d）。2026-11-08 起只有一条装配路径：应用用 SDK `tenon.New`，或用 `apphost`（`Start` + `BuildApp`，内部同样走 SDK）读信任与 profile 后装配（15、16，见归档 30 - 计划与报告）。
- `tenontest` 用例与宿主层 T3 验收在 SQLite 与内存两种存储上都跑（`tenontest.Stores` / `TestT3AcceptanceOnBothStores`，2026-11-02）。

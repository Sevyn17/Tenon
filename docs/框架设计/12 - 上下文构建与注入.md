# 12 上下文构建与注入

> 状态：定稿草案（2026-11-01），本篇是模块篇。结论来自 2026-11-01 的讨论，依据三份调研（外部系统、DSH/bili、我们代码现状），原始报告在 `%TEMP%/art/inj_ext.md`、`inj_dsh.md`、`inj_code.md`。排期：内核部分在 T2b（上下文构建，可与 T2a 并行），见 09 9.5。

## 12.1 问题

工具让智能体**主动拉取**上下文。另有一类信息必须**推给**模型，模型不问也要看到：

- 稳定的指令：定义的 prompt、组件说明、AGENTS.md、技能目录。
- 会话开始时的环境：工作目录、当前用户、时间。
- 运行中发生的事：子任务完成、工作组成员回信、权限档位变化、存储降级、预算将尽。
- 提醒：待办复述、"你已经连续调用同一工具 5 次"。

要定的是：谁能推、推到哪、写不写进历史、怎么去重、怎么标明来源、怎么不破坏提示缓存。

## 12.3 别人怎么做（摘要）

- **易变内容不改系统提示词。** Claude Code、Codex、Gemini CLI、DSH 都把易变内容作为 user 消息或工具结果附在尾部，保住前缀缓存。Letta 把记忆放 system，每次修改缓存失效。
- **注入内容基本都进历史。** Claude Code `<system-reminder>`、Codex settings diff 和 `<turn_aborted>`、DSH 运行时上下文都进历史。只有 OpenCode transform、LangChain `wrap_model_call` 只改本次请求。
- **插件不直接写上下文。** MCP 服务器只能通知，进不进模型由宿主决定。
- **只追加、声明作废。** DSH 的运行时上下文、技能目录、AGENTS.md 变化时追加新的一条并写明"取代之前"，不删旧条目；没变化就不写。
- **常见坑。** 任务结束后提醒还反复出现（Claude Code #12302）；伪造提醒标签（#85126）；每轮全量附环境信息导致膨胀，模型还抄进代码（Cline）。

## 12.4 已定结论

| 编号 | 结论 | 理由 |
|---|---|---|
| C1 | AGENTS.md、技能目录放会话开头的 user 消息（快照），不放系统提示词 | 对缓存友好，DSH、Codex 同样做法；代价是权重略低于系统提示词 |
| C2 | 会话进行中不改系统提示词。所有运行中的变化（包括组件段落变化）都走**状态更新** | 保住前缀缓存 |
| C3 | 状态更新：每次调模型前收集，按 key 只发变化的部分，附在本次请求最后一条消息末尾 | 用户提出（2026-11-01）；与 Claude Code、DSH 一致 |
| C4 | 所有注入内容都进历史，不设"只用于本次请求"的临时注入 | 模型回答可能引用提醒内容，不进历史则回放、审计、压缩都对不上；尾部内容在缓存前缀之后，不影响缓存 |
| C5 | 注入预算指注入内容自身的上限，与会话压缩是两回事 | 压缩管历史变长，注入预算管单次塞入过多 |
| C6 | 空闲时信封是否开回合，由信封的处理方式决定（见 13） | 通知类不开回合，进状态更新 |

## 12.5 内核提供什么

### 分层

发给模型的内容按稳定度分四层，越靠前越稳定：

| 层 | 内容 | 放在哪 | 什么时候变 |
|---|---|---|---|
| L0 底座 | 内核固定说明、工具定义 | system / tools | 底座升级 |
| L1 定义与组件 | 定义 prompt、组件静态段落，按中央顺序表排 | system | 只在新会话或显式迁移时变 |
| L2 会话快照 | AGENTS.md、技能目录、环境 | 会话开头的 user 消息 | 内容变化时通过状态更新说明，不改原条目 |
| L3 历史 | 对话、工具结果、状态更新 | 历史 | 只追加；压缩时折叠 |

### 组装器

组件不直接写上下文，只提交片段，内核的组装器决定放哪、截不截断、去不去重：

```go
type Contribution struct {
    Key      string // 同 key 新内容取代旧内容，例如 "agents_md:/repo/app"、"todo"、"time"
    Kind     Kind   // System | Snapshot | Status
    Body     string
    Priority int    // 状态更新超出总上限时，先丢低的
    Budget   int    // 单条上限（token）；超出落 blob，只注入路径和预览
}
```

`Source` 和 `Trust` 不让组件填，由内核按注册的组件名和信封 `origin` 写入（同 D2 的思路）。

| Kind | 层 | 提交时机（04 点位） | 例子 |
|---|---|---|---|
| `System` | L1 | `SessionOpen` | 定义 prompt、组件说明 |
| `Snapshot` | L2 | `SessionOpen` | AGENTS.md、技能目录、环境 |
| `Status` | L3 | `ModelCall`、`ToolCall`、`Deliver`（通知类信封） | 时间、待办、权限档位、预算余量、文件被外部修改、组件段落变化 |

### 状态更新

1. **时机**：每次调模型前，组装器收集各组件的 `Status` 片段。没有变化就什么都不加。
2. **位置**：附在本次请求最后一条消息的末尾。回合第一次调模型时是用户消息；回合中间（工具调完再调模型）时是工具结果。只附在用户消息上的话，多步任务中途收不到更新。
3. **只发变化**：组装器记住每个 key 上次内容的哈希，只发哈希变了的 key，合并成一块：

   ```
   <status-update>
   <item source="todo" key="todo">…</item>
   <item source="permission" key="mode">已切换到只读</item>
   </status-update>
   ```

   key 被撤销时写一条"已清除"。这避免了 Cline 每轮全量附加导致的膨胀，也避免任务结束后提醒还反复出现。
4. **持久化**：状态更新随所附消息写进历史。每个 key 的哈希存在会话里，进程重启后不重复注入。
5. **通知类信封**：会话收到 `notice` 处理方式的信封（13），不开回合，内容作为一个 `Status` 片段进入下一次状态更新。

### 注入预算

- **单条上限**：每个片段有 `Budget`。超出时截断，或把全文写进 blob、只注入路径和预览（Claude Code 钩子输出超过 10k 字符也是这样处理）。
- **总上限**：一次状态更新有总上限（缺省 2k token，可配置）。超出时按 `Priority` 先丢低优先级的 key，被丢的 key 不更新哈希，下次再试。
- 注入内容写进历史后就是普通历史，由压缩接管。

### 压缩后重建

压缩会把快照和状态更新一起折叠掉。压缩完成后，组装器按 key 把仍然有效的最新 `Snapshot` 和 `Status` 重新注入一次，并重置哈希记录。

### 来源和信任

- 所有注入统一用 `<context source=… trust=internal|external>` 或 `<status-update>` 包裹；组件内容里出现同名标签一律转义，防止伪造。
- 条目 `meta` 记 `source`、`key`、`trust`，界面和审计据此把合成内容和真人输入分开。
- `origin = external` 的内容只能进 user 消息，不能进 system。

## 12.6 模块提供什么

以下都是可选模块，通过 `Contribution` 提交，用户可以不用或重写：

| 模块 / 组件 | 提交内容 | Kind |
|---|---|---|
| instructions | AGENTS.md（含工具触碰文件后发现的嵌套 AGENTS.md） | Snapshot，后续变化走 Status |
| skills | 技能目录（首次全量，之后只发变化） | Snapshot / Status |
| env | 工作目录、当前用户、时区 | Snapshot |
| time | 当前时间（可配刷新间隔） | Status |
| todo | 待办清单复述 | Status |
| permission | 权限档位、计划模式切换 | Status |
| budget | 预算、上下文余量将尽 | Status |
| repeat-guard | 同一工具同参数重复调用提醒 | Status |
| goal | goal 轮次 | 通过信封开新回合（13） |

## 12.7 现有代码的迁移

- 工具结果追加（嵌套 AGENTS.md、hooks）改为提交 `Status` 片段，去重记录从内存搬进会话。
- `Suffix` / `inject:` 删除（C4 不设临时注入）。
- 权限档位、todo 从"只给界面"改为同时提交 `Status`。
- `Steer` 成为内核"在下一次调模型前插入"的底层原语（见 13），不直接开放给插件，插件通过信封使用。

## 12.8 现状差距（2026-11-02，T2b 后）

- 已落地：`core/inject` 组装器（`Item` / `Collect` / `Changes` / `Cleared` / `Budget` / `Render` / 转义与哈希）、session 的 `snapshot` / `status` 条目（随检查点持久化、恢复时推导已发哈希）、`Registrar.Status(key, fn)` → `assembly.Statuses()` → `Builder.Statuses` → agent 在每次调模型前收集、只写变化、追加在请求末尾；压缩后 `reset` 按 key 重新注入快照与状态；`Suffix` / `inject:` 旧路径已删（`request_records.suffix` 列保留，不再写入）。

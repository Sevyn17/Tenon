# 13 会话与消息机制

> 状态：定稿草案（2026-11-01），本篇是模块篇。结论来自 2026-11-01 的讨论。先写"内核提供什么"（不可替换），再写"模块提供什么"（可选、可重写）。排期：信封、地址、会话键、守卫在 T3（09 9.6），运行中插入在 T2a（09 9.4），小组模块（群聊、转人工）在 T4（09 9.7），常驻在 T5（09 9.8）。

## 13.1 基本观点

- 一个会话只运行一个智能体（一个定义）。每个智能体只维护自己的会话历史。
- 从智能体的角度看，所有场景都只是"我的会话里收到一封信封"。场景之间的区别只有三点：投到哪个会话、会话由谁在什么时候创建、原始记录存在哪里。
- 只有群聊需要单独存一份原始记录（小组）。单聊和智能体之间都是点对点，会话历史本身就是原始记录。
- 单聊、群聊、工作组、子智能体、定时、转人工都是**模块**，不进内核。内核只提供它们共用的、涉及并发、持久化、安全的机制。

## 13.2 场景归类

| 具体场景 | 类型 | 会话关系 | 原始记录在哪 |
|---|---|---|---|
| 网页上和助手单聊 | ① 单聊 | 一个对话方对应一个会话 | 会话历史 |
| 客服机器人 | ① 单聊 | 每个客户一个会话，共用同一个定义 | 会话历史 |
| IM 私聊机器人 | ① 单聊 | 每个 IM 用户一个会话 | 会话历史 |
| 同步子智能体 | ② 智能体之间 | 父会话下建子会话，结果作为工具结果返回 | 两个会话各存一份 |
| 领导派活给工作组成员 | ② 智能体之间 | 每个成员一个会话，和领导会话点对点发信封 | 两个会话各存一份 |
| 群里有一个机器人 | ③ 群聊 | 机器人在这个群里有一个会话 | 小组 |
| 群里有多个机器人 | ③ 群聊 | 每个机器人在每个群各有一个会话，不跨群共用 | 小组 |
| 定时任务、webhook、后台任务完成 | ④ 事件 | 投给已有会话，或新建会话 | 发出事件的组件，加会话历史 |

## 13.3 内核提供什么

### 两种地址，两条流程

复用还是新建会话，由发送方填的地址决定（02 §2.3）。

**`session:<id>`：投给已有会话**

1. 会话存在。查不到就拒绝（`ErrSessionNotFound`），不自动新建，否则消息会悄悄进入一个没有上下文的新会话。
2. 会话租户与发送方租户一致。
3. 会话状态：空闲或运行中正常投递；休眠先唤醒再投递；预算挂起收下不开回合；已关闭一律拒绝（`ErrSessionClosed`），由发送方新建会话，需要的话把旧会话摘要带过去。
4. 联系守卫（D4）：发送者须是会话创建者、本轮触发者、成员，或同一所属树里的会话，否则拒绝并记 `guard.denied`。
5. 带 `corr` 时按 D3 核对。
6. 写入信箱，按处理方式执行（见下）。

**`agent:<名字>`：新建会话**

1. 解析定义：裸名字只按 租户 → 平台 解析；用户层定义要写全名 `agent:user/<用户>/<名字>`，模型只能解析本会话创建者自己的用户层定义（D7、P2）。
2. 校验联系权限和会话数配额。
3. 带会话键时按键原子查或建（见下）；查到就转入第一条流程。
4. 新建会话：写入创建者、父会话、租户；固定定义版本哈希；按使用配置链算 `[use.*]`；按创建者权限截断 caps（D7）。
5. 第一封信封进信箱，开回合。
6. 返回会话 id。以后发送方用 `session:<id>`。

### 会话键

- 应用或组件投 `agent:<名字>` 时可以带 `key`。内核按 `(租户, 定义, 创建者, key)` 原子地查找或新建，存储层对这四项加部分唯一约束（不带 key 存 NULL，不参与约束，05）。并发的两条消息只会建出一个会话。模型工具不能设置 `key`（B19 修订）。
- 不带 `key` 时每次都新建。
- 常驻定义（D6）不算会话键的特例，单独实现，放在 T5：每租户一个会话，固定 id `resident:<租户>/<名字>`。T5 之前声明 `resident = true` 的定义报“未支持”（B23 修订）。
- `key` 怎么取由模块决定，比如 `(渠道, 用户)`、`(群, 机器人)`、定时任务名。内核只做原子查或建。

### 信封的处理方式

每封信封带 `mode`，由发送方或模块填写，内核按它执行：

| mode | 空闲时 | 正在运行时 | 典型内容 |
|---|---|---|---|
| `wake` | 开新回合 | 在下一次调模型前插入当前回合 | 用户发言、回信、任务完成、定时提醒、需要处理的外部事件 |
| `context` | 不开回合，入队 | 不插入，入队 | 群里不是对它说的发言（背景） |
| `notice` | 不开回合 | 进入下一次状态更新（12） | 配置、权限档位改了，文件被外部修改 |
| `control` | 内核直接处理 | 内核直接处理 | 中断、关闭 |

入队的 `context` 信封在下一次 `wake` 时随它一起进入模型。缺省 `mode` 是 `wake`。

### 运行中收到新消息

- 缺省**插入**：当前工具调用完成后、下次调模型前，把消息加进当前回合。不打断正在进行的模型调用和工具执行。底层原语是现有的 `Steer`（`append`）。
- **打断**：发送方明确发 `control`（中断），停掉当前回合，丢弃未执行的工具调用（`Steer` 的 `redirect`）。

### 合并

- 到同一个边界时，待处理的信封合并成一条用户消息，每条标明发送者和时间，不拼成分不清来源的文字：

  ```
  <msg from="李四" at="18:20">这周进度怎么样</msg>
  <msg from="张三" at="18:30" to="me">查本周订单</msg>
  ```

- 合并按**权限主体**划分：同一个触发用户加同一个 `budget_ref` 才合并，不同权限主体分轮串行（修订 D5：原为"同一发送者"）。回信的权限主体是当初发出请求的那一轮，所以同一用户发起的多个成员回信可以合并。
- 每个会话内按到达顺序处理，会话之间并行。

### 其他

- `corr` 核对（D3）、`hop` 上限、联系守卫（D4）不变。
- v1 一个会话只支持一个用户，即会话创建者。多用户群会话依赖小组模块，放到后面。

## 13.4 模块提供什么

### 单聊渠道（网页、IM 私聊、客服）

例：客户王五在小程序里问"我的订单到哪了"。

1. 渠道组件投 `agent:客服`，带 `key=小程序/王五`。内核查或建会话。
2. 信封 `from=王五`、`mode=wake`。会话开回合，查订单，回复。回复、工具调用和结果写进这个会话的历史。
3. 渠道组件订阅会话输出，把回复发回小程序。

一千个客户就是一千个会话，共用一个定义，彼此并行。

### 子智能体与工作组

- 同步子智能体：结果作为工具结果返回，不走信封。
- 工作组，例：用户对领导 L 说"调研三个竞品"。
  1. L 调 `team_spawn`，内核建三个成员会话（`parent=L`）。L 给每个成员发 `request` 信封，`corr` 由内核签发。
  2. 成员各自运行，做完发回信（`mode=wake`，带 `corr`）到 `session:L`。
  3. L 空闲则开新回合，运行中则插入下一次调模型；几封回信同时到就合并，每段标明成员。
  4. 记录：用户和 L 的对话在 L 会话里，L 和成员的往来两边各一份。界面按会话树读出整个团队过程。
- 成员之间需要互相讨论时，改用群聊模块。

### 群聊（小组）

小组是群聊原始记录的存储，加上投递规则。群记录属于多方，任何一个会话的历史都不等于它。

例：群里有张三、李四，订单助手 A、报表助手 B。

1. 张三发"@订单助手 查本周订单"。IM 渠道写进小组记录（序号 101）。小组判断 A 被 @，向 `agent:订单助手`（`key=群1`）投 `wake` 信封；B 没被 @，不投。
2. A 开回合时，小组把 A 已读位置之后的群记录作为背景补齐，与这次 @ 的消息合并成一条用户消息。
3. A 回复后，小组把回复写进记录（序号 102，发送者 A），再发到 IM 群。
4. 李四 @ 报表助手（序号 103），B 被唤醒，小组补齐 101–103，B 能看到 A 的回答。

规则：

- 每个机器人在每个群各有一个会话，不跨群共用。
- 背景不逐条投递。小组为每个机器人记已读位置，唤醒时一次补齐。
- 机器人的发言只有 @ 了别的机器人才唤醒对方，`hop` 上限兜底，防止互相回复停不下来。
- 两人指令冲突时按到达顺序，模型能看到谁说的，可以反问。
- 智能体提问时只有那一轮的触发者能回答（`corr` 与触发者绑定）。

### 转人工（可选开关）

- 转人工后还是原来的会话，会话 id 不变，历史保留，变的是消息处理方式。
- 开关打开后，会话挂上一个小组。客户、人工客服、机器人三方发言都先写进小组，再由小组决定投给谁。人工客服是人，没有自己的会话。机器人可以改为只在被 @ 时回答，或只给人工客服提供建议回复。
- 开关放在定义或渠道配置里，缺省关闭。随小组模块一起做。

### 事件（定时、webhook、后台任务完成）

例：每天 9 点汇总日报。定时组件发信封（`origin=external`、`mode=wake`；`origin` 由入口类型决定），目标二选一：

- 投常驻会话（T5），日报接着之前的上下文写；
- 投 `agent:日报` 不带 `key`，每天新建会话，互不影响。

后续处理与单聊相同。

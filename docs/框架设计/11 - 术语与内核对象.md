# 11 术语与内核对象

> 状态：草案（2026-11-01）。本目录各篇用到的术语以这里为准。取代 [99 原文存档](<99 - 目标态架构草案（原文存档）.md>) 附录术语表；原表里的"实例""线程"已废弃（B9）。

## 11.1 内核对象

内核只认四种对象：定义、会话、信封、资源。其余东西（记忆、小组、看板、成员表）都是组件的数据。

### 定义（`ybase.Agent`）

智能体就是它的定义。只读、带版本，不运行，没有实例，没有自己的记忆（02 2.1、03）。定义按命名空间区分，不叠加：租户定义与平台定义同名时整份替换；用户层定义放独立命名空间 `user/<用户>/<名字>`，只本人可见，不覆盖平台定义（03 3.5，D7）。

内核字段（封闭面，共 6 个，D1）：

| 字段 | 说明 |
|---|---|
| `id` | 智能体标识，`agent:<名字>` 地址用它 |
| `description` | 一句话说明，给人和其他智能体看 |
| `model` | 模型档位或具体模型 |
| `prompt` | 系统提示词 |
| `tools` | 允许使用的工具 |
| `resident` | 是否常驻，缺省 `false`；见 11.4"常驻会话"。T5 之前声明 `true` 的定义加载时报"未支持"（B23 修订） |

扩展槽与底座字段：

| 字段 | 说明 |
|---|---|
| `use.<组件>` | 挂哪些组件以及给它们的使用配置，由组件的配置结构校验。权限上限放 `[use.permission]`，由 permission 组件经守卫参与 08 8.3 的交集 |
| `x.<键>` | 应用自定义扩展字段，内核不解释 |
| `format`、`version`、`files` | 底座加载时填写：格式版本、整包内容哈希、附带文件 |

### 会话

唯一的执行单位：内部串行，会话之间并行（02 2.2、2.4）。

| 字段 | 说明 |
|---|---|
| `id` | 会话 id，`session:<id>` 地址用它 |
| 定义及版本 | 创建时锁定；定义更新后已有会话继续用旧版本 |
| `tenant` | 所属租户，取自创建时的调用上下文 |
| 创建者 | 内核只记创建者；成员表由成员组件管理。用户层使用配置取创建者（06，D8） |
| 父会话 | 派生出来的子会话才有；决定回收和重启策略 |
| 使用配置 | 创建会话时按 组件缺省 < 定义 < 租户 < 用户 算好存入会话，`*Ctx.Config()` 读取（06，D8） |
| `meta` | 应用写入的业务键，模型改不了（05 5.4） |
| 状态 | 活跃 / 休眠 / 已关闭（细分状态见 02） |
| 会话键 `key` | 可选；`agent:` 投递时由应用或组件带上，内核按（租户, 定义, 创建者, key）唯一约束原子地查找或新建；不带 key 时存 NULL，不参与唯一约束；模型工具不能设置 key（B19 修订，13 13.3） |
| 信箱、历史、检查点、租约 | 见 11.2 |

会话上没有单独的 `resident` 字段；常驻会话的 id 固定为 `resident:<租户>/<名字>`，是否常驻由定义决定（D6）。常驻不算会话键的特例，两者分开实现；常驻放在 T5。

### 信封

所有消息的统一格式（02 2.3）。信封字段只以这张表为准，01、02、05 引用这里，不各自另写（D2）。

| 字段 | 说明 | 谁写 |
|---|---|---|
| `id` | 全局唯一，兼作幂等键 | 调用方可给，缺省内核生成 |
| `from` | 发送者地址；人发的就是应用鉴权后经 `ybase.WithUser` 带入的用户。组件转发用户消息时 `from` 仍是用户，组件记为经手方 `via` | 内核 |
| `to` | 目标地址，见 11.3 | 调用方 |
| `kind` | `request` / `reply` / `notify` / `control` | 调用方 |
| `mode` | 处理方式：`wake`（唤醒会话开一轮）/ `context`（只进背景，下次唤醒时补上）/ `notice`（进状态更新）/ `control`（内核处理，不进模型）；缺省由 `kind` 推出（13 13.3） | 调用方，守卫可降级 |
| `key` | 会话键，只对 `agent:` 地址有效（13 13.3） | 调用方 |
| `corr` | 关联 id。请求时由内核生成不可猜的随机值并登记待回复表；回信带上它回到发出请求的会话（D3） | 内核 |
| `trace` | 一次任务的全部信封共享一个 trace id | 内核 |
| `hop` | 智能体触发智能体的跳数，超限截断（08） | 内核 |
| `origin` | `human` / `agent` / `external`，由入口类型决定（应用鉴权后的用户 = `human`，定时和 webhook = `external`）；沿链传递，组件只能降低不能升高 | 内核 |
| `caps` | 解析后的具体工具集合（如 `[fs_read, shell]`，无通配），触发链上的权限交集（08 8.3） | 内核 |
| `budget_ref` | 记账归属 | 内核 |
| `body` | 正文；长内容只放摘要和续读入口 | 调用方 |
| `deadline` | 可选，超时视为无回复 | 调用方 |

"内核"一栏的字段在投递时由内核写入，调用方传入的值一律忽略。没有 `reply_to`：回信靠 `corr` 反查请求会话。租户不在信封里单独写，信封和它所在的会话同属一个租户。

回信核对（D3）：`corr` 存在、未过期、未用过、发送者 = 预期回复方；只收第一条，其余拒绝并记 `guard.denied`。

### 资源

有地址、可被订阅的共享对象，由组件经 `Registrar` 登记资源类型（04 4.2）。例如小组、看板、外部线程（IM 群、GitHub issue）。订阅 = 订阅者 + 资源 + 匹配器；内核匹配器只做程序规则，模型判断类匹配器由组件登记（09 9.8）。

## 11.2 会话的组成部分

| 术语 | 含义 |
|---|---|
| 信箱 | 会话的收件队列。推理期间到达的信封排队；下一轮只合并同一权限主体（同一触发用户且同一 `budget_ref`）的信封，合并成一条用户消息、每封用 `<msg from at>` 包裹；不同权限主体分轮串行（B21，13 13.3） |
| 待回复表 | 新表 `session_pending`（不复用 `session_requests`，那是模型请求日志）：`corr`、所属会话、预期回复方、deadline、是否已用（D3）。Rewind 作废其后签发的 `corr`，并按所属树取消对应子会话 |
| 历史 | 会话的条目日志，每条带发送者 `from`；是事实来源 |
| 检查点 | 一轮运行中可恢复的位置；崩溃后从这里继续，不重复已成功的工具调用 |
| 租约 | 会话的写锁，同一时刻只有一个节点持有（单写者），带递增的 epoch 防旧持有者写入 |
| 一轮 | 从取信到回复完成的一次运行；权限和记账按本轮主触发者算；回信触发的轮沿用原请求那轮的 `caps` |
| 会话上下文 | 历史、检查点和压缩摘要。内核唯一的"记忆"，会话之间隔离 |

## 11.3 地址

| 地址 | 含义 |
|---|---|
| `session:<id>` | 指定会话，只查不建：找不到或已关闭都拒绝（13 13.3） |
| `agent:<名字>` | 和该智能体新建一个会话并返回会话 id；要求定义存在、发送方通过联系守卫。裸名字只按 租户 → 平台 解析；用户层定义要写全名 `agent:user/<用户>/<名字>`，模型只能解析本会话创建者自己的用户层定义。带 `key` 时按（租户, 定义, 创建者, key）查找或新建；常驻定义（T5）投进 `resident:<租户>/<名字>`，不存在才创建（D6） |
| `human:<名字>` | 人；可挂多个端点，按 `corr` 取第一条回复。缺省只能联系本会话创建者、本轮触发者和成员（D4） |
| `remote:<host>/agent:<名字>` | 远端智能体（T6） |
| 资源地址 | 由资源类型定义，例如 `group:<id>` |

带 `corr` 的回信不需要写目标，直接回到发出请求的会话。地址解析限定在调用上下文的租户内（08 8.8）。

**落地（2026-11-02，v1 收口）：** `human:` 投递接进内核——`Host.Deliver` 收到 `human:` 地址发布 `human.delivered`（v1 没有端点注册表，由界面应答）；工具确认由内核签发 `corr` 并写 `session_pending`、发布带 `corr` 的 `human_requested`；应答可以是回信信封（`KindReply` + `corr`，投回会话后由 `resolveHuman` 交给等待中的工具确认并发布 `human.answered`），也可以是既有 `Confirm` 命令（`call_id`，兼容旧界面）。子会话确认的转发仍由当前 CLI/桌面端做，等 appapi 协议升 2 时删掉。

## 11.4 扩展与运行时术语

| 术语 | 含义 | 见 |
|---|---|---|
| 组件 | 编译进程序的扩展单元（原"内置插件"），全局单例 | 04 |
| 插件 | 外部扩展：插件包、MCP server、扩展进程、远端智能体四档 | 04 4.8 |
| `Registrar` | 组件在 `Setup` 里登记工具、中间件、守卫、资源类型、集合的入口；不暴露定义存储 | 04 4.2 |
| 点位 | 中间件挂载点：`SessionOpen`、`Deliver`、`Turn`、`Context`、`ModelCall`、`ToolCall` | 04 4.3 |
| `*Ctx` | 每次调用传给组件的上下文：`Tenant()`、`Session()`、`Trigger()`、`Envelopes()`、`Config()`、`Meta()`、`Trace()` | 04 4.4 |
| `SessionLocal[T]` | 按会话持有的资源（shell 进程、浏览器），随会话休眠回收 | 04 4.4 |
| 守卫 | 内核在投递、新建会话、调模型、调工具前做的检查：联系名单、权限、预算、并发、跳数 | 08 |
| `GuardRule` | 组件登记的守卫规则，返回 Deny / Allow / Abstain；任一 Deny 即拒绝，Allow 只能放开 `session:` 投递的缺省限制（D4） | 08 |
| 主触发者 | 本轮合并的信封所属的权限主体（同一触发用户、同一 `budget_ref`）；`Trigger()` 返回它，权限和记账按它算 | 08 8.3 |
| 状态更新 | 每次调模型前内核收集各组件按 `key` 提交的状态，只发有变化的 key，合并成一条单独的 `status` 条目写进历史，渲染在末尾；已发哈希从 `status` 条目推导（B16 修订） | 12 |
| 注入预算 | 注入内容的上限：单 key 上限（超出截断或写文件给路径）、单次状态更新总上限（低优先级先丢）；压缩后按 key 重新注入 | 12 |
| 小组 | `group` 模块的资源：保存群原始记录和投递规则；@ 才唤醒，其余只推进各机器人的已读位置 | 13 13.4 |
| 模块 | 框架里可选的 Go 包（如 `ybase/context`、`ybase/chat`、`ybase/group`），一个模块含若干组件；只能用公开扩展点 | 01 1.2 |
| 组件配置 | 运维配置链：代码缺省 < `ybase.toml` < 环境变量，启动时生效，定义和用户改不了（D8） | 06 |
| 使用配置 | `[use.*]` 链：组件缺省 < 定义 < 租户 < 用户，创建会话时算好；`limit` 字段守卫每轮按触发者再取最小 | 06 |
| 派生 | 创建带父会话链接的子会话，即子智能体 | 02 2.2 |
| 所属树 | 父子会话构成的树，带 `restart` / `give_up` / `escalate` 策略 | 02 2.2 |
| 常驻会话 | T5。定义声明 `resident = true`：每租户一个，id 固定 `resident:<租户>/<名字>`；可休眠不回收，重启后有待处理信封才唤醒 | 02 2.2 |
| `Store` | 存储接口，用 `ybase.WithStore` 装配，不是组件 | 05 |
| `Collection` | 组件声明的数据集合；分区 = 租户 + 组件声明的 `Partition`，事务也在 Collection 上按这个分区 | 05 |
| 定义来源 | 返回定义包的接口；按命名空间区分不做字段合并（租户同名整份替换），用户层走独立命名空间 `user/<用户>/<名字>` | 03 3.5 |
| 记忆 | `memory` 组件从会话提炼的派生数据，按用户等键分区；不属于智能体 | 02 2.5 |

## 11.5 废弃术语

| 旧术语 | 现在 |
|---|---|
| 实例 | 删除。并行靠会话，不靠多开实例（B9） |
| 线程 | 就是会话 |
| 实例信箱 | 会话信箱 |
| 按 `meta.user` 区分用户 | `ybase.WithUser(ctx, u)`，记为信封 `from` |
| `runtime.Builder` | `ybase.New` |
| `MetaSource` / `MetaTrust` | 信封 `origin` |
| 定义字段 `name` / `permissions` | `id` / `[use.permission]`（D1） |
| 信封 `reply_to` | 删除，回信靠 `corr`（D2） |
| 会话字段 `resident` | 由定义声明，会话 id 固定（D6） |
| 定义创建者默认可联系 | 删除（D4） |

## 9.2 T1a 定义与存储

- **S1 补全**：会话表保留旧 `agent_version` 整数列不用，新增 `agent_hash TEXT` 存定义整包内容哈希；补 `creator`、租约（`lease_holder` + `lease_epoch`，T2a 启用）、`meta` 列（已完成）。再加会话键列 `session_key`（不带 key 存 NULL）和部分唯一索引（租户, 定义, 创建者, key）`WHERE session_key IS NOT NULL`；`use_config` 列；`definitions.version` 改存哈希（新列，旧列保留）；`SessionMeta.Meta`。
- 补 v2 带数据库升级到 v3 的测试：旧库有数据，升级后旧会话可读，旧代码仍能读新库。
- `Store` 接口（05）+ SQLite 实现 + 内存实现；`ybasetest` 一致性测试两个实现都过。
- 回归快照基线：现有 CLI / 桌面端的典型对话录成快照，之后每步对比。
- 定义加载 `core/agentdef`：定义只认 6 个内核字段（`id`、`description`、`model`、`prompt`、`tools`、`resident`），权限在 `[use.permission]`（D1，T1 只声明上限，T3 再与 `caps` 求交）；按命名空间加载平台 / 租户 / `user/<用户>/<名字>`，不做字段合并（D7）；裸名字只按 租户 → 平台 解析（P2）；`resident = true` 报"未支持"。
- 单机租户恒为 `local`，经 ctx 带入；创建者缺省 `local`。
- **验收用例**：同名租户定义整份替换平台定义，不做字段合并；用户层定义只在写全名时解析到；v2 带数据升级测试通过。

## 9.3 T1b 组件与配置

- `Component` / `Registrar` / `*Ctx`（04）；工具不再按会话重造：`runtime.Builder.Build(id, child)` 改为装配期登记一次，调用时传 `*Ctx`（04 4.4）。
- 两条配置链：组件配置（代码缺省 < `ybase.toml` < 环境变量）和使用配置 `[use.*]`（组件缺省 < 定义 < 租户 < 用户），后者在创建会话时算好存进 `use_config`，`*Ctx.Config()` 读取（D8）。
- 用户层越权拒绝：用户层定义写了超出创建者有效权限的工具，在写定义接口上拒绝；已存定义在创建者降权后加载不报错，靠运行时求交兜底（P1、P9）。
- 子智能体、工作组改用内置定义模板加载，行为不变；删掉按 ID 猜角色的代码（`plugins/collab/workgroup/plugin.go:53`）。模板放平台命名空间，与租户同名定义冲突时报错。
- `ybase.New` + 选项；写错 `[use.<组件>]` 字段、引用未装组件，在 `ybase.New` 里一次性报错（03 3.6、07 7.2）；未 `Start` 调用运行接口返回 `ErrNotStarted`。
- `kernel/core/` 不再 import `store/sqlite`；所有按 id 的查找带租户条件。
- 组件不再各自假设 SQLite：现有 `p_<名>_` 表先统一显式声明 `Requires{SQL: true}`，T4 `Collection` 交付后再迁过去（B2）。
- **回归**：现有全部测试通过；桌面端和 CLI 日常对话、子智能体、工作组手工走一遍，回归快照无差异。
- **验收用例**：用户层定义写了超出创建者权限的工具，保存时被拒；`[use.*]` 写错字段启动即报错。

## 9.4 T2a 生命周期

- 同一智能体的多个会话同时推理，互不等待。
- 运行中到达的同一权限主体（同一触发用户 + 同一 `budget_ref`）的 `wake` 信封排队，在下一次调模型前合并插入；插入确认和检查点在同一事务里写（B20、B21，13 13.3）。
- 并发上限生效：超出上限的会话排队，不报错。
- 租约带纪元：旧节点丢租约后的写入被存储拒绝（02 2.2）。
- 会话空闲后休眠，下一封信封到达时唤醒，从检查点继续；休眠与投递并发时不丢唤醒，另有兜底扫描捡起漏唤醒的会话。
- 进程在一轮运行中途被杀，重启后从最后一个检查点继续，不重复已成功的工具调用（02 2.6）。
- 所属树策略 `restart | give_up | escalate` 可配，缺省 `give_up`。
- 预算挂起、中断、Fork、Rewind 按 02 2.2 的状态机走，并发对应事件（07 7.5）；Rewind 作废其后签发的 `corr`，并按所属树取消对应子会话。
- **验收用例**：杀进程注入测试；租约过期后另一个节点接管会话，旧节点迟到的写入被拒；休眠检查与投递交错的竞态测试（假时钟 + 故障注入）。

## 9.5 T2b 上下文构建

- 上下文组装器按 12 的分层构建请求；系统提示词在会话进行中不变（B15）。
- 状态更新：每次调模型前收集各组件按 `key` 提交的状态，只发变化的 key，写成一条单独的 `status` 条目渲染在末尾；已发哈希从 `status` 条目推导（B16 修订）。
- 注入预算：单 key 上限（超出截断或写文件给路径）、单次状态更新总上限（低优先级先丢）（B17）。
- 压缩后另写 L2 快照，不占状态更新预算；按 key 重新注入仍有效的最新版本。
- 注入内容带来源与信任标签，由内核写入。
- 删除 `Suffix` / `inject:` 旧路径（`core/agent/agent.go:232`）。
- **验收用例**：同一状态连续两次调模型只注入一次；压缩后状态仍在；超预算时低优先级条目被丢弃且有记录；重放同一会话得到相同请求前缀（缓存安全）。

## 9.6 T3 信封与守卫

- 信封全字段与 `mode`（11）；`from`、`origin`、`hop`、`caps`、`budget_ref`、`trace` 由内核写入，调用方传入的值忽略（D2）；`origin` 由入口类型决定，组件只能降低可信度。
- 按权限主体合并（B21）；只有 `wake` 会插入，`notice` 进状态更新，`context` 只排队（P6）。
- `corr` 由内核签发，落新表 `session_pending`（不复用 `session_requests`，那张是模型请求日志），回信按存在、未过期、未用过、发送者 = 预期回复方核对，只收第一条（D3）。
- 发件箱：投递和本轮检查点同事务写入，提交后再派发。
- `session:` 只查不建，找不到或已关闭都拒绝（B18）；`agent:` 带会话键时 `FindOrCreate`（B19 修订）。
- 组件发信用 `Registrar.Mailer()` 返回的绑定句柄，组件记为经手方 `via`（P4）。
- 工具确认、向人提问都走信封投递到 `human:` 地址，原来的子会话转发确认逻辑删除；子智能体同步调用结果仍回到工具结果，异步工作组走 `reply`。
- 守卫第一版：联系名单、权限交集（`caps`）、跳数上限、`origin = external` 传递；`GuardRule` 的 Deny / Allow / Abstain 合并规则（08，D4）；`control` 只允许创建者、父会话、内核和登记组件（P7）。
- `explain <trace>` 能列出一次调用经过的会话、信封和工具。
- **验收用例**：低权限智能体调用高权限智能体，后者不能执行前者没有的工具；伪造或重放的 `corr` 回信被拒并记 `guard.denied`；不在同一所属树、也没有规则放开的会话互投被拒；跳数超限的链路被截断并回错；两个并发 `agent:` 投递带同一 key 只产生一个会话。

## 9.7 T4 资源、集合、事件、插件、小组

- 通用资源 + 订阅（订阅者、资源、匹配器）跑通；内核匹配器只做程序规则。
- `Collection` 的四种操作在 SQLite 和内存实现上都通过同一套一致性测试（B8）。
- 事件来自持久日志、有序号、可续读；异步投递，订阅方处理失败不影响主流程（B7）。
- 插件包（`ybase-plugin.toml`）和 MCP server 能装、能开关、能被 `explain` 看到。
- 小组模块：群聊每个机器人每群一个会话，@ 才唤醒，背景按已读位置补齐（B22）；转人工开关；多人会话，本轮触发者可以中断本轮。
- **验收用例**：用两个定义文件加一个资源配置拼出"带 @ 的小组"，不写 Go 代码；多人会话里低权限成员的消息触发不了高权限工具。

## 9.8 T5 常驻与外部入口

- `resident = true` 的定义每租户只有一个会话，固定 id `resident:<租户>/<名字>`；发往 `agent:<名字>` 时查到就投、查不到就建；不回收，进程重启后有待处理信封才唤醒（D6）。常驻和会话键分开实现。
- 定时触发、外部事件通过统一入口转成信封，带 `origin = external`。
- 模型判断类匹配器只能由组件登记，消耗记入订阅者预算。
- **验收用例**：用定义文件拼出 Router + Worker，外部事件进来后由 Router 分发；两个节点同时向常驻定义投递，只产生一个会话。

## 9.9 T6 远端

- `remote:` 地址可投递；本地定义公开部分导出 Agent Card。
- 扩展进程协议（JSON-RPC 2.0 over stdio，MCP 超集）能贡献资源类型、匹配器、桥接。
- **验收用例**：跨机器调用时联系名单、权限交集、预算记账照样生效。

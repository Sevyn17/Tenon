## 9.4 T2a 生命周期

- 同一智能体的多个会话同时推理，互不等待。
- 运行中到达的用户消息排队，在下一次调模型前插入（不依赖信封；按权限主体合并 `wake` 信封移到 T3）。
- 并发上限生效：超出上限的会话排队，不报错。
- 租约带纪元：旧节点丢租约后的写入被存储拒绝（02 2.2）。
- 会话空闲后休眠，下一封信封到达时唤醒，从检查点继续；休眠与投递并发时不丢唤醒，另有兜底扫描捡起漏唤醒的会话。
- 进程在一轮运行中途被杀，重启后从最后一个检查点继续，不重复已成功的工具调用（02 2.6）。
- 所属树策略 `restart | give_up | escalate` 可配，缺省 `give_up`。
- 预算挂起、中断、Fork、Rewind 按 02 2.2 的状态机走，并发对应事件（07 7.5）；Rewind 按所属树取消对应子会话（作废其后签发的 `corr` 移到 T3，`corr` 在 T3 才有）。
- **验收用例**：杀进程注入测试；租约过期后另一个节点接管会话，旧节点迟到的写入被拒；休眠检查与投递交错的竞态测试（假时钟 + 故障注入）。

**状态（2026-11-02）：T2a-2 已落地。** 存储层加会话生命周期状态：`store.SleepStore`（`SessionStatus` / `SetSessionStatus` 条件迁移 + 纪元校验 / `SessionsWithStatus`），sqlite 与 memstore 同语义，迁移不满足返回 `store.ErrStateMismatch`（storetest 的 `SleepStatus` 两个实现都覆盖）。host：`Host.SleepAfter`（空闲超时，0 = 不休眠）>0 时 actor 主循环带定时器，空闲且信箱为空、无未完成回合时 `SetSessionStatus(active→sleeping, epoch)` 成功即发布 `session_sleep` 并退出（defer 释放租约与对象）；`open` 抢到租约后读状态，`sleeping` 用新纪元迁回 `active` 并发布 `session_wake`（投递路径即唤醒），`deleted` 返回 `ErrClosed`。`Host.ScanOnce` 扫「状态 sleeping 且信箱有待处理信件」的会话并 Open 唤醒（并发扫描由租约与状态条件决定谁生效），`Host.ScanLoop` 周期跑；boot `StartOptions.SleepAfter` 与 `ybase.WithSleepAfter` 打开时启动/`Close` 停止。验收用例：`core/host/t2a2_test.go` 的 `TestIdleSleepsAndWakesOnOpen` / `TestScanOnceWakesSleepingWithMail` / `TestRunningTurnDoesNotSleep`（假时钟以短超时替代）。休眠与投递的"先写后查"细节完全对齐 02 2.2 现有文字；状态机其余部分已随 T2a-3 落地（见下一段），`wake` 合并插入与 `corr` 作废仍待 T3。

**状态（2026-11-02）：T2a-1 已落地。** 存储层加会话写租约：`store.LeaseStore`（`AcquireLease` / `RenewLease` / `ReleaseLease`）+ `Checkpoint.Epoch`，sqlite 与 memstore 同语义，旧纪元写入返回 `store.ErrLeaseLost`（storetest 的 `LeaseFencing` 两个实现都覆盖）；`Host` 打开会话即按 holder 抢租约、退出时释放（`Host.Holder` 可配，缺省进程内生成），换宿主接管纪元后旧写者下一次检查点失败并关闭 actor。并发上限用 `Host.Limit`（同时推理的会话数，超出排队不报错，`turn` 开头取槽位）。运行中到达的用户消息在需求边界立即写入当前回合（`session.Core.MidInput`，写一条 user 条目、不新开回合，下一次调模型前可见）；`drainInbox` 用 `processing` 集合避免同一条 inbox 被回合中插入路径重复消费。崩溃续跑沿用既有检查点差异写（`TestConfirmCommandAndCrashResume`）。验收用例：`core/host/t2a1_test.go` 的 `TestConcurrentSessionsInfer` / `TestConcurrencyLimitQueues` / `TestMidTurnUserMessageInserted` / `TestLeaseTakeoverRejectsStaleWrites`，`core/session/midinput_test.go` 两条；`TestSecondHostConflicts` 改为把租约纪元失效也视为「旧写者被拒」。

**状态（2026-11-02）：T2a-3 已落地。** 所属树策略与状态机四件事：
- 所属树策略：`Agent.Origin`（空 = 顶层，`subagent` / `member` / `fork` / `side` = 派生）从会话行恢复；`Host.TreePolicy`（`restart | give_up | escalate`，缺省 `give_up`）+ `Host.TreeRestarts`。`turn` 现在返回 `(EndReason, error)`，新增 `turnErr` 把「回合以 `EndFailed` 收尾」转成错误，统一交给 `actor.turnFailed`：发布 `turn.failed`、把等待态收尾成 Idle、提交 `run_state=idle`；顶层会话错误照旧交回句柄；子会话按策略 `restart`（最多 N 次 `Agent.Retry`，失败后退出）、`escalate`（发布 `session.escalated` 后退出）、`give_up`（退出并让句柄得到错误）。
- 预算挂起：存储加 `store.StatusSuspended`；`Host.Suspend(ctx, id, reason)`（空闲会话、条件迁移 active→suspended、`rt.suspended` 记原因、`run_state=suspended`、发布 `session.suspended`）。挂起期间 `drainInbox` 直接返回、信箱保留，`sleep` 跳过；`Resume` 命令看到 `suspended` 先迁回 `active` 并发布 `session.resumed`，再走原有续跑路径。预算来源（守卫）与挂起超时转中断仍随 T3。
- 中断：`turn` 以 `EndCancelled` 收尾时发布 `turn.interrupted`；会话回 Idle、信箱保留、可继续收信（`Cancel` 语义沿用 T2a-1 的 `session.Core.Cancel`）。
- Fork / Rewind：`Host.Fork` 成功后发布 `session.forked`（from / upto / origin）；Rewind 提交后发布 `session.rewound`（to），并按所属树关闭内存里已打开的子会话（发布 `session.closed`，reason=`parent_rewind`）；`corr` 作废与关闭时对未用 `corr` 回错随 T3。事件名按 07 7.5，原有 `turn_start` / `turn_end` 保留到 T3 协议升级。
验收用例：`core/host/t2a3_test.go` 的 `TestTreePolicyGiveUpChild` / `TestTreePolicyRestartChild`（模型第一次失败、第二次成功，断言调用 2 次）/ `TestInterruptPublishesAndKeepsSession` / `TestSuspendStopsTurnsUntilResume`。`go vet ./...`、`go test ./... -count=1` 全绿，两套回归快照无差异。

## 9.5 T2b 上下文构建

- 上下文组装器按 12 的分层构建请求；系统提示词在会话进行中不变（B15）。
- 状态更新：每次调模型前收集各组件按 `key` 提交的状态，只发变化的 key，写成一条单独的 `status` 条目渲染在末尾；已发哈希从 `status` 条目推导（B16 修订）。
- 注入预算：单 key 上限（超出截断或写文件给路径）、单次状态更新总上限（低优先级先丢）（B17）。
- 压缩后另写 L2 快照，不占状态更新预算；按 key 重新注入仍有效的最新版本。
- 注入内容带来源与信任标签，由内核写入。
- 删除 `Suffix` / `inject:` 旧路径（`core/reqlog/reqlog.go` 的 `Suffix` 字段与 `inject:<来源>` 统计类别，`core/agent/persist.go` 的持久化）。
- **验收用例**：同一状态连续两次调模型只注入一次；压缩后状态仍在；超预算时低优先级条目被丢弃且有记录；重放同一会话得到相同请求前缀（缓存安全）。

## 9.6 T3 信封与守卫

- 信封全字段与 `mode`（11）；`from`、`origin`、`hop`、`caps`、`budget_ref`、`trace` 由内核写入，调用方传入的值忽略（D2）；`origin` 由入口类型决定，组件只能降低可信度。
- 按权限主体合并（B21）；只有 `wake` 会插入，`notice` 进状态更新，`context` 只排队（P6）。运行中到达的同一权限主体（同一触发用户 + 同一 `budget_ref`）的 `wake` 信封排队，在下一次调模型前合并插入；插入确认和检查点在同一事务里写（B20，13 13.3；从 T2a 移来）。
- Rewind 作废其后签发的 `corr`（从 T2a 移来）。
- `corr` 由内核签发，落新表 `session_pending`（不复用 `session_requests`，那张是模型请求日志），回信按存在、未过期、未用过、发送者 = 预期回复方核对，只收第一条（D3）。
- 发件箱：投递和本轮检查点同事务写入，提交后再派发。
- `session:` 只查不建，找不到或已关闭都拒绝（B18）；`agent:` 带会话键时 `FindOrCreate`（B19 修订）。
- 组件发信用 `Registrar.Mailer()` 返回的绑定句柄，组件记为经手方 `via`（P4）。
- 工具确认、向人提问都走信封投递到 `human:` 地址，原来的子会话转发确认逻辑删除；子智能体同步调用结果仍回到工具结果，异步工作组走 `reply`。
- 守卫第一版：联系名单、权限交集（`caps`）、跳数上限、`origin = external` 传递；`GuardRule` 的 Deny / Allow / Abstain 合并规则（08，D4）；`control` 只允许创建者、父会话、内核和登记组件（P7）。
- `explain <trace>` 能列出一次调用经过的会话、信封和工具。
- **验收用例**：低权限智能体调用高权限智能体，后者不能执行前者没有的工具；伪造或重放的 `corr` 回信被拒并记 `guard.denied`；不在同一所属树、也没有规则放开的会话互投被拒；跳数超限的链路被截断并回错；两个并发 `agent:` 投递带同一 key 只产生一个会话。

## 9.7 T4 资源、集合、事件、插件、小组

- 通用资源 + 订阅（订阅者、资源、匹配器）跑通；内核匹配器只做程序规则。
- `Collection` 的四种操作在 SQLite 和内存实现上都通过同一套一致性测试（B8）。
- 事件来自持久日志、有序号、可续读；异步投递，订阅方处理失败不影响主流程（B7）。
- 插件包（`ybase-plugin.toml`）和 MCP server 能装、能开关、能被 `explain` 看到。
- 小组模块：群聊每个机器人每群一个会话，@ 才唤醒，背景按已读位置补齐（B22）；转人工开关；多人会话，本轮触发者可以中断本轮。
- **验收用例**：用两个定义文件加一个资源配置拼出"带 @ 的小组"，不写 Go 代码；多人会话里低权限成员的消息触发不了高权限工具。

## 9.8 T5 常驻与外部入口

- `resident = true` 的定义每租户只有一个会话，固定 id `resident:<租户>/<名字>`；发往 `agent:<名字>` 时查到就投、查不到就建；不回收，进程重启后有待处理信封才唤醒（D6）。常驻和会话键分开实现。
- 定时触发、外部事件通过统一入口转成信封，带 `origin = external`。
- 模型判断类匹配器只能由组件登记，消耗记入订阅者预算。
- **验收用例**：用定义文件拼出 Router + Worker，外部事件进来后由 Router 分发；两个节点同时向常驻定义投递，只产生一个会话。

## 9.9 T6 远端

- **验收用例**：跨机器调用时联系名单、权限交集、预算记账照样生效。

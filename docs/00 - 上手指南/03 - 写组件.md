# 写组件

工具和定义够用时不需要组件。要按会话加工具、加系统提示、拦调用、在组件之间共享服务，就写一个组件。只 import `tenon`。完整代码见 `examples/component/main.go`。

## 1. 最小的组件

```go
type kit struct{}

func (kit) Name() string                    { return "support-kit" }
func (kit) Setup(cx *tenon.Registrar) error { return nil } // 登记：点位、服务、守卫
func (kit) Start(sc *tenon.Scope) error     { return nil } // 起后台工作

app, err := tenon.New(tenon.Default(), tenon.With(kit{}), …)
```

- `Setup` 在 `New` 里按依赖顺序调用，只登记，不做耗时的事。出错时 `New` 失败。
- `Start` 在 `App.Start` 里调用。后台工作用 `sc.Go(name, func(ctx) error)`，`ctx` 在 `Close` 时取消；清理用 `sc.OnClose(func(ctx) error)`。
- 组件名在装配里唯一，和内置组件重名时报错。

## 2. 在点位上登记

```go
tenon.RegisterAt(cx, tenon.PointTools, "orders", tenon.ToolsOf(60, query, refund))
```

登记项的类型由点位决定，写错编译不过：

| 点位 | 登记项 | 用途 |
|---|---|---|
| `PointTools` | `ToolsEntry`（用 `ToolsOf(order, 工具…)` 构造） | 会话工具。`order` 决定在请求里的位置，内置工具在 10–90 |
| `PointSystemBlock` | `BlockEntry{Order, Func}` | 系统提示块。`Func(*SessionCx)` 返回 `*SystemBlock{Text}`，返回 nil 表示这个会话不加 |
| `PointLayer` | `LayerEntry{Guard, Order, Func}` | 会话层：包住工具调用做拦截或改写 |
| `PointAfterTurn` | `AfterTurnFunc(func(id string, end EndReason))` | 回合结束通知 |

```go
tenon.RegisterAt(cx, tenon.PointSystemBlock, "support-rules", tenon.BlockEntry{Order: 10,
    Func: func(sc *tenon.SessionCx) (*tenon.SystemBlock, error) {
        return &tenon.SystemBlock{Text: "回答订单问题前先用 order_query 查。"}, nil
    }})
```

`SessionCx` 带会话 id、工作目录、定义（`Def`），可以按会话决定加不加。`ToolsEntry.Visible` 也是这个用法。

用 `WithTools` 加的工具每个会话都有；放在组件的 `PointTools` 里，可以和配置、服务放在一起，也可以用 `Visible` 按会话挑。

## 3. 配置

组件实现 `Info()`，声明配置结构体：

```go
type catalogConfig struct {
    Orders  map[string]string `cfg:"orders"`
    Blocked []string          `cfg:"blocked"`
    Limit   int               `cfg:"limit" default:"20"`
}

func (catalog) Info() tenon.ComponentInfo {
    return tenon.ComponentInfo{Config: &catalogConfig{}}
}

func (catalog) Setup(cx *tenon.Registrar) error {
    c := cx.Config().(*catalogConfig) // 已解码、已填缺省值
    …
}
```

应用用 `WithConfig` 给值：

```go
tenon.WithConfig("catalog", map[string]any{"orders": map[string]any{"A1": "已发货"}, "blocked": []any{"A2"}})
```

未知的键、类型不对的值在 `New` 里报错。不实现 `Info` 的组件不收配置，给了 `WithConfig` 也报错。

## 4. 服务

一个组件提供、别的组件用。键带类型：

```go
type Catalog interface{ Status(id string) (string, bool) }

var catalogKey = tenon.NewKey[Catalog](./"catalog")
```

提供方在 `Info` 里写 `Provides`，在 `Setup` 里 `Provide`：

```go
func (catalog) Info() tenon.ComponentInfo {
    return tenon.ComponentInfo{Config: &catalogConfig{}, Provides: []string{catalogKey.Name()}}
}
// Setup 里
tenon.Provide[Catalog](cx, catalogKey, mapCatalog(c.Orders))
```

使用方在 `Requires` 里写 `catalogKey.Need()`（必需）或 `catalogKey.Maybe()`（可选），在 `Setup` 里取：

```go
cat, err := tenon.Get(cx, catalogKey)              // 必需
cat, ok, err := tenon.GetOptional(cx, catalogKey) // 可选：提供方不在装配里时 ok 为 false
```

装配按 `Requires` 排顺序：提供方的 `Setup` 先跑。`With` 里谁先谁后无所谓。必需的服务没人提供、两个组件提供同一个服务，都在 `New` 里报错。

## 5. 守卫

```go
cx.Guard(tenon.GuardRule{Name: "blocked-orders", On: tenon.GuardToolCall,
    Check: func(r tenon.GuardRequest) (tenon.Verdict, string) {
        if r.Tool == "order_query" && frozen(r.Args) {
            return tenon.Deny, "订单已冻结"
        }
        return tenon.Abstain, ""
    }})
```

| 位置 | 请求里有 | 被拒时 |
|---|---|---|
| `GuardToolCall` | `Tool`、`Args`、`Risk` | 失败结果交给模型（"工具 X 被守卫拒绝：原因"），这一轮继续 |
| `GuardSessionOpen` | `Agent`（定义名） | `NewSession` 后的第一次 `Send` / `Stream`、`Ask` 返回 `ErrDenied` |
| `GuardDeliver` | `Envelope` | 信封投递失败，记 `guard.denied` |

同一位置上任何一条 `Deny` 就拒绝；全是 `Abstain` 按内核缺省。`GuardToolCall` 先于权限组件执行：守卫拒绝的调用不会再弹确认。

守卫只回答"行不行"。要改参数、改结果，在 `PointLayer` 登记一个变换层。

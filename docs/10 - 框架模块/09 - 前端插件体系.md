## 2. 竞品

| 维度 | DSH | opencode | pi |
|---|---|---|---|
| 前端插件身份 | 后端插件包在 `package.json` 声明 `dsh.client`，导出 `./client` bundle；与后端同一个包 | GUI 插件 `Plugin.define` 为 manifest，id 由宿主分配（内置在 `compose` 给 key，bundle 用对应 server 插件 id）；id 作所有贡献 id 的前缀 | 扩展同时注册工具、命令、UI |
| 加载 | 宿主扫描已启用条目组合启动图；浏览器按需懒加载；bundle 只注册 factory，首次使用才执行 | 宿主先读 manifest，再懒加载 `windowEntry` / `mainEntry` | 进程内加载 |
| 动态组合 | 启用 / 停用插件经 HMR 同步到已打开页面，停用后回收模块与样式；release 不一致不应用 | 贡献随作用域（generation）结束 | — |
| 贡献点 | Slot（普通 entry）与 Component Factory；三栏 AppFrame 布局；资源协议（`dsh-resource://`）；`/` 命令；会话渲染 target；设置 slot（页面、标题栏操作、插件标签页、引导） | 注册表：Command、MenuItem、Panel（会话侧栏 tab）、SettingsPage、TitlebarItem、ComposerPill、Slot（`window.bottom`、`session.header`…）、LinkHandler、Style、MenubarItem | `ctx.ui`：notify / confirm / select / input / custom、`setStatus`（页脚）、`setWidget`（编辑器上方）；`registerCommand` |
| 数据绑定 | 插件是普通组件，收类型化 props；渲染器把会话 / 工作区 observable 绑定为 selector，插件不自己订阅 | `props.session` 是响应式 getter，不复制；`ctx.use(token)()` 返回 `Live<T>`（pending / active / inactive-disabled / inactive-failed） | — |
| 设置 | 按命名空间读写宿主设置文档、schema 校验、修订号防覆盖；`whileServed(ns)`：所有者插件被组合时才出现页面 | SettingsPage 可是整页、宿主页上的一节、或一节里的几行 | — |
| 失败 | Factory 错误走监督通道，不拖垮共享定义 | 抛错的贡献什么也不渲染并记录，窗口其余部分继续工作；不可用的功能显示不可用状态，"never a dead button" | `hasUI = false` 时对话类方法降级 |
| 第三方 | 插件市场可安装 | 内置与第三方用同一 SDK；内置独有能力走 `builtin` 子路径 | 同进程扩展 |

可借鉴：
1. **前后端同一插件身份**（DSH、opencode）：前端贡献挂在后端插件名下，后端装配了才激活。
2. **贡献点是有类型的注册表**（opencode 的 Registry 列表最清楚），不是一个万能 slot。
3. **数据由宿主绑定进 props**（DSH、opencode）：插件不自己订阅事件，避免泄漏和重复订阅。
4. **四态可用性**（opencode `Live<T>`）：pending / active / disabled / failed，界面上不出现点了没反应的按钮。
5. **错误隔离**：一个贡献抛错只影响它自己。
6. **设置按命名空间、跟随所有者**（DSH `whileServed`）= 原设计"由装配清单驱动"。
7. **UI 原语抽象到可降级**（pi `ctx.ui`、`hasUI`）：同一插件在 TUI / Web / 无界面模式都能跑。

## 3. 和原设计的差异与取舍

| 点 | 原设计 | DSH / opencode | 取舍 |
|---|---|---|---|
| 运行期插件代码 | 零；只三种声明式形态 | 插件 bundle 运行期加载 | **分级**：第一方插件前端代码编译期内置、按插件 chunk 懒加载（取懒加载的好处，不引入运行期下载代码）；第三方只用声明式形态。外部前端 bundle 与 WASM 外部插件一起推迟（原设计 v2） |
| 贡献粒度 | 只有"专属页面" | 侧栏面板、头部、composer、标题栏、命令、菜单 | **补齐**：原设计漏了"往工作台某个位置挂一块"的粒度 |
| 工具结果渲染 | 未写 | 会话渲染 target / 卡片 | **新增**：按工具名或 `Attrs.present` 注册结果渲染器，无渲染器用通用卡片 |
| 配置 | 三层 | 设置 slot + 命名空间 | 一致，保留三层 |

## 4. 推荐方案

### 4.1 三类贡献

| 类别 | 贡献点（注册表） | 兜底 |
|---|---|---|
| 工作台 | `Panel`（侧栏 tab）、`Slot`（`session.header` / `composer.above` / `window.bottom` / `status`）、`Command`（命令面板 + `/` 命令 + 快捷键）、`MenuItem`、`ItemRenderer`（按条目 kind / 工具名 / `Attrs.present` 渲染）、`ExtRenderer`（按 `client_ext` 键）、`LinkHandler` | 无渲染器 → 通用工具卡片（参数 + 结果预览）；未知 ext 键忽略 |
| 配置 | `SettingsPage`（整页 / 某页的一节 / 一节里的几行）：L1 由 config schema + UI 注解自动生成；L2 自定义组件 | 默认 L1 |
| 会话内交互 | A2UI（`ui_show` / `ui_ask`），确认与提问走挂起记录（`HumanRequested`） | `fallback_text` |

### 4.2 规则

1. **身份与激活**：前端贡献声明在后端插件的 manifest 里；只有后端装配了该插件，前端才激活它的贡献（与"装配即可用"对称）。设置页区块随所有者插件出现与消失。
2. **代码来源**：第一方编译期内置、按插件懒加载；第三方只有声明式形态（A2UI、ext + 通用渲染器、Schema 表单），不执行第三方前端代码。
3. **数据绑定**：贡献收宿主绑定好的 props（会话视图、工作区、插件 ext）；不直接订阅事件总线。
4. **可用性四态**：每个贡献依赖的后端能力有 pending / active / disabled / failed 四态，界面显示对应状态。
5. **错误隔离**：贡献抛错只渲染错误占位并记日志。
6. **作用域**：贡献随前端作用域回收（窗口 / 会话 / 插件），与后端作用域（plugin-manager L1）同构。
7. **多端同一模型**：CLI / TUI / Web 实现同一组贡献点，各端只做自己能做的（TUI 的 Panel 可以是可切换视图，CLI 只实现 Command、ItemRenderer、确认提示）。插件能力声明 `surfaces`，缺失时降级（pi `hasUI` 思路）。

## 5. P0 需要预留的后端接口

| 接口 | 放在 | 里程碑 |
|---|---|---|
| 插件 config schema 带 UI 注解：`title`、`description`、`group`、`widget`、`overridable` | plugin-manager `Meta.Config` | M2 |
| manifest 增 `client` 段：声明贡献点（类型 + id），不含代码 | plugin-manager `Meta` | M2 |

| 宿主管理路由：插件清单、config schema、读写配置（带修订号） | session-host / CLI | M4（CLI 先用，P5 Web 复用） |

CLI 在 P0 实现 `Command`（`/` 命令）、`ItemRenderer`（工具卡片的终端版）、确认提示三类贡献点。

## 5.1 长会话加载（review-1，P5 实现，存储侧 M1 预留）

- 存储：按 `(session_id, idx)` 区间分页；列表只读 `title / preview / run_state`；条目 `summary` 列供折叠视图；`turn` 索引支持按回合跳转；大结果已是工件。
- 传输：首屏只取尾部（最近 50 条或 3 个回合）；断线按 `sync_seq` 用 `Follow(after)` 补增量；文本增量走易失通道，以 `ItemAppended` 为准；折叠卡片展开再取 body。
- 渲染：虚拟列表、双向懒加载；按 `(session_id, idx)` 缓存，条目不可变、仅撤销时按截断点清理；压缩点之前默认折叠；推理块、长工具输出、子智能体过程默认折叠。
- 观测视图（G1–G5）：上下文组成、每轮请求详情、速度 / 耗时、缓存命中率、子会话跳转都是 `session_requests` + `trace_spans` + 父子关系的投影。

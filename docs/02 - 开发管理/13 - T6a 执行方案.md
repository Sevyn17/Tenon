# 13 T6a 执行方案

> 状态：生效（2026-11-11）。T6a「远端地址与 Agent Card」是 T6 最大、最容易出安全问题的一步（[03 T4-T6 方案](<./03 - T4-T6 方案.md>) 第六节风险表）。本篇把它写成可执行步骤。设计边界见 [08 8.x](<../01 - 设计文档/框架设计/08 - 管控与安全.md>)、[11 术语与内核对象](<../01 - 设计文档/框架设计/11 - 术语与内核对象.md>) 的信封表、[09 9.9](<../01 - 设计文档/框架设计/09 - 演进与验收.md>)。

## 一、现状核对

- `mail.Address` 只有 `session / agent / human / component` 四种；`ParseAddress` 与 `deliver` 的 `switch env.To.Kind` 都只认这四种。没有 `remote:`。
- 出站传输：`transport` 目录目前是**入站服务端**（bind/server/tokenfile），没有出站 HTTP 客户端。
- `host.Deliver` 在 `deliver` 里按 To.Kind 分派；`caps` 由发送会话的 `effectiveCaps` 写入；联系名单/守卫在 `deliverSession`。
- 事件跨机器续读：T4b 留了口（本机存储续读），跨机器未做。

## 二、交付物

1. **`remote:` 地址**：`remote:<host>/agent:<名字>`（host 是基址或已登记的对端名）。`mail.Address` 增加 `Host` 语义（或复用 `ID` 承载 `host/agent:name`），`ParseAddress` 解析，`deliver` 增加 `AddrRemote` 分支 → 走**出站传输**把信封 POST 到对端 `/agent:<名>`。
2. **Agent Card 导出**：本地定义（平台/租户层）的公开部分——名字、描述、公开工具清单（`tools` 里非敏感的？或声明的公开工具）——导出为 JSON（`GET /agent-card/:名`）。**不导出**提示词、`[use.*]`、`caps`。
3. **入站复用现有鉴权**：对端收到远端信封，走现有令牌 + Host/Origin 检查（`transport` 的入站服务端），再进 `Host.DeliverAgent`。`caps` 由发送方写入，接收方再与自己权限求交（08 8.3 现有 caps 机制天然满足）。
4. **跨机器事件续读**：T4b 的续读请求带序号，响应走同一传输（同一出站客户端）。

## 三、文件与类型（预估）

- `runtime/mail`：`ParseAddress` / `String` 支持 `remote:<host>/agent:<名>`；`Envelope` 已有 `To`/`Caps`。
- `runtime/host/envelope.go`：`deliver` 的 `switch` 加 `case mail.AddrRemote`：写 `RemoteSender`（宿主注入的接口 `Send(ctx, host, env) error`），不落本地。
- `runtime/host/host.go`：`Host.Remote` 字段（`RemoteSender` 接口，可空 = 不支持远端）。
- `transport`：新增出站客户端 `Client.Send(ctx, baseURL, env)`（POST JSON，带令牌）；新增入站 handler 收远端信封 → `Host.DeliverAgent`。
- `Agent Card`：`runtime/agentdef` 或 `host` 提供 `AgentCard(name) (json, error)`，从定义取公开字段。
- 预算记账：跨机器时 `budget_ref` 记在发送方（D5）；接收方不重复记。

## 四、验收（09 9.9）

跨机器调用：
1. 接收方定义不在发送方联系名单内 → 被拒（08 8.2）。
2. 接收方权限窄于 `caps` → 按接收方权限执行（caps ∩ 接收方有效权限）。
3. 预算按 `budget_ref` 记在发送方（真实预算账本落地后）。
4. Agent Card 只含公开字段，不含提示词/权限/使用配置。

测试用两个真实 `Host` + 一个内存/loopback 传输做跨机器模拟（不起真实网络或起本地 httptest）。

## 五、不显然的取舍（决策日志记）

1. **`remote:` 只出站、入站复用现有 transport**：不新造鉴权，令牌 + Origin 检查沿用（08 8.2）。
2. **caps 仍由发送方内核写**：接收方求交，防止发送方越权（D2）。联系名单按**发言者**判，不按转发组件。
3. **Agent Card 白名单导出**：只导名字/描述/公开工具；其余一律不导，避免泄漏提示词与权限。
4. **预算跨机器记发送方**：与 08 8.4「按触发记账」一致。

## 六、依赖与风险

- 依赖入站 transport 的现有令牌机制与本方案新增的出站客户端。
- 风险最大：跨进程鉴权、caps 求交、联系名单。必须有跨机器反例测试（不在名单被拒、权限窄按接收方）。
- 预算记账部分依赖预算账本（v1 后基础设施，与 T4f/T5c 同缺口）。

## 七、不做

- 真正的公网 TLS/证书管理（用现有 transport 部署方式）。
- 跨租户投递（任何地址都不行，8.8）。
- A2A 的完整发现协议（Agent Card 之外的名片交换）——本步只导 Agent Card。

## 八、落地状态（2026-11-11）

已落地（可独立验证的部分）：
- **`remote:` 地址**：`mail.AddrRemote`，解析 `remote:<host>/agent:<名字>`（`ParseAddress`/`String` 往返），非法形式报错。`TestParseRemoteAddress`。
- **出站分派**：`Host.Remote`（`RemoteSender` 接口）+ `deliver` 的 `AddrRemote` 分支 → `deliverRemote` 交给出站传输；没配返回 `ErrUnsupportedAddr`。`TestDeliverRemoteViaSender` / `TestDeliverRemoteNoSender`。
- **Agent Card**：`agentdef.CardOf` 只导 `id`/`description`/`tools`，不导提示词、`[use.*]`、caps、文件；`Host.AgentCard(name)` 取名片。`TestAgentCardNoLeak`。

**2026-11-11 补充（HTTP 传输已通）**：`transport/web` 加 `RemoteClient`（实现 `host.RemoteSender`：POST 信封到 `<host>/remote/<to>`，Bearer 令牌、30s 超时、非 2xx 带对端响应体返回错误）与 `RemoteHandler`（入站：读信封、拒 `from=human`、交 `deliver`）。对端鉴权复用现有 `web.Server` 令牌机制。用例 `TestRemoteRoundTrip` / `TestRemoteRejectsHumanFrom` / `TestRemotePropagatesError` / `TestRemoteMissingHost` / `TestRemoteCapsPreserved`。把 `RemoteClient` 赋给 `Host.Remote` 即启用远端投递。

**安全修正（2026-11-11 复核后）**：初版入站走的是 `host.Deliver`，那是**本机入口**语义——第一行就把 `env.Caps` 清成 `nil`（= 不限）并把 `hop` 归零。远端因此能借「不带 caps / 带宽松 caps」拿到不限权限，是提权漏洞。另外 `guardContact` 对 `from=component` 无条件放行，远端把 `From.Kind` 设成 `component` 就能冒充本地组件往任意会话投递。

修法：新增 **`Host.DeliverRemote`**（远端入口），与 `Deliver` 的区别是 **caps 与 hop 沿链保留**（跨机器是触发链上的一环），只做安全归一：
1. 拒 `from=human`（远端不能冒充本地已鉴权用户，08 8.5）；
2. `origin` 强制 `external`（跨机器内容一律不可信，不能被对端声明成可信）；
3. `from=component` **降级**：对端声称的组件身份记进 `Via`，`From` 归一成 `component:remote`——`guardContact` 不再把它当本机组件放行；
4. `caps` 保留，由会话打开时与接收方有效权限求交（08 8.3）。

`RemoteHandler` 的 `deliver` 参数必须是 `Host.DeliverRemote`（文档已注明）。用例：`TestRemoteCapsPreserved`（handler 不丢 caps）、`TestDeliverRemoteRejectsHuman`、`TestDeliverRemoteDowngradesComponent`、`TestDeliverRemoteUnknownSession`、`TestDeliverRemoteNarrowsTurnCaps`。

**未落地**：跨机器事件续读（T4b 留的口）、跨机器预算记账（账本已就绪，需把 `budget_ref` 与对端对齐）。这些是 T6a 的传输实现层，属应用/transport 部署，方案第三节已列出接线点；`Host.Remote` 与 `deliverRemote` 就是其落点，注入实现即可启用。跨机器鉴权沿用现有令牌 + Origin 检查，caps 由发送方内核写入、接收方求交（现有机制）。

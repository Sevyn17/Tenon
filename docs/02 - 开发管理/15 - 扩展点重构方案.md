# 15 扩展点重构方案：拆掉会话层，四类扩展各归其位

> 状态：待执行（2026-11-11 定案）。设计依据见 [框架设计/04 4.3.1](<../01 - 设计文档/框架设计/04 - 扩展模型.md>)。本篇把「拆 `SessionLayer`」写成能照着改的步骤。

## 一、问题与结论

`SessionLayer`（`toolhub.Layer`）同时承担三件事，才长出 `Authorizes` / `Guard` / `Timeout` / `FailOpen`
四个补丁字段：

- **贡献**：往会话里放一层（`LayerEntry.Func` 每会话构造时调）
- **拦截**：包住工具调用（`Layer.Call` 的 `next`）
- **决策**：判定准不准（`Authorizes` 标记「我是那个授权者」）

拆开后的目标形态（04 4.3.1）：

| 类别 | API |
|---|---|
| 贡献 | `Tool` / `SystemBlock` / `Status` / `PermissionItem` / `ResourceType` / `Matcher` |
| 拦截 | `Wrap[Req,Resp](r, point, mw)`（六点位，已落地） |
| 决策 | `WrapGuard[Req](r, point, name, fn)`（纯谓词，并行 reduce）+ `r.Authorizer(a)`（只 ToolCall，可挂起问人） |
| 通知 | `OnSessionReady` / `OnAfterTurn` / `OnSessionDelete`（保持独立） |

**8 个 `SessionLayer` 注册者里有 6 个只做 `ToolCall` 一件事**——这印证了「会话层」是过度泛化。

## 二、原语（第 0 步，只新增不改行为）

```go
// 判定区：纯谓词。Verdict 复用 component 的 Abstain/Allow/Deny（08 D4）。
type GuardFn[Req any] func(ctx context.Context, c *Ctx, req Req) (Verdict, string)

// WrapGuard 登记一条判定。判定区并行跑，任一 Deny 即拒（reduce），不接受 next、不能改写。
func WrapGuard[Req any](r *Registrar, p MwPoint[Req, any], name string, fn GuardFn[Req])

// Authorizer 决策服务：可阻塞（问人）、可挂起。恰好一个组件提供，没有则用内核缺省（失败即收紧）。
type Authorizer interface {
	Decide(ctx context.Context, c *Ctx, call ToolCallReq) (Verdict, string, error)
}
func (r *Registrar) Authorizer(a Authorizer)
```

要点：

- `WrapGuard` 的 `Resp` 用 `any` 占位——判定不改结果，不需要 Resp 类型。**与 `Wrap` 不对称是有意的。**
- 判定区在改写区**之内**（更靠内核）：改写完的请求才交给判定。
- 判定区**并行**跑：纯谓词无依赖，`errgroup` 或 `WaitGroup` + 收集首个 Deny。
- `Authorizer` 只在 `ToolCall` 点位调用；其余点位只用判定区谓词。

## 三、五步迁移（每步一提交，可独立验证）

### 第 1 步：迁 `extproc`（最干净，验证机制）

`modules/extend/extproc/plugin.go:81` 现在登记 `SessionLayer{Order:90, Func: ...}`，里面已经是标准
中间件形态（`Call: p.middlewareCall("tool_call")`）。改成：

```go
if p.hasMiddleware("tool_call") {
    component.Wrap(cx, component.ToolCall, p.toolCallMw())
}
```

`p.conn == nil` 的检查放进中间件内部（进程没起来就放行）。

**验收**：`TestDeliverMiddlewareBridge`、`TestMiddlewareDeny` 保持绿；`extproc` 的 e2e 不变。

### 第 2 步：迁 `redact`（改写 + 决策分离，验证拆分模式）

`modules/context/redact/plugin.go:28-31` 两个登记：

| 现在 | 改成 |
|---|---|
| `SessionLayer{Order:0}` → `Layer(red)`（脱敏输出） | `Wrap(ToolCall, ...)` 改写区 |
| `SessionLayer{Guard:true, Order:1}` → `WriteGuard()`（写操作守卫） | `WrapGuard(ToolCall, ...)` 判定区 |

`Layer(red)` 内部是「`next` 之后脱敏 `out.Content`」——直接搬进中间件。

**验收**：脱敏输出逐字节不变（回归快照）；写操作仍被拒。

### 第 3 步：迁 `instructions` + `hooks`（验证 `Timeout`/`FailOpen` 替代）

**`instructions`**（`modules/context/instructions/plugin.go:48`）：`Timeout: 2s, FailOpen: true`。

`FailOpen` 不引入新字段，中间件自己实现：

```go
component.Wrap(cx, component.ToolCall, func(ctx context.Context, req component.ToolCallReq,
    next func(context.Context, component.ToolCallReq) (component.ToolCallResp, error)) (component.ToolCallResp, error) {
    resp, err := next(ctx, req)           // 先跑内核
    if err != nil { return resp, err }
    // 追加项目指令：带 2s 超时，超时或出错就放行（FailOpen）
    tctx, cancel := context.WithTimeout(ctx, 2*time.Second)
    defer cancel()
    t := discoverWithTimeout(tctx, req.Args)   // 内部 select tctx.Done()
    if t == "" { return resp, nil }            // 超时/无指令：放行
    resp.Output.Content = append(resp.Output.Content, ...)
    return resp, nil
})
```

**`hooks`**（`modules/extend/hooks/plugin.go:95-98`）：pre 钩子可拒绝 → `WrapGuard`；post 钩子是副作用 → `Wrap`。
注意 `hooks` 的 pre 钩子**有外部副作用**（执行用户脚本），放判定区要确认它仍是「纯谓词语义」——
如果不是，它该留在改写区并在内部处理拒绝。

**验收**：故意让指令读取慢（测试注入 3s 延迟），确认 2s 超时后放行（`FailOpen` 语义）；
hooks 的 pre 拒绝行为不变。

### 第 4 步：迁 `permission` + `sandbox`（动安全边界，最后做）

**`permission`**（`modules/security/permission/plugin.go:71`）：

- `Authorizes: true` 的授权判定 → `r.Authorizer(...)` 服务（`Decide` 里做档位判定 + 挂起问人）
- `Func` 里的装配期检查（`s.SetItems` / `s.SetLookup` / `CheckItems`）**不属于扩展点**，移到组件 `Start` 或会话构造钩子
- `§9.5`「必然 deny 的工具不进模型工具列表」→ 属**贡献**（`Tool.Visible` 或工具集过滤），不是中间件

**`sandbox`**（`modules/security/sandbox/plugin.go:56`）：

- 逃逸判定 → `WrapGuard(ToolCall, ...)` 判定区
- 限参数 → `Wrap(ToolCall, ...)` 改写区
- 一个组件拆两处登记

**验收**：权限档位全部测试、挂起确认、恢复后重判、沙箱逃逸拦截、回归快照。**这一步必须全绿才能继续。**

### 第 5 步：删 `SessionLayer`

8 个都迁完后删：

- `runtime/assemble`：`SessionLayer` / `LayerEntry` / `LayerFunc`
- `runtime/toolhub`：`Layer` 的 `Guard` / `Authorizes` / `Timeout` / `FailOpen` 字段
- `component.RegisterAt(cx, assemble.SessionLayer, ...)` 全部改到新 API

`Hub` 最后只剩：注册的工具 + 两条编译好的链（改写链、判定链）。

**验收**：`gofmt` / `vet` / 全量测试 / 回归快照 / `-race` 全绿；`explain` 能分别列出「贡献 / 改写 / 准入」。

## 四、不做的

- **不给 `FailOpen` 加通用开关**：通用开关会让「失败该不该阻断」变成配置问题，而不是组件作者的显式决定。
- **`Authorizer` 不推广到六个点位**：只有工具调用需要挂起问人；其余点位用判定区谓词。
- **不改六个点位本身**：4.3 的六个点位（Deliver/ToolCall/SessionOpen/Turn/Context/ModelCall）已落地，本方案只动「会话层」。

## 五、风险与回退

| 风险 | 处置 |
|---|---|
| 权限/沙箱是安全边界 | 第 4 步单独提交，前置全部权限测试；有任一红就回退该提交 |
| `FailOpen` 语义丢失（超时变成阻断） | 第 3 步专门造「慢指令」测试验证放行 |
| 层顺序变化改变行为 | 每步跑回归快照（`apphost`）；顺序差异逐条记决策日志 |
| 装配期检查被搬到运行期 | `permission` 的 `CheckItems` 明确放 `Start`，保留「启动即失败」语义 |

回退：每步独立提交，`git revert` 单个提交即可回到上一步。

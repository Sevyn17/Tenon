# 09 T4e 执行方案

> 状态：生效（2026-11-11）。本篇把 [03 - T4-T6 方案](<./03 - T4-T6 方案.md>) 的 T4e「小组模块」写成能照着改的步骤。设计边界以 [框架设计/13 13.4](<../01 - 设计文档/框架设计/13 - 会话与消息机制.md>) 的「群聊（小组）」「转人工」与 [09 9.7](<../01 - 设计文档/框架设计/09 - 演进与验收.md>) 为准；集合、资源与订阅、投递、注入等机制用已经落地的 T4a / T4c / T3 / T2b，不重造。

## 一、开工前核对（2026-11-11 对过代码）

| 方案写法 | 代码现状 | 本步怎么接 |
|---|---|---|
| 小组是「群聊原始记录的存储，加上投递规则」 | 记录要一列、按序号读；刚落了 `store.Collection`（T4a）：`Get/Put/Query/Delete`，按声明索引等值查，分区字段由组件给 | 群记录与已读位置都放小组自己的 `Collection`，不新建专用 SQL 表 |
| 「每个机器人在每个群各有一个会话，不跨群共用」 | `Host.deliverAgentID` 带 `key` 时按 `FindSessionByKey(定义, 创建者, key)` 查或建（13 13.3 B19）；`key` 只对 `agent:` 有效 | 机器人会话键 `key = 群 id`；创建者固定为小组组件（`from` 是组件），保证同一群同一机器人落到同一会话 |
| 「@ 才唤醒」 | T4c 落地的扇出：组件写完资源记录调 `Mailer.Fanout(rec, subs)`，按订阅跑匹配器，命中走 `Host.Deliver`（`kind=notify`、`origin=external`） | 小组登记资源类型 `group`；每条记录扇出一次，`list` 匹配器按 `at` 字段（被 @ 的名字）命中该机器人订阅 |
| 「背景按已读位置补齐，不逐条投」 | 每回合调模型前的注入点 `inject.Func func(*callctx.Ctx) []Item`（12.5，`Registrar.Status`）；`callctx.Ctx` 有 `SessionID()` 与 `Meta()` | 小组登记一个 `Status`：调模型前按本会话的（群、机器人）查已读位置，把其后的群记录拼成一段背景注入，再推进已读位置 |
| 「智能体提问只有本轮触发者能回答」 | `corr` 与触发者绑定：`store` 的 `CorrStore`、`Host.DeliverAgent` 已有；提问回信按 `corr` 核触发者 | 小组不新造机制：把本轮触发者（人被 @ 的名字或人地址）记进会话 meta，提问走现有 corr |
| 「转人工开关，缺省关闭」 | 组件配置走 `[use.<组件>]` / `WithConfig`，`ComponentInfo.Config` 结构体 + `cfg` / `default` tag | 小组组件声明 `Config`，`manual` 布尔缺省 false |
| 「两个定义文件 + 一个资源配置拼出带 @ 的小组，不写 Go 代码」 | 定义 = `agentdef.Dir` 的文件；资源配置 = 小组组件的一段 `[use.group]` 配置（群、成员机器人、转人工） | 小组读 `callctx.Ctx.Use("group")` 拿配置；验收只用定义文件 + `[use.group]`，不写 Go |

**现成的、不重做**：群记录序号单调由小组自己排（内核不分配，04 4.7 资源记录序号亦由组件排）；`hop` 上限走内核（`MaxHop`），小组不自己计数；联系名单 / 守卫走 `Host.Deliver`，小组不绕过。

## 二、交付物

1. 新组件 `modules/collab/group`：群记录集合 `group.messages`（按 `seq` 单调；索引 `seq` 用于分页取「已读位置之后」）、已读位置集合 `group.reads`（键 `<群>:<机器人>`）、群配置从 `[use.group]` 读。
2. 资源类型 `group` 与内置 `list` 匹配器配合：一条群记录扇出，按 `at` 命中被 @ 的机器人订阅；命中 `wake`，未命中不投。
3. 每机器人在每群一个会话（`key = 群 id`，创建者为小组组件）；被 @ 时投 `wake` 信封。
4. 背景补齐：调模型前用 `Status` 注入「本机器人已读位置之后的群记录」，与本次 `@` 消息一起；注入后推进已读位置。
5. 机器人回复写回群记录（发送者 = 机器人会话），再按需要扇出（只有 @ 了别人才唤醒对方，`hop` 兜底）。
6. 转人工开关（`[use.group] manual = true`）：客户 / 人工客服 / 机器人三方发言先入组记录，再由小组决定投给谁；人工客服是人地址，没有自己的会话。
7. 重启恢复：启动时按每个（群、机器人）的已读位置补投遗漏的唤醒（复用 `Ready` 点位，像 workgroup 的 `Recover`）。

## 三、文件与类型

### 3.1 新组件骨架

`modules/collab/group/plugin.go`（照 `workgroup/plugin.go` 的模式）：

- `init()` 注册组件名 `group`；`Meta` 的 `Requires` 含 `assemble.ServiceHost` / `assemble.ServiceDB` / `component.ServiceSQL`？——**不需要 SQL**：群记录与已读位置都用 `Collection`，无自有表。`Meta.Effects` 含 `component.EffectTools`（若暴露工具，见 3.5）。
- `Setup`：
  - `component.Use[*host.Host](cx, assemble.ServiceHost)` 取宿主。
  - `cx.Collection("messages", store.CollectionSpec{Version:1, Indexes:[]string{"seq"}, Partition:"tenant"})`。
  - `cx.Collection("reads", store.CollectionSpec{Version:1, Indexes:[]string{"group"}, Partition:"tenant"})`。
  - `cx.ResourceType(component.ResourceType{Name:"group", Render: renderRecord})`。
  - `cx.Status("group_bg", ...)` 注册背景注入（3.4）。
  - `cx.On(...)` 或暴露工具接收「群消息进来」（3.3）。
  - `cx.Template(...)`（若需要内置定义，见第三节末，T4e 不需要内置定义——用两个定义文件）。
- `Start(sc)`：`New(...)` 建 Group，`sc.OnClose` 收尾；`Ready` 点位补投。

### 3.2 群记录与已读位置（集合）

群记录 `Doc{Key: <seq 的十进制字符串，左补零保证字典序=数值序>, Version, Body: {"seq":int64,"group":string,"from":string,"from_kind":string,"body":string,"at":[]string,"ts":int64}}`。

- 序号：小组用一个「群内的最大序号 + 1」——从 `messages` 按 `seq` 索引取该群最后一条的 `seq`。为免每次全扫，已读位置集合里存 `next_seq`？——**不存**：用 `Query(group, "seq")` 拿最大并不现实（等值查询）。改用**每条群记录 key 左补零到 20 位**，`Query` 不支持范围，故取「最大 seq」需要另法。**决定**：每个群在 `reads` 里放一条 `__meta__` 文档记 `next_seq`（条件写 `ifVersion` 做 CAS），新记录 `Put` 后 `next_seq+1`。这与 workgroup 用集合做自增序号的既有做法一致（见 `workgroup.go` 的 `seq` 递增）。
- 已读位置：`reads` 文档 key = `<群>:<机器人>`，`Body{"group":..,"bot":..,"pos":int64}`。
- 分区：`Partition:"tenant"`，框架填租户。

### 3.3 @ 与扇出

- 一条群记录 `Put` 后，`Render` 出正文；`Fields` 含 `"at"`（被 @ 的名字，逗号拼）、`"from"`、`"body"`。
- 订阅从配置生成：`[use.group]` 里每个群声明成员机器人列表；每个机器人一条 `Subscription{Resource:"group:<群>", Subscriber:"session:<该机器人在该群的会话 id>", Matcher:"list", Params:{"field":"at","value":"<机器人定义名>"}, Exclude:"component:group"}`。
  - 但 `session:` 地址要会话 id，而会话可能在写入时还没建。**改走 `agent:` 带 key**？——T4c 的 `Fanout` 只接受 `session:` 收信地址（`fanoutOne` 校验 `to.Kind == mail.AddrSession`）。所以小组要么先确保会话已建（`deliverAgentID` 建一个），要么**不经 Fanout 而直接 `Host.DeliverAgent`**。**决定**：小组用自己的扇出（不走 `Mailer.Fanout`），因为它需要的正是「按 @ 决定投哪个 `agent:<名字>`（带 key）」，而 `Fanout` 的 `session:` 模型不适合「会话可能尚未存在」。小组直接对每个被 @ 的机器人 `Host.DeliverAgent(env{To:agent:<名字>, Key:群id, Mode:wake, Kind:notify, Origin:external, From:人地址, Via:group})`。记录已读位置由注入推进（3.4），不依赖 Fanout。
  - 这样 T4c 的资源类型 / 匹配器仍在：小组登记资源类型 `group`（供 explain 与将来订阅者用），但**扇出投递由小组自己做**，因为目标是「按 @ 投 agent 带 key」，不是「投已存在的 session」。这点写进决策日志。
  - `hop` 由内核 `Host.DeliverAgent` 管；小组把发送机器人的 `hop` 带进 `From`/`Hop`？——`DeliverAgent` 会把 `Hop` 重置为 0（入口语义）。机器人回复要延续 hop 得走 `Host.Deliver`（经发件箱）而非 `DeliverAgent`。**决定**：机器人回复走「机器人会话发件箱」——即机器人在回合里通过 `Mailer` / `Host.Deliver` 发 `agent:<名字>` 带 key，天然延续 hop；小组只负责「人 → 机器人」用 `DeliverAgent`（入口，hop=0 合理）与「写记录」。这符合 13.4「机器人的发言只有 @ 了别的机器人才唤醒对方，hop 上限兜底」。

### 3.4 背景注入（`Status`）

`inject.Func func(*callctx.Ctx) []Item`：

1. 从 `ctx.Meta()` 取本会话的 `group` 与 `bot`（会话建立时写进 meta）。
2. 查 `reads` 里 `<群>:<bot>` 的 `pos`。
3. `Query(messages, "seq", ...)` 拿不到范围，改按「已读位置之后」：因 key 左补零且 `Query` 只等值——**用分页扫**：`Query` 无法范围，故改用「按 key 升序 `Get` 逐条」不现实。
   - **改方案**：群记录 key 用 `seq` 左补零字符串，小组取背景用 `messages` 的**分页**：`Query(part, "seq", <某种>)` 不行。集合没有「列出全部/范围」。
   - **决定**：给 `messages` 加一个恒为固定值的索引字段 `idx`（值恒 `"all"`），`Query(part, "idx", "all", Page{After: "<pos 的零补 key>", Limit: N})` —— `After` 是上一页最后一条的 Key，集合按 Key 升序；`After = pos 的零补 key` 即「pos 之后」。这正是集合 `Page.After` 的语义（collection.go 45–49、63）。于是背景补齐 = 从 `After` = pos 开始翻页，拼到没有下一页，注入，推进 `pos` 到末条。
4. 注入一个 `Item{Key:"group_bg", Kind:KindStatus, Body: 拼接的背景文本, Priority: ...}`；正文标 `TrustExternal`（群消息来自外部人，转述给模型按 external）。
5. 注入后把 `pos` 写到末条 seq（条件写）。

> 只有「本会话是某个群里的机器人会话」才注入（`ctx.Meta()` 有 `group`/`bot`）。顶层直接会话、工作组会话不注入。

### 3.5 工具（可选，按最小实现）

T4e 的验收不需要 Go 代码，也不需要机器人调工具——机器人只是收到 `wake` 后正常回复。回复写回群记录由哪一步做？——**AfterTurn 点位**：`assemble.SessionCx` 在构造时给 `AfterTurnFunc func(id string, end session.EndReason)`；小组登记 `AfterTurn`，本会话（群机器人会话）回合结束后，把这一轮助手的最终回复写进群记录（发送者=机器人），并按回复里的 `@` 扇出给被 @ 的其它机器人（走它们的会话发件箱 / `Host.Deliver` 带 key）。

- 如何拿这一轮的最终回复文本？`AfterTurn` 只给 `id` 和 `end`。需要读会话历史最后一条助手消息。用 `store.Store` 读该会话最后条目（workgroup 的 settle 有类似「读成员最后结果」的做法，可参照 `workgroup.go` 的 settle）。
- **决定**：小组在 `AfterTurn` 里读该会话历史最后一条 assistant 文本，作为机器人发言写入群记录；若文本含 `@<名字>`，对每个命中的机器人 `Host.Deliver`（`agent:<名字>` 带 `key=群id`、`mode=wake`、`from=session:<本会话>`（保持 hop 链）、`via=group`）。

### 3.6 转人工（配置开关）

`[use.group] manual = true` 时：客户 / 人工客服（`human:<id>`）/ 机器人三方发言都先写群记录；小组按配置把「客户消息」投给机器人（被 @）或人工客服（人地址），把「机器人回复」投人工客服；人工客服回复（`human:` 入）写记录再投机器人。人工客服没有会话，靠 `human:` 地址投递（`Host.deliverHuman`）。缺省 false = 纯群聊。

## 四、验收（09 9.7）

写两个定义文件 + 一段 `[use.group]`，不写 Go 代码：

1. `agentdef.Dir` 目录里放两个定义 `alice-bot`、`bob-bot`（或任意两个名字）。
2. `[use.group]` 配一个群 `g1`，成员 `alice-bot`、`bob-bot`。
3. 测试驱动（Go 测试可，验收本身不写业务 Go）：
   - 人 `@alice-bot 查订单` 进群 → 只有 `alice-bot` 收到 `wake` 信封，`bob-bot` 的会话没有新信封。
   - `alice-bot` 回复后写入群记录；人再 `@bob-bot` → `bob-bot` 收到 `wake`，其背景注入里含 `alice-bot` 的回复。
4. 断言：`bob-bot` 在第一步 `ListSessions` / 收件箱无该群新信封；第二步注入的背景文本包含 `alice-bot` 上一步回复的正文。

测试放 `modules/collab/group/group_test.go`；用真实 `Host` + 两个 `agent:` 定义 + 内存存储，尽量走 `Host.DeliverAgent` 真实路径。

## 五、文档

- 13 13.4「群聊（小组）」补一句：群记录与已读位置存小组自己的集合；@ 扇出投 `agent:<名字>` 带 `key=群id`；背景用每回合注入点补齐。转人工一节补开关位置 `[use.group] manual`。
- 05 数据与存储的集合一节加两行：`group.messages`、`group.reads` 的形状与索引。
- 计划 01 回填 T4e 进度；决策日志记不显然的取舍（见下）。

## 六、不显然的取舍（决策日志记）

1. **扇出不走 `Mailer.Fanout`**：`Fanout` 只投已存在的 `session:`；小组要「按 @ 投可能尚未建会话的 `agent:<名字>` 带 key」，故直接 `Host.DeliverAgent`。资源类型 `group` 仍登记（explain 与将来订阅者用）。
2. **背景用 `Status` 注入而非系统块**：系统块在会话构造时算一次；已读位置每轮变，必须每轮注入。
3. **群记录序号由小组自排**（`__meta__.next_seq` 条件写 CAS），内核不分配。
4. **hop 连续性**：人 → 机器人走 `DeliverAgent`（入口 hop=0）；机器人 → 机器人走会话发件箱 `Host.Deliver`（延续 hop）。这就是 13 篇「hop 上限兜底」的来源。
5. **每机器人每群一个会话**：`key=群id`、创建者固定为 `component:group`，保证 `FindSessionByKey` 命中同一会话。

## 七、不做

- 群会话里多用户权限求交与按人分轮：归 T4f（13 13.5 待定项的定案在 T4f）。
- 跨机器群：归 T6a。
- 群记录的高级查询（全文检索、聚合）：集合只做等值 + 分页，不做。
- 内置群定义模板：T4e 用两个定义文件，不内置「群成员」定义。

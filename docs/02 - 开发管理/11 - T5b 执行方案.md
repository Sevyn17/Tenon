# 11 T5b 执行方案

> 状态：生效（2026-11-11）。把 [03 - T4-T6 方案](<./03 - T4-T6 方案.md>) 的 T5b「定时与外部事件入口」写成步骤。设计边界见 [13 13.4「事件」](<../01 - 设计文档/框架设计/13 - 会话与消息机制.md>) 与 [09 9.8](<../01 - 设计文档/框架设计/09 - 演进与验收.md>)。

## 一、现状核对

- 投递入口已有：`Host.Deliver`（信封）与 `Host.DeliverAgent`（agent:，含 T5a 常驻）；`Mailer.Send`（组件发信，origin=agent）。
- `Host.Deliver` 对 `From.Kind==component && Origin==external` 保留 origin=external（不降为 agent），正是外部事件要的。
- 常驻（T5a）已支持，事件可投常驻会话接着上下文写。
- 没有现成的定时器 / webhook / 统一外部入口组件。

## 二、交付物

新组件 `modules/extend/events`（注册名 `events`）：

1. **统一入口** `Hub.Post(ctx, target, body)`：把外部事件转成信封——`origin=external`、`mode=wake`、`from=component:events`、`via=events`，目标二选一：`agent:<名字>`（不带 key，每次新建）或 `resident:<名字>`（T5a 固定会话）。经 `Host.Deliver` 投递。
2. **Router 分发**：组件注册一个会话工具 `event_dispatch`（`assemble.SessionTools`，`Visible` 按定义挑，或全开），让 Router 定义的智能体在一个回合里把事件转发给 Worker：`dispatch(to, body)` → `Hub.Post`。这样"外部事件进来 → Router 分发到 Worker"只用两个定义文件 + 配置拼出，不写业务 Go。
3. **定时**：组件配置 `[plugin.events]` 里声明定时任务（`schedule = [{ every = "24h", target = "resident:日报", body = "汇总今天的订单" }]`）。`Start` 里用进程内 `time.Ticker`/`Timer` 按周期 `Post`；`OnClose` 停表。不引外部调度器。
4. **webhook**：走 `transport` 的既有令牌鉴权；入口把 HTTP 请求体变成 `Post(agent:<名>, body)`。传输层本就带应用鉴权，本步只提供 `Hub.Post` 作为 webhook handler 的落点（真正的 HTTP 挂载由应用/transport，同现有 `appapi.UploadHandler` 的做法）。

## 三、文件与类型

- `modules/extend/events/plugin.go`：注册 `events`；`Meta.Config=&Config{}`；`Setup` 取 `*host.Host`，登记工具 `event_dispatch`；`Start` 起定时器；`OnClose` 停。
- `modules/extend/events/events.go`：`Hub{host}`；`Post(ctx, target, body) error`；`Config{ Schedule []Task }`；`Task{ Every, Target, Body }`。
- `items.go`：权限项 `event.dispatch`（EffectCollab）。

`Post` 关键：
```go
addr, err := mail.ParseAddress(target)   // agent:x / resident:x / session:x
// resident:x 归一成 agent:x（T5a 按常驻定义处理）；否则 agent:x 不带 key 每次新建。
env := mail.Envelope{ From: component:events, Via: "events", To: addr, Kind: request, Mode: wake, Origin: external, Body: body }
host.Deliver(ctx, env)
```

## 四、验收（09 9.8）

用两个定义文件（`router`、`worker`）+ 一段 `[plugin.events]`，不写业务 Go：
1. 外部事件经 `Hub.Post(ctx, "agent:router", "...")` 投入 → router 会话被唤醒开回合。
2. router 回合里调 `event_dispatch(to="agent:worker", body=...)` → worker 会话被唤醒。
3. 断言：worker 的会话历史含分发的正文；两个会话的 origin 是 external（不可信）。
4. 定时：把 `every` 设成很短，等一拍后目标会话收到信封（用测试直接调 `Hub.Post` 也可覆盖核心，定时器仅验证起停）。

测试放 `modules/extend/events/events_test.go`，用真实 `Host` + 内存存储。

## 五、不显然的取舍（决策日志记）

1. **分发用组件注册的工具**而非内置"发信工具"：框架没有通用 agent→agent 发信工具；Router 分发靠 events 组件登记的 `event_dispatch`。这与 workgroup 的 `team_send` 同型。
2. **origin 由入口决定**：`Hub.Post` 一律 `origin=external`（外部事件不可信），组件不能自己声明 human（08 8.7）。
3. **target 用地址字符串**：`agent:`/`resident:`/`session:`；`resident:` 归一成 `agent:` 交给 T5a 的常驻查找。
4. **定时用进程内 Ticker**：不引外部调度器（03 方案明说）。

## 六、不做

- 真正的 HTTP webhook 端点（属 transport/应用层，本步只提供 `Hub.Post` 作为落点）。
- 跨机器定时（归 T6a）。
- 定时任务的持久化与错过的补跑（本步进程内；重启补跑留后续）。

## 七、落地状态与不显然的边界（2026-11-11）

已落地 `modules/extend/events`（注册名 `events`，加入默认预设）：
- `Hub.Post(ctx, target, body)`：外部事件 → `origin=external`/`mode=wake`/`from=component:events` 的信封，目标 `agent:<名>`（不带 key 每次新建）或 `resident:<名>`（T5a 常驻）。`TestHubPostToAgent`。
- 会话工具 `event_dispatch {to, body}`（权限项 `event.dispatch`，EffectCollab）：Router 定义在回合里把事件分发给 Worker。`TestDispatchToolViaAgent` / `TestRouterForwardsToWorker`（定义 + 配置，不写业务 Go）。
- 定时：`[plugin.events] schedule = [{every, target, body}]`，`Start` 用 `sc.Go` 起进程内 Ticker，作用域结束即停；`TestEventsWiring` 验装配与工具登记。
- **重要边界**：外部事件一律 `origin=external`（不可信）。权限组件对不可信回合把 allow 工具降级为「确认」，无界面时直接拒绝（08 8.3）——所以**由外部事件直接驱动的 Router 回合调用写/协作类工具会被拦，需要确认或改由可信入口触发**。这是正确的安全边界，不是缺陷；真要从外部事件触发特权分发，应由应用在可信侧（鉴权后按 human 投递）或显式放宽权限规则来做。仍保留 `event_dispatch` 供可信回合的 Router 分发。
- 不做项见第六节。

# 12 T5c 执行方案

> 状态：部分落地（2026-11-11）。把 [03 - T4-T6 方案](<./03 - T4-T6 方案.md>) 的 T5c「模型判断类匹配器」写成步骤。设计边界见 [04 4.7](<../01 - 设计文档/框架设计/04 - 扩展模型.md>)。

## 一、现状核对

- 匹配器只能经 `Registrar.Matcher(name, fn)` 登记（resource.go:70）——**内核与扩展进程都无法内置**：内核只 `installBuiltinMatchers` 装了 `exact`/`prefix`/`list`（纯程序规则），扩展进程（T6b）尚不存在。所以「只能由组件登记」这条**已成立**。
- `Matcher` 是 `func(ResourceRecord, params) (Match, error)`（resource.go:48）。T5c 要放宽「不调模型」的约束到模型判断类：需要一个能调模型的匹配器原语。
- 判定失败按「不匹配」处理：`fanoutOne` 里匹配器返回错误则该订阅记 `Errors` 并跳过，其余订阅不受影响（`Mailer.Fanout` 逐条独立）。
- **「每次判断的模型开销记入订阅者预算」+「预算用尽后停止判断并记 guard.denied」依赖预算账本**——与 T4f 同一缺口：仓库无预算账本（08 8.4 的 `budget_ref` 只是字段与主体划分，无累计账）。匹配器是纯函数、拿不到 host/事件发布通道，「记 guard.denied 类事件」也无落点。

## 二、交付物

1. **模型判断匹配器原语** `component.ModelMatcher(judge, opts)`：把「一个判断函数（可调模型）+ 失败按不匹配 + 判断次数上限」包成标准 `Matcher`。判断函数签名 `func(ctx, rec, params) (bool, error)`。
2. **内置示例组件** `modules/extend/modelmatch`（注册名 `modelmatch`）：登记一个模型判断匹配器 `llm`——用 `assemble.Models` 的 `modelhub.SideCall` 让模型判断「这条记录是否符合订阅参数里的 question」，回答 yes/no。
3. 判断失败（模型报错/非 yes/no）→ 返回不匹配，不阻塞扇出。
4. 判断次数上限（`opts.MaxJudgments`）：超过后该匹配器直接返回不匹配（**本地计数**，是先于预算账本的兜底）。

## 三、文件与类型

- `runtime/component/modelmatcher.go`：`type Judge func(ctx context.Context, rec ResourceRecord, params map[string]string) (bool, error)`；`func ModelMatcher(j Judge, max int) Matcher`。`max<=0` = 不限。计数用原子计数器，`max` 用尽后返回 `Match{Matched:false}`。
- `modules/extend/modelmatch/plugin.go`：`Setup` 取 `assemble.Models`（可选，没有就不登记）、`cx.Matcher("llm", ...)`。judge 里构造 `session.Request{Messages:[user: "...这条记录...符合...吗？只回 yes/no"]}`，`SideCall` 拿回答，前缀 yes → 命中。

## 四、验收（09 9.8 / 03 T5c）

- `TestModelMatcherFailureIsNoMatch`：judge 报错 → Matcher 返回未命中、不阻塞（不影响同批其他订阅）。
- `TestModelMatcherCap`：judge 恒真但 `MaxJudgments=2`，第 3 次起返回未命中（模拟「预算用尽停止判断」的本地兜底）。
- `TestModelMatcherViaComponent`：`modelmatch` 组件登记 `llm` 匹配器，`Assembly.Matcher("llm")` 取到。
- 真正的「预算用尽 + `guard.denied` 事件」随预算账本一起（v1 后基础设施）。

## 五、不显然的取舍（决策日志记）

1. **「只能由组件登记」无需新代码**：登记入口只有 `Registrar.Matcher`，内核只装三个纯程序规则匹配器——已满足。
2. **判断次数上限 ≠ 预算账本**：本步先用匹配器自带的本地计数做兜底（用尽即判不匹配），真正的「按订阅者预算扣减 + 用尽发 `guard.denied`」要等预算账本；且匹配器是纯函数、无事件发布通道，需要账本 + 一个从 matcher 上报的接口，属基础设施。

## 六、不做

- 预算账本（与 T4f 同一 v1 后基础设施项）。
- 从 matcher 发 `guard.denied` 事件（需要 matcher → host 的上报通道，随账本一起）。
- 扩展进程登记匹配器（T6b）。

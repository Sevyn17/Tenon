## 二、交付物

1. 两个登记点位：`Registrar.ResourceType`、`Registrar.Matcher`。内核内置精确、前缀、名单三个匹配器，组件可以再登记自己的程序规则匹配器。
2. 订阅存在组件自己的 `Collection` 里。一条订阅是订阅者、资源、匹配器、匹配器参数，外加可选的排除来源。
3. 扇出：组件写完一条资源记录后调用 `Mailer.Fanout`，框架按该资源的订阅跑匹配器，命中的投成信封。投递走现有 `Host.Deliver`，不新开通道。
4. 守卫照常生效。没登记放行规则时，匹配的订阅者也收不到。

## 三、文件与类型

### 3.1 资源类型与匹配器（`runtime/component/resource.go`，新文件）

```go
// ResourceType 一种资源（04 4.7）。记录存在组件自己的 Collection 里，内核不存。
type ResourceType struct {
    Name string // 地址类型，如 "group"；资源地址是 "<Name>:<id>"
    // Render 把一条记录渲染成信封正文。nil 时用记录的 Body。
    Render func(ResourceRecord) string
}

// ResourceRecord 一条资源记录。序号由组件排，内核不分配。
type ResourceRecord struct {
    Resource string // 资源地址，如 "group:g1"
    Seq      int64  // 该资源内的序号，从 1 起
    From     mail.Address
    Body     string
    // Fields 匹配器能看到的字段。缺省含 "from"（地址字符串）与 "body"。
    Fields map[string]string
}

// Match 一次匹配的结论。Matched 为 false 时不投。
type Match struct {
    Matched bool
    Mode    mail.Mode // 空 = notice
}

// Matcher 订阅匹配器。只看这一条记录和本订阅的参数，不读存储、不调模型。
type Matcher func(rec ResourceRecord, params map[string]string) (Match, error)

// ResourceType 登记一种资源类型。同名（跨组件）重复登记拒绝。
func (cx *Registrar) ResourceType(t ResourceType) error

// Matcher 登记一个匹配器。同名重复登记拒绝。
func (cx *Registrar) Matcher(name string, m Matcher) error
```

内置三个，`Assembly.Start` 里登记，组件同名登记拒绝（内置优先）：

| 名字 | 参数 | 命中条件 |
|---|---|---|
| `exact` | `field`、`value` | `Fields[field] == value` |
| `prefix` | `field`、`value` | `Fields[field]` 以 `value` 开头 |
| `list` | `field`、`value` | `Fields[field]` 等于 `value` 里逗号分隔的某一项 |

三个都要求 `field`、`value` 非空，缺参返回错误，该订阅本条不投，记日志，不影响其他订阅。`field` 不在 `Fields` 里视为不命中，不视为错误。

### 3.2 订阅（组件自己的集合）

内核不建订阅表。约定写在这里，小组模块（T4e）照这个形状登记：

```go
Collection("subscriptions", store.CollectionSpec{
    Version: 1, Partition: "resource", Indexes: []string{"all"},
})
```

一条文档：

| 字段 | 含义 |
|---|---|
| `key` | 订阅 id，组件自己分配 |
| `resource` | 资源地址，同时是分区值 |
| `all` | 恒为 `"1"`，给"列出这个资源的全部订阅"用（05 5.6 不允许列出一个分区的全部） |
| `subscriber` | `session:<id>` |
| `matcher` | 已登记的匹配器名 |
| `params` | 匹配器参数，JSON 对象，值必须是字符串 |
| `exclude` | 可选，命中则跳过的来源地址，逗号分隔 |

谁来建由持有资源的组件决定，在运行时建，不在 `Setup` 里登记。`Setup` 只登记有哪些匹配器可用。

### 3.3 扇出（`runtime/component/resource.go`）

```go
// Fanout 把一条资源记录按订阅投给会话（04 4.7）。
//
// subs 是该资源的订阅，由调用方从自己的集合查好传进来：内核不查组件的集合，
// 也不负责发现"有新记录"。写记录和调用本方法之间崩溃，由组件启动时按自己的序号补投。
func (m *Mailer) Fanout(ctx context.Context, rec ResourceRecord, subs []Subscription) (FanoutResult, error)
```

一封扇出信封这样填：

| 字段 | 取值 | 理由 |
|---|---|---|
| `from` | 记录的 `From` | 联系名单看的是发言者，不是转发组件 |
| `via` | 本组件名 | 04 的表："会话外转发"填转发组件 |
| `to` | 订阅的 `subscriber` | 只接受 `session:`，别的地址本步拒绝 |
| `kind` | `notify` | 资源记录不期待回复 |
| `mode` | 匹配器给的，空则 `notice` | 13 的"只有 @ 才 wake"由匹配器表达，内核不用认识 @ |
| `origin` | `external` | 记录正文来自资源，不是本会话的智能体；`OriginExternal` 是唯一不可信来源 |
| `hop`、`trace`、`caps` | 不填 | `Host.Deliver` 会清零再写，组件填了也没用 |

`to` 不是 `session:` 的订阅记一条错误并跳过，不让一条坏订阅挡住其余的。`Host.Deliver` 拒绝的（联系名单、守卫、跳数）同样记日志、跳过，收集进 `FanoutResult.Denied`，不作为 `Fanout` 的返回错误。`Fanout` 返回错误只表示"根本没投成"，例如没有投递服务。

排除来源在跑匹配器之前做：`rec.From` 的字符串出现在订阅的 `exclude` 里就跳过。这是数据，不是匹配逻辑，内核能统一做。用它防"机器人自己的回复又投回自己"，不靠匹配器。

跳数在这条路上是 1，超不过上限 8。资源扇出防循环靠 `exclude`，不靠跳数。跳数仍由 `Deliver` 检查，不绕过。

## 四、顺序

1. **登记与内置匹配器**。`ResourceType`、`Matcher`、三个内置匹配器。用例：重复登记拒绝、三个匹配器的命中与不命中、缺参返回错误。`go vet`、`go test` 全绿后提交。
2. **扇出**。`Mailer.Fanout`。用例用 `fakeSender`（`mailer_test.go` 已有）：两条订阅、一个精确匹配器，只有命中的产生信封，信封字段按 3.3 的表；`exclude` 命中的不投；没有投递服务时返回错误。提交。
3. **守卫验收**。用真实 `Host.Deliver`：建两个会话、一个资源类型、两条订阅、一个精确匹配器。记录进来后只有匹配的订阅者的信箱里有这封信封。不登记放行规则时，匹配的订阅者也收不到，且记 `guard.denied`。登记一条只放行"本组件转发、`via` 为本组件"的 `Allow` 规则后，才收得到；这条规则放不开跳数（跳数仍由 `Deliver` 检查，本步不另造超限用例）。提交。

第 1 步没过不开始第 2 步。每步一个提交，决策日志各记一行。

## 五、验收

- 注册一个资源类型、两条订阅、一个精确匹配器，记录进来后只有匹配的订阅者收到信封（第 3 步）。
- 不登记放行规则时，匹配的订阅者也收不到，拒绝记 `guard.denied`（第 3 步）。
- 信封走 `Host.Deliver`：`origin = external`，`kind = notify`，`hop` 由内核写（第 2、3 步）。
- `go vet ./...` 与 `go test ./...` 全绿。

## 七、不做

- 不新增 `ResourceStore`，不建资源记录表、订阅表。
- 不让内核发现"有新记录"。写记录和扇出之间崩溃的补投由组件做，本步只保证 `Fanout` 一次调用内的投递。
- 不让匹配器读存储、调模型、带状态。模型判断类归 T5c。
- 不做"这个会话订了哪些资源"的反查。
- 不投 `agent:`（那会新建会话），不投 `human:`、`component:`。
- 不做资源记录的保留期清理。

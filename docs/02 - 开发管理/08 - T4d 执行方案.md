## 二、交付物

1. 插件包清单新增可选字段 `agents`，指向包目录内的一个定义目录。目录布局与 `agentdef.Dir` 相同。
2. 包里的定义进入可用定义列表：经 `agentdef` 的同一套解析与校验，错误信息带清单路径与定义文件路径。
3. 项目未受信时，项目级包的定义不加载。用户级包不受受信影响，与现在的包加载一致。
4. `explain` 输出增加"插件包"一段：每个包的名字、来源（用户级 / 项目级）、清单路径、内容摘要、贡献的定义名。

## 三、文件与类型

### 3.1 清单字段

`runtime/pkgs/pkgs.go`：

```go
type Manifest struct {
    // ...现有字段...
    Agents string `toml:"agents"` // 定义目录（相对包目录），布局同 agentdef.Dir
}
```

`Parse` 里按 `skills` 的方式校验：必须是包目录内的相对路径，目录须存在。不在这里解析定义，只确认目录在。

骨架清单 `scaffoldManifest` 加一段注释掉的 `agents = "agents"`，说明目录布局。

### 3.2 定义来源

`runtime/pkgs/pkgs.go` 新增：

`Package` 加字段 `AgentsDir string`（定义目录的绝对路径，空表示不带定义），`Parse` 校验通过后填上。`runtime/pkgs/agents.go` 提供 `AgentSources(ps)`（转成定义来源）与 `Infos(ctx, ps, scope)`（explain 摘要）。

定义不在 `pkgs` 里解析。合成来源不用新造：`agentdef.Multi` 已是"按给的顺序合并，同层同名以先给的为准"。

应用侧接线（`apphost.Start` 读完包之后，一处 `tenon.WithPackages(ps)`，不新开散落的选项）：`WithPackages` 把包定义单独存一路（不算应用定义，不参与缺省智能体与单定义解析），并把 `pkgs.Service` 预置给插件、把 `pkgs.Infos` 填进 `Assembly` 供 `explain` 用。合成顺序 `appDefs(WithAgents > 内联 WithAgent) > 包定义 > 内置缺省`，于是优先级是：应用显式给的来源 > 内联 WithAgent > 用户级包 > 项目级包 > 内置缺省。包里的定义与组件模板同名时，走现有的"启动报错"（`agentdef.WithTemplates`），不新写冲突规则。

> 修订（2026-11-11，T4d 独立检查）：原方案经 `tenon.WithAgents` 追加包来源，会让包定义算进 `appAgentNames`，装单定义包顶掉内置缺省、装多定义包让不带名字的 `Ask` 报歧义、还静默遮蔽同名内联 `WithAgent`（H2 回归）。改为 `WithPackages` 单独一路。

这个方向与包本身的覆盖相反：`pkgs.Load` 是同名包项目级覆盖用户级，定义是包内内容，同名时取先加载的，即用户级。前提是两个包本身不同名（`pkgs.Load` 会把同名用户级包整包去重，其定义根本不进来源）；不同名包之间的同层同名定义才走到"用户级优先"。理由见第六节，决策日志记一行。

### 3.3 校验与报错

包不自己校验定义内容。校验发生在两个时机，都走 `agentdef` 现成的：

- 装配时：`Assembly.Definitions` 调 `agentdef.WithTemplates`，模板与包里的平台定义同名即返回错误，应用当启动失败。
- 解析时：`agentdef.Resolve` 加载定义，`agentdef` 现有的校验（format、内核字段、`use.*`、工具名、`resident`）原样生效。

错误信息要能定位到包。`agentdef.Dir` 的错误现在带目录路径，包的定义目录在包目录内，路径本身已含包位置。本步不改 `agentdef` 的错误格式。验收用例检查错误信息里含清单所在目录。

### 3.4 explain

`runtime/component/explain.go` 的 `Explain` 增加可选的包信息。不改签名去加参数（调用方都要改），改为装配时记下：

```go
// PackageInfo 一个已加载插件包的摘要，explain 用。
type PackageInfo struct {
    Name     string
    Scope    string   // user / project
    File     string   // 清单路径
    Contents string   // 内容摘要
    Agents   []string // 贡献的定义名，如 "platform:helper"
}
```

`Assembly` 增加 `SetPackages([]PackageInfo)`，`Explain` 在插件列表之后输出"插件包"一段。没有包时不输出这段。

包信息由应用在装配后填：`apphost` 已经持有 `[]*pkgs.Package`，遍历得到 `PackageInfo`。定义名从 `agentdef.Dir(p.AgentsDir()).List` 取，取不到（目录后来被删）就记空并在摘要里注明。

### 3.5 信任

不改 `pkgs.Load`。项目未受信时它现在就不返回项目级包，包里的定义自然不加载。验收用例覆盖这条：同一目录，受信与未受信各加载一次，对比可用定义列表。

## 四、验收

一个测试目录只含 `tenon-plugin.toml` 与 `agents/platform/<名字>/agent.toml`，不写 Go 代码：

1. 作为用户级包加载后，该定义出现在 `agentdef.Visible` 的结果里，`Resolve` 能取到，`Version` 与直接用 `agentdef.Dir` 读同一目录的结果相同。
2. `Explain` 输出含"插件包"一段，含包名、清单路径、该定义名。
3. 同一份包放到项目级目录，项目未受信时加载结果里没有这个定义；受信后有。
4. 定义文件缺必填字段时，`tenon.New` 失败（`validateDefinitions` 对每个 `Visible` 引用调 `Load`，坏定义让它返回错误，与既有的"坏清单启动失败"策略一致，不做逐份跳过），错误信息能定位到包（含包目录名与原因）。注意 `DirSource.List` 只看文件在不在、不解析内容，坏定义仍会出现在 `Visible` 里——"不进可用定义列表"是指解析层面取不到，不是列举层面。补一个启动路径测试。
5. 包里的平台定义与组件模板同名时，装配返回错误。

测试放 `runtime/pkgs` 与 `runtime/agentdef`：包解析与目录校验在 `pkgs`，合成来源与同名冲突在 `agentdef`。`Explain` 的断言加到 `runtime/component` 现有的 explain 测试里。

## 一、这一轮框架改了什么

### 1.1 前端分层（破坏性）

框架不再提供界面代码，只保留协议客户端。

| 内容 | 变化 |
|---|---|
| `web/` 包名 | `@tenon/web` → **`@tenon/client`** |
| `web/` 内容 | 16981 行（L0+L1+L2+L3）→ **2074 行**（只有 L0 协议客户端） |
| L1 hooks / L2 组件库 / L3 工作台 | **移出框架**，归产品仓库 `client/web` |
| `web/embed.go` | 删除（框架不再内嵌前端产物） |
| `examples/web-server` | 不再传 `Static`，界面由应用提供 |

`@tenon/client` 不依赖 React，界面用 Vue / 原生 / 移动端 / TUI 都能用。

**产品侧要做的**：`client/web` 已接手 L1/L2/L3，`package.json` 依赖改为
`"@tenon/client": "link:../../../tenon/web"`。已在本轮完成。

### 1.2 `[[ui]]` 扩展点补上形状契约

新增 `runtime/pkgs/declarative.go`：把 `DeclNode`（15 种节点）与 `DeclAction`
（4 种动作）的形状写进框架。

**为什么**：`UISlot.View` 是 `json.RawMessage`，原先只校验大小不校验形状。
前端迁出后，形状只在产品仓库的渲染器里，框架的扩展点变成「有定义、无约束」。

**产品侧要做的**：渲染器（`client/web/src/ui/declarative.tsx`）按这份契约实现。
已一致（`value` 字段在 progress 与 form 上语义不同，两边都是这个约定）。

### 1.3 修复：信任提示里的目录名

`apphost/trust.go` 硬编码「项目无 **.tenon** 配置」，产品目录是 `.mortise`。
改为 `appid.DirName()` 动态取。

**注意**：这个修复在框架源码里，**要等框架下次发版（v0.2.1）才对发布构建生效**。
产品当前用 `v0.2.0`，`plugin list` 仍显示 `.tenon`；用 `go.work` 本地构建则已正确。

### 1.4 其他

- L17：子会话继承父 trace（`session_inbox` 加 `trace` 列，迁移 v16）
- L13–L16：SSE 扫描器收敛、备份职责划归应用、结构性问题治理收尾
- 失效引用清理：`StampOutbound` 注释、9 处文档路径

## 五、框架与入口的关系（2026-11-13 补充）

产品侧问过「加了新模块，CLI 要不要跟着改」。查完代码的结论是**绝大多数不用改**：

| 新模块的形态 | CLI 要改吗 |
|---|---|
| 加工具（`modules/tools/xxx/`） | ❌ 不用，CLI 通用渲染 `⚙ 工具名 {参数}` |
| 加插件（`apphost/assemble.go` 加空导入） | ❌ 不用，三入口同时装 |
| 加协议命令（`appapi/v2.go`） | ❌ 不用（只是没有终端快捷方式） |
| 需要终端专属入口 | ✅ 要改（加子命令或斜杠命令） |

**框架侧要守住的**：`appapi` 不能出现「按入口分支」的代码（`if client == "cli"` 这类）。
现在没有，要加约束测试防止腐化。详见产品侧 `05 - 入口架构与能力协商方案`。

## 七、存储实现迁出：先拆 SQL 依赖（2026-11-13 补充）

产品侧 `Mortise/docs/07 - 存储实现迁出框架方案.md` 提出把 SQLite 实现搬到产品仓库。
审查后**停掉搬家，先做前置的一步**，理由写在那一篇的「审查修订」节。这一步已经在框架里做完：

| 项 | 变化 |
|---|---|
| 投递账 | `p_workgroup_runs` 改为集合 `workgroup.runs`（固定分区 `runs`、索引 `state`、成员 id 作 key） |
| SQL 依赖 | `workgroup` 不再声明 `Requires{SQL: true}`；`service:sql` 改为可选（`?service:sql`），只用于把 v0.2.x 旧表搬进集合 |
| 装配 | 删掉 `tenon.go` 里「外部存储没有 SQL 出口时悄悄去掉 workgroup」的分支 |
| 标准组件 | 不再有组件把 `service:sql` 当必需依赖 |

**效果**：`memstore` 能装起全部标准插件，框架测试不必再为 workgroup 准备 `*sql.DB`。
旧库升级不受影响：有 SQL 出口时 `importRuns` 搬完删表（`TestImportRuns`），没有就跳过。

**已做完**（2026-11-13，v0.3.0）：SQLite 实现已迁出框架，`modules/storage/sqlite` 与
`modules/storage/store-sqlite` 两个包删除，`go.mod` 不再依赖 `modernc.org/sqlite`，
`runtime/assemble/deps_test.go` 的两个例外也已删除。详见 20 篇。

**验证**：`go test ./... -count=1` 全过，含 `TestAssembledSnapshot`、`TestPluginsSetEndToEnd`、
`TestPluginsSetKeepsAStore`、`TestWorkspaceManagerSwitch`、`TestImportLegacyProjectStore`。
例外是 `runtime/host` 的 `TestInterruptPublishesAndKeepsSession` 在全量并发下偶发一次
（中断时序，与本次改动无关），单独 `-count=5` 全过。

# 19 框架侧交付与验收交接（2026-11-13）

> 状态：生效。本篇是**框架仓库对产品仓库的交接记录**：这一轮框架改了什么、
> 产品侧要跟着做什么、哪些已经验证、哪些还没。
>
> 产品侧的对应文档：`Mortise/docs/04 - 全功能测试方案.md`（测试执行与结论）、

## 一、这一轮框架改了什么

### 1.1 前端分层（破坏性）

框架不再提供界面代码，只保留协议客户端。

| 内容 | 变化 |
|---|---|
| `web/` 包名 | `@tenon/web` → **`@tenon/client`** |
| `web/` 内容 | 16981 行（L0+L1+L2+L3）→ **2074 行**（只有 L0 协议客户端） |
| L1 hooks / L2 组件库 / L3 工作台 | **移出框架**，归产品仓库 `client/web` |
| `web/embed.go` | 删除（框架不再内嵌前端产物） |
| `examples/web-server` | 不再传 `Static`，界面由应用提供 |

`@tenon/client` 不依赖 React，界面用 Vue / 原生 / 移动端 / TUI 都能用。

**产品侧要做的**：`client/web` 已接手 L1/L2/L3，`package.json` 依赖改为
`"@tenon/client": "link:../../../tenon/web"`。已在本轮完成。

### 1.2 `[[ui]]` 扩展点补上形状契约

新增 `runtime/pkgs/declarative.go`：把 `DeclNode`（15 种节点）与 `DeclAction`
（4 种动作）的形状写进框架。

**为什么**：`UISlot.View` 是 `json.RawMessage`，原先只校验大小不校验形状。
前端迁出后，形状只在产品仓库的渲染器里，框架的扩展点变成「有定义、无约束」。

**产品侧要做的**：渲染器（`client/web/src/ui/declarative.tsx`）按这份契约实现。
已一致（`value` 字段在 progress 与 form 上语义不同，两边都是这个约定）。

### 1.3 修复：信任提示里的目录名

`apphost/trust.go` 硬编码「项目无 **.tenon** 配置」，产品目录是 `.mortise`。
改为 `appid.DirName()` 动态取。

**注意**：这个修复在框架源码里，**要等框架下次发版（v0.2.1）才对发布构建生效**。
产品当前用 `v0.2.0`，`plugin list` 仍显示 `.tenon`；用 `go.work` 本地构建则已正确。

### 1.4 其他

- L17：子会话继承父 trace（`session_inbox` 加 `trace` 列，迁移 v16）
- L13–L16：SSE 扫描器收敛、备份职责划归应用、结构性问题治理收尾
- 失效引用清理：`StampOutbound` 注释、9 处文档路径

| 编号 | 内容 | 状态 |

## 五、怎么接管

1. 读产品侧 `docs/04 - 全功能测试方案.md` 的第九节（执行结果与总结论），
   知道哪些验证过、哪些没有。
2. 读产品侧 `docs/01 - 产品说明.md` 的「安全配置的三条必读」，
   知道缺省配置的实际行为（沙箱必须开、redact 有下限、备份不能直接拷）。
3. 框架侧改动看 `CHANGELOG.md` 的 `[v0.2.0]` 段，破坏性变更清单在里面。
4. 设计意图看 `docs/01 - 设计文档/框架设计/`，`web/README.md` 讲清了
   为什么框架只留协议客户端。

# 18 内核与 I/O 分离方案

> 状态：**第 0、1 步已落地（2026-11-12）**。第 2–5 步未开始。
>
> 目标：框架内核（`runtime/`）不接触具体文件和数据库；「存哪、从哪读」由应用决定。
> 两种产品形态共用同一个内核：轻量嵌入（智能体只是别的软件的一块）和以智能体为中心的完整产品。
>
> 相关：配置源细节见第四节；落地步骤见第六节；进度见 `16 - 待办与遗留事项`。

## 一、原则与判断

1. **内核不接触数据层与文件层**。内核只定义接口与机制，不替应用决定数据存哪、配置从哪来。
2. **接口归内核，实现由框架提供，但放在内核之外、按需选装**。会话存储接口有 15 个方法，还要求条件写、写租约、旧节点写入拒绝等语义；让每个应用自己实现一遍容易出错。框架自带现成实现，并把一致性测试套件（`storetest`）公开，第三方实现可自检。
3. **配置不只有文件一种形式**。嵌入场景的配置直接是 Go 值；文件只是其中一种来源，且这种来源属于宿主层。
4. **工具读写工作区不算违规**。`fs`、`shell` 这类工具的功能本身就是读写工作区，它们是可选组件，嵌入方不开即可。

## 二、现状问题（2026-11-12 实测）

1. **根包 `tenon` 直接引用 SQLite 实现**（`agents.go` 的 `SQLiteStore` / `MemoryStore`）。
   任何人 `import tenon`，就算只用内存存储，也会把整个 SQLite 驱动编进程序。
2. **`runtime/` 里 10 个非测试文件直接调用 `os`**（profile、插件包扫描、智能体定义目录、appid 用户目录等），
   2 个文件引用 `net/http`（`modelhub`）。
3. **四套配置机制并存**：profile（只能从文件）、组件 `[plugin.*]`（跟着 profile）、`[use.*]`（已可注入）、
   组件私有文件（组件自己 `os.ReadFile` 并自己做分层合并）。
   `hooks.Setup` 约 60 行自己拼路径、判断受信、合并三层——这些是框架该做的事。

## 三、目标分层

```
runtime/          内核：只有接口和机制，不做任何读写
                  不引用 os / database/sql / net/http / modernc.org/sqlite

adapters/         框架自带的实现，各自独立成包，按需引入
  storage/sqlite    SQLite 存储（从 runtime/store/sqlite 搬来）
  storage/memory    内存存储（测试和嵌入用）
  config/file       从 TOML 文件读配置（按层：用户 / 项目 / 插件包）
  defs/dir          从目录读智能体定义

apphost/          独立运行的宿主：把 adapters 组装好，读用户目录和环境变量
```

两种用法：

```go
// 轻量嵌入：零文件、存储用宿主自己的
app, _ := tenon.New(
    tenon.Minimal(),
    tenon.WithStore(myPostgresStore),          // 宿主自己实现，跑 storetest 自检
    tenon.WithConfig("shell", shell.Config{Timeout: 60}),
)

// 以智能体为中心：用 apphost，文件和 SQLite 都已接好
rt, _ := apphost.Open(apphost.Options{Workdir: dir})
```

## 四、配置源设计（修正版）

内核只定义层，不负责合并，也不规定格式：

```go
// runtime/component/configsource.go

// ConfigSource 配置的来源（内核不关心是文件、数据库还是远程）。
// 应用经 tenon.WithConfigSource 注入；nil 时不从外部取配置（组件只用代码里给的值）。
type ConfigSource interface {
    // Layers 配置层，按「低优先级 → 高优先级」返回。
    Layers(ctx context.Context) []ConfigLayer
}

// ConfigLayer 一层配置。
type ConfigLayer struct {
    Name    string          // 层名（explain / 报错用），如 "user"、"project"、"package:x"
    Trusted bool            // 由提供方判定；组件只认这个标记，不自己判断受信
    // Values 与格式无关的配置值（文件适配器负责把 TOML 解析成它）。
    // key 约定："component/<组件名>"、"file/<组件名>/<文件标识>"。
    Values map[string]any
}
```

**与初稿的两处修正**：

1. 默认实现（读文件）不放在 `runtime/`，放在 `adapters/config/file` 或 `apphost`。
2. 接口不返回 TOML 原始字节——那等于要求嵌入方先把配置写成 TOML 文本，是把文件格式偷偷带进接口。
   返回与格式无关的 `map[string]any`，组件自己 `toml.Unmarshal` 等价物解码并决定合并方式。

组件侧用 `Meta.Files` 声明私有配置（Key / Schema / Optional / Merge），
框架按层取值、解码、合并后经 `Registrar.File(key)` 交给组件。
`hooks.Setup` 从约 60 行降到约 10 行，不再知道配置在哪个目录、有几个层级、什么时候脱敏。

`[use.*]` 是会话级配置（每轮按触发者重算），与部署期配置不同概念，`useconf.Source` 保持独立不动。

## 五、例外（允许留在内核，写进允许名单并注明理由）

| 项 | 理由 |
|---|---|
| `toolhub/attrs.go` 引用 `os/exec` | 沙箱接口签名用到 `exec.Cmd` 类型，只有类型引用、没有实际读写；以后再看要不要换成抽象类型 |
| `runtime/store/sql.go` 引用 `database/sql` | 可选能力接口 `store.SQL` 的方法签名用到 `*sql.DB` 类型；随第 3 步一起评估 |
| `fs`、`shell` 等工具（在 `modules/`，本就不受内核禁令约束） | 功能本身就是读写工作区，可选组件 |

## 六、落地步骤（每步一提交，行为不变）

| 步 | 内容 | 风险 | 状态 |
|---|---|---|---|
| **0** | 加「内核禁止引用」测试：`runtime/` 不许引用 `os`、`os/exec`、`database/sql`、`net/http`、`modernc.org/sqlite`。现有违规列进允许名单，之后只许删不许加 | 无 | **已落地**（`kernel_io_test.go`；故意加一条 `os` 引用，测试准确报出后已还原） |
| **1** | 根包不再引用 SQLite 和 memstore：`SQLiteStore` / `MemoryStore` 移到对应实现包（`runtime/store/sqlite`、`runtime/store/memstore`） | 低（删公开函数，API 不兼容，新项目可接受） | **已落地**（`memstore.MemoryStore()`、`sqlite.SQLiteStore(ctx, path)`；公开面快照已更新） |
| **2** | 配置源抽象（按第四节），文件实现放在 `runtime/` 之外；迁移 hooks → permission → mcp / models | 中 | 未开始 |
| **3** | `runtime/store/sqlite` 与 `memstore` 搬到 `adapters/storage/`，`storetest` 公开成一致性测试套件 | 中高（约 5400 行，主要是路径与引用改动） | 未开始 |
| **4** | profile 读文件、插件包目录扫描、`agentdef.DirSource`、`appid` 读环境变量和用户目录的部分移到 `apphost` 或 `adapters/`；内核只保留纯解析函数（文本进、结构出） | 中 | 未开始 |
| **5** | `modelhub` 的 HTTP 辅助代码移出内核，模型适配器允许注入 `http.Client` | 中 | 未开始 |

**验证**：每步 `gofmt` / `vet` / `go test ./...` / `-count=2` / 回归快照 / 公开面快照 / 文档链接，双仓库推送确认 CI。

**说明**：第 3 步结束前，内核仍然带着具体存储实现，「轻量嵌入」只能算部分可用（第 1 步之后至少不再被迫编进 SQLite 驱动）。

## 七、待拍板（配置迁移时再定，不影响第 0、1 步）

1. 插件包配置是否统一放第 ② 层（会改变 hooks 的优先级：现状插件包排在最后、优先级最高）。
2. 是否保留 `project_hooks` 这个额外闸门。
3. `mcp` 是否增加用户级配置（现状只有项目级）。

## 八、验收

1. `runtime/` 不再引用 `os` / `database/sql` / `net/http` / `modernc.org/sqlite`（允许名单清空）。
2. `import tenon` 不再带入 SQLite 驱动。
3. `hooks` 的 `Setup` 从约 60 行降到约 10 行，不再出现 `filepath.Join` / `userHome` / `Merge`。
4. 应用能 `tenon.WithConfigSource(mySource)` 从数据库或远程提供配置，也能只用 Go 值、零文件运行。
5. 现有行为不变（回归快照一致）。

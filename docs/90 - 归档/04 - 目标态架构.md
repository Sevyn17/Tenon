# 目标态架构：以智能体为中心的内核（摘要）

> 状态：草案（2026-11-01）。本篇已拆分细化到 [框架设计](<../框架设计/00 - 索引.md>) 目录，正文以那里为准。原文全文存档在 [99 - 目标态架构草案（原文存档）](<../框架设计/99 - 目标态架构草案（原文存档）.md>)，只读。

> 来源：2026-11-01 与用户的讨论，起因是 [Super-agent 调研](<../调研报告/02 - Super-agent 对 YBase 的启发.md>)。

## 要点

- **定位**：本项目交付的是智能体底座，一个 Go 库（SDK）加标准组件。桌面版、SaaS、客服、电商、端侧守护进程等都是引用底座的上层应用，另行排期（A15）。
- **中心换成智能体**：智能体 = 定义，不运行、没有实例；会话是唯一执行单位，内部串行、会话之间并行。内核对象只有定义、会话、信封、资源（小组、看板、外部线程）（B9 取代 A1、A2、A12 的实例模型；A6、A7）。
- **协作**：没有硬性编排，也没有组合智能体。协作只有派发式和自主式两种，可以混用；人也是一个地址（A3、A5、A8）。
- **定义**：以 Go 结构体为准，内核只认六个字段，其余写在 `[use.<组件>]` 和应用自留的 `[x.*]` 里；定义是一个定义包，版本为整包内容哈希（A13、B4、B5）。
- **数据**：内核表结构固定；组件通过存储原语（`Store`、`Collection`）存数据，不直接写 SQL；应用的信息挂在 `meta` 上，或者订阅事件写进自己的库（B2、B6、B8）。
- **命名**：编译进程序的单元叫"组件"，"插件"专指 Node / Python 外部扩展；代码改名在 T1 一起做（A11、A14）。

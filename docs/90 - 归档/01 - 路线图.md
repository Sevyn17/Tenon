# ybase kernel 路线图

> 原则：每个阶段结束时智能体都必须能用；先能用、再好用、再可度量、最后自进化。没有评估就没有自进化。
> 旧设计（platform / agentrt / Plugins）冻结在 tag `pre-kernel-freeze`，按需回收，不整体复活。

## 阶段总览

| 阶段 | 目标 | 退出判据 |
|---|---|---|
| P0 好用（原 P0 + P1 合并，2026-10-28） | 本地 CLI 达到主流 harness 日常可用水准 | 用真实模型改通一个仓库里的 bug；崩溃后按原 id 续跑；连续 2 小时日常编码不需要切回其他工具 |
| P2 可度量 | 每次运行可追踪、可回放、可打分 | 本地评测集一条命令跑完，出分数与成本报告 |
| P3 会积累 | 记忆、技能、经验从使用中沉淀 | 同类任务第二次比第一次步数 / 成本明显下降 |
| P4 自进化（RSI） | 在评估把关下改进自身 | 自动提出的改进经评测门禁合入，分数单调不降 |
| P5 外延 | 多端与云 | 按需从冻结 tag 回收 |

## P0 好用（原 P0 + P1 合并）

每个阶段走同一循环：调研 → 方案（`docs/<阶段>/`）→ 讨论确认 → 开发计划 → 执行与验收。框架模块方案见 [docs/10 - 框架模块/](<10 - 框架模块/00 - 索引.md>)。

框架（模块）：
1. 会话内核：修 C1–C3（构造单一路径、压缩后保留尾部的缺陷、对拍测试），加 `RequestHash`（[10 - 框架模块/01 - 会话内核.md](<10 - 框架模块/01 - 会话内核.md>) 定稿）。
2. 持久化：单个 SQLite 文件；日志 + 头部 + 幂等记录 + 请求记录（内容寻址存 BlobStore），模型调用前 checkpoint；恢复按原 id 续跑（[10 - 框架模块/07 - 数据契约.md](<10 - 框架模块/07 - 数据契约.md>)）。
3. 会话宿主：actor、全量命令集、inbox、挂起与人工确认（单一路径）、条件写头部（[10 - 框架模块/02 - 会话宿主.md](<10 - 框架模块/02 - 会话宿主.md>)）。
4. 插件管理器：02 最小子集 + 作用域资源回收（context + 清理注册表）；profile（TOML）+ mandatory + explain（[10 - 框架模块/03 - 插件管理器.md](<10 - 框架模块/03 - 插件管理器.md>)）。
5. 工具管理器：调用栈（入口 → Transform → Guard → 执行器）、读写锁并行、幂等、超大结果存工件、可用集冻结 + 显露集按需追加（[10 - 框架模块/04 - 工具管理器.md](<10 - 框架模块/04 - 工具管理器.md>)）。
6. 模型管理器：协议适配器（openai-chat、anthropic-messages）+ 声明式提供方，调度器内重试、三类超时、熔断、能力只收窄（[10 - 框架模块/05 - 模型管理器.md](<10 - 框架模块/05 - 模型管理器.md>)）。
7. 事件总线（易失订阅 + `Follow` 可靠回放）、数据契约（SQLite）；前端只预留后端接口（[10 - 框架模块/09 - 前端插件体系.md](<10 - 框架模块/09 - 前端插件体系.md>)）。开发计划见 [30 - 计划与报告/01 - P0 开发计划.md](<30 - 计划与报告/01 - P0 开发计划.md>)。

插件：
8. 工具：精确编辑、grep / glob、行范围读、shell（含后台 job）、网页抓取 / 搜索、todo / 计划 / ask_user。
9. 上下文：项目指令（AGENTS.md）、压缩（插件化）、技能（Agent Skills 标准，按需加载）。
10. 安全：权限 Guard（三档 + 确认）、沙箱、密钥（环境变量）、脱敏。
11. 协作：子智能体（fork / spawn，结果经 inbox 回交）、后台任务。
12. 扩展：MCP 客户端、用户脚本钩子插件（工具前 / 工具后 / 回合结束）。
13. 入口：CLI；真实模型冒烟。

## P2 可度量（RSI 的地基）

1. Trace：OTel 只记存储里没有的元数据（重试、Guard 判定、耗时）；完整轨迹由导出插件从存储投影为 ATIF。
2. 回放：会话存储即录制格式，`replay` 提供方插件按请求记录回放模型输出。
3. 评测集：Polyglot Go 题 + 本仓库 bug-fix 提交生成 20–50 题；dev / holdout / regression / anticheat 四层；进程 + 临时副本 + 沙箱隔离，Docker 可选（[10 - 框架模块/08 - 评测运行器.md](<10 - 框架模块/08 - 评测运行器.md>)）。
4. 评测命令：独立二进制 `ybase-eval`，输出通过率、步数、token、成本；配对 bootstrap 门禁。
5. 回归门禁：改动 harness 代码 / 提示词 / 工具描述前后各跑一次，分数下降即拦截。

## P3 会积累

1. 记忆：项目级 / 用户级，显式写入 + 会话结束自动提炼，带来源与时间，可查可删。
2. 经验提炼：从 trace 中抽取失败模式与成功路径，形成候选经验条目。
3. 技能策展：高频成功路径提炼为 SKILL.md 候选，使用计数与效果写旁路 JSON。
4. 检索注入：按任务相关性注入记忆与技能，注入量受预算约束。

## P4 自进化（RSI）

分三级，逐级放开，每级都必须通过 P2 的评测门禁。

| 级别 | 可修改对象 | 机制 | 人工把关 |
|---|---|---|---|
| L1 制品进化 | 系统提示词、工具描述、技能、记忆 | 失败 trace → 提出改动 → 评测对比 → 合入 | 合入前人工确认 |
| L2 策略进化 | 压缩阈值、工具选择、子智能体分工等配置 | 参数搜索 + 评测 | 周期性审阅 |
| L3 代码进化 | harness 自身代码（工具、插件、循环） | 隔离 worktree 内自改 → 构建 + 测试 + 评测 → 存档（Darwin Gödel Machine 式变体档案，保留多样性而非只留最优） | 必须人工审阅 diff |

不可自改的红线（写死在代码里，评测也覆盖）：
- 内核安全不变式（S1–S7）、权限与沙箱策略、评测集与判分器本身。
- 任何自改都在隔离副本中进行，可一键回滚到任一历史版本。

## P5 外延

桌面 / Web UI、会话协议、云 Worker、多租户与计费，按真实需求从 `pre-kernel-freeze` 回收。

## 插件与工具层：逐个设计流程

每个组件走同一流程，一次一个，产出放 `kernel/docs/<组件>.md`（一页以内）：

1. 调研：Codex、Claude Code、DeepSeek Harness（`refer/deepseek-harness`）、OpenCode、Aider、Cline 等的做法，附源码 / 文档出处。
2. 对比：列 2–3 种方案的取舍。
3. 决策：选定方案与理由，标出不做的部分。
4. 最小实现 + 测试。
5. 评测：P2 就绪后，用评测集验证收益。

建议顺序：编辑工具 → 搜索工具 → shell / 沙箱 → 权限 → 压缩 → 项目指令 → 并行执行 → 子智能体 → 技能 → MCP → 钩子 → 记忆 → web / 浏览器。

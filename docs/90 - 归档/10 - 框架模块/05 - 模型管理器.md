## 3. 竞品对比

| 维度 | 本方案（06 / M3） | DSH `dsh-llm` / `-retry` | opencode | pi `ai` / `durable` | Codex |
|---|---|---|---|---|---|

| 推理回放 | 03 #9：按 Assistant.model 过滤 | "回放状态只在同一适配器内流动"，否则发出前丢弃 | — | — | — |
| 缓存亲和 | 未写 | — | — | 每个会话一个持久 UUIDv7，作为 `sessionId` 传给提供方用于前缀缓存与会话亲和；重试、压缩、换模型都不变；fork 换新 | — |

可借鉴点：

1. **单次尝试与重试分开**（DSH）：适配器只做一次，重试是策略。我们放在调度器里实现机制、策略走配置，效果一致（见 D1 为何不照搬到步边界）。
2. **稳定失败 code + 恰好一个终止事件**（DSH、pi）：上层只按 code 分支，不解析文本；流不会"无声结束"。
3. **"模型可见 ⟺ 已记录"**（DSH）：我们用"Transform 之后的最终请求进请求记录"实现同一条不变式，同时保留 Transform 改写能力。
4. **推理块只回传给同一适配器**（DSH）：印证 03 #9。
5. **会话级缓存亲和 id**（pi）：零成本提高前缀缓存命中，采纳为 D5。
6. opencode 允许插件钩子改写重试决定：我们不开这个钩子，重试策略只走配置，避免插件把有界重试改成无界。

## 4. 推荐方案

### 4.1 接口（Go）

```go
// Adapter：一个协议的单次流式调用。不重试、不聚合、不计量。
type Adapter interface {
	Protocol() string                                        // openai-chat / anthropic / openai-responses
	Stream(ctx context.Context, req *Request, ep Endpoint) Stream
}

// Stream：恰好以一个终止事件结束（Done 或 Failed），之后不再有事件。
type Stream interface{ Next() (Event, bool) }

type Event struct {
	TextDelta, ReasoningDelta string
	ToolCallDelta              *ToolCallDelta
	Usage                      *session.Usage   // 先于终止事件
	Done                       *Done            // 终止：StopReason + 完整 AssistantItem
	Failed                     *Failure         // 终止：稳定 Code + Message + RetryAfter
}

type Failure struct {
	Code       Code          // 见 §4.3
	Message    string
	RetryAfter time.Duration // 提供方给出时
	Partial    *session.AssistantItem // 已收到的部分（中断时写 interrupted 条目）
}

// ModelHub：模块。会话调用走层，side_call 直进调度器。
type ModelHub interface {
	Call(sc *Scope, cx *Cx, req *Request) Stream             // Transform → Guard → 调度器 → 适配器
	SideCall(sc *Scope, attr Attribution, alias string, req *Request) Stream
	Resolve(alias string) (Plan, error)                      // 压缩等插件按计划最小窗口估算
}
```

`Request` 带 `RequestID`（来自内核 `ModelNeed`）、`SessionKey`（D5）和别名；调度器把别名展开为计划，逐项选适配器。

### 4.2 调度器：单次尝试 + 重试策略

```text
for 每个计划项 step:
  if 熔断打开(step) → 下一项
  for attempt in 0..policy.max:
    stream = adapter.Stream(...)              // 单次
    转发增量（经 DeltaFilter）
    终止 Done   → 返回
    终止 Failed：
      ContextOverflow     → 原样上抛（压缩层处理）
      Auth / InvalidRequest / NoAdapter / MissingCredential → 换下一项
      可重试 code 且预算未尽 且未超 deadline
                          → 已发出增量则发 StreamReset；
                            记尝试（观测层）；等待 min(RetryAfter≤上限, 退避)；继续
      其他                → 换下一项
全部失败 → 返回最后一个 Failed
```

- 重试只在调度器内，**不进会话日志**：模型调用前已 checkpoint 并写了请求记录（session-host H11、session-core D1），等待退避时崩溃，恢复后按请求记录原样重发，不丢、不重复写条目。尝试记录（序号、code、延迟、降级原因）写观测层（OTel），轨迹导出从这里取。
- **（review-1 R3 修订）** 回交内核始终用 need id（`RequestID`，内核生成、恢复沿用）。发给厂商的幂等 / 去重键是 attempt key = need id + 计划项序号：同一计划项内重试沿用，换计划项即换；每次尝试写一个 attempt span。
- **（review-1 G5）缓存用量归一**：每个协议适配器把厂商字段归一到 `Usage.CacheRead / CacheWrite`（OpenAI `prompt_tokens_details.cached_tokens`；DeepSeek `prompt_cache_hit_tokens`；Anthropic `cache_read_input_tokens` / `cache_creation_input_tokens`），厂商未报标 `Missing`，不当作未命中。attempt span 记请求外壳哈希，命中率骤降时可定位是哪一步改了前缀。命中率与节省金额是投影（目录单价含缓存读写价）。
- 取消：`Scope` 取消即停止当前尝试与退避；已收到的部分以 `Failed{Code: Aborted, Partial}` 返回，宿主写 interrupted 条目（保留用户已看到的文本）。

### 4.3 稳定失败 code

`NO_ADAPTER`、`MISSING_CREDENTIAL`、`AUTH`、`INVALID_REQUEST`、`RATE_LIMIT`、`QUOTA`、`SERVER`、`TIMEOUT`、`TRANSPORT`、`EMPTY_RESPONSE`、`CONTEXT_OVERFLOW`、`CONTENT_FILTER`、`ABORTED`。可重试集合：`RATE_LIMIT`、`SERVER`、`TIMEOUT`、`TRANSPORT`、`EMPTY_RESPONSE`。上层一律按 code 分支。

### 4.4 side_call 语义（补 06 §3.3）

- **取消**：继承调用方作用域。压缩在 Transform 层里发起的摘要调用挂在回合作用域上，回合取消即取消摘要。
- **超时**：调用方传入；未传时取调用方所在层的超时（压缩层 120s）。
- **不经插件层、不发增量**；结果如要落库，必须过 redact 落库扫描（06 原规则）。
- **计量**：归属记到调用方会话，写观测层；不进内核 `TurnInfo.Usage`（那是模型可见回合的用量）。

### 4.8 点位与插件（2026-10-28 补）

模型管理器与工具管理器同构：模块不可替换，管理的内容由插件注册到点位。

| | 工具管理器 | 模型管理器 |
|---|---|---|
| 模块内置，不可插入 | 入口环节、执行器 | 调度器（降级计划、熔断、超时、重试） |
| 插件注册的内容 | 工具、工具来源 | **协议适配器**、**提供方**（声明式数据）、目录条目、目录来源（本地发现） |
| 插件挂的层 | 工具 Transform / Guard | 模型 Transform / Guard（压缩、路由、输出检查） |
| 插槽 | ToolResultStore、BlobStore | ModelCatalog |
| 给其他插件的能力 | 工具调用 | `side_call` |

**两层拆分（补充调研得出，见 §3.2）：**

| 层 | 是什么 | 谁提供 | 数量 |
|---|---|---|---|
| 协议适配器 | 一种 wire 协议的翻译：请求组装、流解析、工具 id 合法化、缓存标记、推理块、错误归一为稳定 code | 插件（代码） | 少：openai-chat、anthropic-messages、openai-responses、gemini… |
| 提供方 | `{id, base_url, auth: env:/keychain:, api: 用哪个协议适配器, models: 目录条目, compat: 兼容标志}` | 插件**或**用户 `models.toml`（纯数据） | 多：deepseek、moonshot、ollama、openrouter… |

- 新增一个 OpenAI 兼容厂商 = 写一段提供方声明，不写代码。
- **兼容标志是数据**（如 `supports_prompt_cache_key`、`reasoning_field`、`max_tokens_field`、`supports_parallel_tool_calls`），由协议适配器读取；不为每个厂商分叉适配器。
- 目录条目字段：上下文窗口、输出上限、输入模态、推理档位映射（档位 → 厂商值，`null` = 不支持）、缓存保留档、单价。
- 本地模型（ollama、lmstudio、vllm）由插件注册**目录来源**：启动时从本地服务发现模型，失败只告警、不阻塞装配。

**目录合并顺序**（后者覆盖前者，键 = `provider/model`，整条覆盖、不做字段级合并；`explain` 显示每条的来源）：
内置快照 < 插件提供 < 本地发现 < 用户 `models.toml`。

**插件例子：** `provider-deepseek`（提供方声明 + 目录）、`adapter-anthropic`（协议适配器）、`provider-ollama`（提供方 + 目录来源）、`compact`（模型 Transform 层 + `side_call`）、`router`（模型 Transform 层，改别名）、`embedding`（插件服务 `Embedder`，不进模型管理器，06 §8）。

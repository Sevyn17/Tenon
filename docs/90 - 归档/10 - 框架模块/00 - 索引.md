# 框架模块评估（P0 第一轮）

流程：调研 → 方案 → 讨论确认 → 开发计划 → 执行与验收。本目录是"调研 + 方案"的产物，每个模块一份，逐份评审。

## 来源约定

- 以 agentrt 基线为准：`agentrt/.devkit/00 基线/`（核心运行时 M3–M7、M10；共享 S1–S7）。
- 02 初步设计作理由参考：`.devkit/02 - 初步设计/02 - 智能体/01 - 框架/`（01–10）。

- 现有代码：`kernel/`（session 拷自 ybase-session，agent / model / tools / cmd 为新写的最小实现）。

## 框架构成

框架 = **6 个模块**（不可替换）+ **2 篇约定**（数据契约、通信协议）+ 插槽默认实现；插件在框架之外（01 §1）。评测运行器是独立进程，不属于框架。

## 每份文档的固定结构

1. **来源**：基线篇章节 + 02 对应篇章节；基线与 02 的主要差异。
2. **逐条评估**：表格，每条结论一行，处理方式取 保留 / 简化 / 推迟 / 删除 / 修正，附理由；保留条目摘录原文要点并注明出处（篇名 §节）。
3. **竞品对比**：Codex、DSH 读实现代码（注明文件路径），Claude Code、OpenCode 只用公开资料；未读原文的标"未核实"。
4. **推荐方案**：本地单用户内核范围内的 Go 接口形态与关键规则。
5. **待拍板**：需要用户决定的点，每点给出选项与倾向。

处理方式口径：本地单用户、单进程、CLI 优先；多租户、多节点、平台对接、多端同步一律"推迟"，不是"删除"。

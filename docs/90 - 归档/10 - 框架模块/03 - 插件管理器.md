## 5. 推荐方案

### 5.1 插件接口（Go）

```go
// Plugin：编译期注册，profile 启用。
type Plugin interface {
	Meta() Meta
	Setup(cx *SetupCx) error            // 只做注册：插槽、服务、工具、层、钩子、订阅、模板、迁移
	Start(sc *Scope) error              // 建立能力（进程、连接）；后台任务用 sc.Go
}

type Meta struct {
	Name     string
	Version  string
	Requires []Dep      // 插槽 / 插件服务
	Provides []string   // 插件服务名
	Config   *Schema    // 每项标注能否在智能体层覆盖
	Trust    TrustLevel // 内置恒为 Trusted；为外部插件预留
}

// 注册（全部在 Setup 内，装配期结束后注册表只读）。
func (cx *SetupCx) FillSlot(s Slot, impl any) error
func (cx *SetupCx) Provide(name string, svc any) error
func Use[T any](<cx *SetupCx, name string>) T                 // 只能取 Requires 里声明过的
func (cx *SetupCx) Tools() ToolRegistry                     // register_tool / register_source
func (cx *SetupCx) Models() AdapterRegistry
func (cx *SetupCx) ModelLayer(spec LayerSpec, l ModelLayer)
func (cx *SetupCx) ToolLayer(spec LayerSpec, l ToolLayer)
func (cx *SetupCx) Hooks(h HookSet)                         // create / restore / before_turn / after_turn
func (cx *SetupCx) Subscribe(f Filter, h Handler)
func (cx *SetupCx) AgentTemplate(def AgentDef)
func (cx *SetupCx) OpenPoint(p PointSpec)                   // 乙类点位（如 before_compact）

type LayerSpec struct {
	Position Position   // Transform / Guard
	Failure  Failure    // Transform 默认 FailOpen；Guard 只能 FailClosed
	Timeout  time.Duration
	Order    int        // 同位置内的显式序（§5.2）
}
```

插件在 `Setup` 里没有资源，只有注册；所有资源都在 `Start` 或钩子里创建，并挂在拿到的作用域上（§5.3）。

### 5.2 同位置层排序（补 P21）

1. 位置由外到内：Transform → Guard → 内置环节。
2. 同位置：可选在外、强制在内；Guard 最内侧一定是强制插件。
3. 同一组内按 `Order` 升序，`Order` 相同按插件名字典序——结果确定、`explain` 可见。
4. 固定约束：compact 必须是最外层 Transform（启动自检）；会改 `Request.model` 的路由层只能换成窗口不小于原计划最小窗口的模型（compact 按计划最小窗口估算，不依赖层序）。

### 5.3 作用域（L1，借 Cordis fiber）

```go
// Scope：context + 清理注册表。父作用域取消即级联取消，清理按注册倒序执行。
type Scope struct { /* ctx context.Context; parent *Scope; cleanups []func(context.Context) error */ }

func (s *Scope) Context() context.Context
func (s *Scope) OnClose(f func(context.Context) error) // 注册清理
func (s *Scope) Go(name string, f func(ctx context.Context) error) // 受监管后台任务：panic 捕获、按策略重启、作用域关闭时取消并等待
func (s *Scope) Child(name string) *Scope
```

四层：进程 → 插件 → 会话 → 回合。

| 作用域 | 创建 | 关闭 | 典型资源 |
|---|---|---|---|
| 进程 | 启动 | 进程退出（drain 后） | 日志、OTel 导出器 |
| 插件 | `Start` 前 | 进程退出 | 沙箱守护进程、MCP 服务器连接池、文件监听 |
| 会话 | actor 拉起 | actor 退出（空闲 / Close / Delete / Drain / panic） | 持久 shell、浏览器标签、会话级 MCP 连接 |
| 回合 | before_turn 之前 | TurnEnd 之后 | 回合内临时资源；工具调用只用 context 取消，不单独开作用域 |

钩子与层的上下文 `Cx` 携带当前会话 / 回合作用域，插件在其上 `OnClose` 即可，不依赖 `SessionUnloaded` 事件送达。

### 5.4 生命周期点位全表（含 L2–L5）

| 层 | 点位 | 类型 | 说明 |
|---|---|---|---|
| 进程 | Setup / Start / drain / stop | 插件接口 | stop 即插件作用域关闭 |
| 会话 | create（带 `origin`：new / fork / subagent，及 `parent_id`） | 钩子 Transform+Guard | **L2** |
| 会话 | restore | 钩子 | — |
| 会话 | 会话作用域关闭 | 作用域 | **L1**，取代"订阅 SessionUnloaded 清理" |
| 回合 | before_turn（Allow / Deny / Record） | 钩子 | — |
| 回合 | after_turn（带结束原因） | 钩子 | 需要"继续"时向 inbox 投 Send，不新增机制 |
| 步 | 模型层 Transform / Guard | 层 | 每步提醒注入、压缩、路由 |
| 调用 | 工具层 Guard（前）/ Transform 返回侧（后） | 层 | 权限、用户脚本钩子、脱敏 |
| 压缩 | before_compact(upto)，可 Deny | 乙类点位（压缩插件开） | **L3**：记忆先提炼再丢 |
| 空闲 | `SessionIdle(after)` 事件 + 定时插件"空闲且有预算"触发 | 事件 | **L4**：整合任务按存储水位幂等执行，事件丢失只会推迟 |
| 配置 | 数据级热更新由插件自行监听；插件级变更只对新会话生效，P0 进程重启生效 | 规则 | **L5** |
| 人工 | `HumanRequested` / `HumanResolved` | 事件 + 挂起记录 | 可靠性由挂起记录保证 |

不做插槽：
- **观测（S2/S3，review-1 G2 修订）**：模块把 span（回合 / 步 / 尝试 / 工具 / 层 / 钩子 / 压缩）写进本地 `trace_spans` 表，这是观测事实的**唯一来源**；OpenTelemetry 只是从这张表导出的投影，导出器可多个，作为进程配置。span 属性只放元数据与引用，不放正文。用量、缓存命中（G5）并入尝试 span。
- 沙箱、权限、Redact、向量、嵌入：插件服务或调用层，不冻结为插槽（01 原则 2）。

### 5.6 可靠观察规则

- **需要完整性的消费者（审计、轨迹、索引、经验提炼）一律按存储游标读**（日志 `idx` / `sync_seq`、请求记录、工具结果、截断归档段），不订阅事件总线。
- 事件总线只给界面渲染与尽力而为的订阅者。
- 完整轨迹 = 会话日志 + 请求记录 + 工具结果 + 归档段 + OTel 元数据；ATIF 格式由导出插件投影生成，不另存全文（一个事实只存一处）。
- 压缩在 base profile 默认启用 basic 策略，不保留"无压缩时内核机械截断"的特例路径。

### 5.6.1 功能演进总原则（review-1，2026-10-28）

1. **事实层完整**：会话日志、请求记录、工具结果、span、父子关系五类事实都可靠落本地。新功能缺数据时先补事实，不加机制。
2. **功能是投影或插件**：统计、轨迹、缓存命中率、分支树是读事实的投影；行为功能挂点位。必须改内核或模块才能做的功能，说明漏了点位，回到覆盖矩阵补。
3. **记录只加不改**：条目 `meta`、span 属性、请求记录来源标签同版本只加字段，读方忽略未知字段（event-bus D3 推广到所有记录）。
4. **R2 约束落代码**：全部模型 Transform 跑完后，调度器校验前缀与基础请求逐字节相同（压缩层用 `BuildWithCompaction` 的视图除外）、tools 为原集合子集；违反按 Guard 失败处理。

> 2026-10-31 薄内核改造（docs/30 - 计划与报告/04 - 薄内核改造方案.md）新增会话构造期点位，定义在 `kernel/runtime/points.go`：
> - `session_tools`（ToolsEntry，按 Order、插件名排序）、`session_layer`（LayerEntry，非 Guard 在外、Guard 在内，再按 Order）、`system_block`（BlockEntry）：现有点位都是进程级的，做不到每会话一份（指令层的已装载集合、run_code 要本会话 hub、技能按会话扫描）。对应矩阵的 Tool / TL / Cr 列。
> - `after_turn`（AfterTurnFunc）：即 AT 列，原先 hooks 直接挂在 `host.Hooks.AfterTurn`。
> - `ready`（ReadyFunc）：会话构造器就绪后执行一次（工作组补投要打开领导会话）。现有 Start 早于构造器设置，做不到。

## 6. 定稿结论（2026-10-28，D1–D3 均按倾向采纳：TOML / Go struct + tag 生成 Schema / 指数退避重启 3 次后 degraded）

| # | 问题 | 选项 | 倾向 |
|---|---|---|---|
| D1 | profile 文件格式 | A. TOML（与 02 示例一致）；B. YAML 加按 id 补丁（Cordis 风格） | A：只需 include + mandatory + 插件列表与配置，不需要补丁语义；层级浅，TOML 更不易写错 |
| D2 | 插件配置 Schema 表达 | A. Go struct + tag，生成 JSON Schema；B. 手写 JSON Schema | A：单一来源，类型安全，explain 与智能体定义校验共用 |
| D3 | 后台任务重启策略默认值 | A. 不重启，失败发 Error 事件；B. 指数退避重启最多 3 次 | B：常驻能力（MCP 连接、文件监听）断开后自愈；超过 3 次标记插件 degraded 并在 explain 中可见 |

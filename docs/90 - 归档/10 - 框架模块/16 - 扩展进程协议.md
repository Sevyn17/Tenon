# 扩展进程协议（外置插件第二档，仅设计）

状态：**只写设计，未实现**。遇到插件包（[15 - 插件包](<15 - 插件包.md>)）做不到的第一个真实需求时再实现，届时按需求裁剪本文。

## 一、定位

插件包只能复用已有能力（MCP 工具、钩子命令、技能、提示词）。需要参与会话装配的扩展（改系统块、回合后处理、订阅事件、包住工具调用）目前只能写进内核的 Go 插件。扩展进程协议让这类扩展用任意语言写，作为子进程运行。

## 二、传输与握手

- stdio 上的 JSON-RPC 2.0，消息格式与 MCP stdio 传输相同（一行一个 JSON）。协议是 MCP 的超集：一个扩展进程同时是合法的 MCP 服务，工具、资源照 MCP 走。
- `initialize` 时双方在 `capabilities.experimental.ybase` 里声明版本和要用的能力；内核不认识的能力忽略，扩展没声明的能力内核不调用。
- 只声明 MCP 能力的进程就是普通 MCP 服务。

## 三、`ybase/*` 能力

| 能力 | 方向 | 说明 |
| --- | --- | --- |
| `ybase/systemBlock` | 内核 → 扩展 | 新会话装配时请求系统块；返回 `{text, order, breakpoint}`，对应内核的 system_block 挂点 |
| `ybase/afterTurn` | 内核 → 扩展（通知） | 回合结束回调，带会话 id 与回合摘要；对应 after_turn 挂点，不阻塞下一回合 |
| `ybase/subscribe` + `ybase/event` | 扩展 → 内核订阅，内核 → 扩展推送 | 订阅事件总线的主题（通配同总线规则），慢消费者丢弃并补发 resync |
| `ybase/callLayer` | 内核 → 扩展 | 包住工具调用的一层，分 Guard（调用前决定放行 / 拒绝 / 询问）与 Transform（改参数或结果） |

调用层规则：

- 扩展在握手时为每个层声明 `kind`（guard / transform）、匹配的工具名、`timeout_ms`（必填，内核封顶）。
- 失败策略固定，不可配：**Guard 超时或出错按拒绝处理**（安全优先），**Transform 超时或出错按放行处理**（原样传递，不丢结果）。两者都记事件并在界面提示。
- 层的顺序：内置层在前，扩展层按装配顺序。

## 四、启动与 SDK

- 声明方式沿用插件包：清单里加 `[[extension]]`（command / args / env / timeout / sandbox），或在 `[[server]]` 上标 `ybase = true`。
- 提供 Python、Node、Go 三个薄 SDK，只封装握手、能力注册和 JSON-RPC 分发；Python 用 `uvx`、Node 用 `npx` 启动，Go 直接编译。
- 进程放在沙箱里运行（同 MCP stdio 子进程：`sandbox` 字段，缺省取新会话档位的沙箱级别），环境变量去掉密钥与 `YBASE_*`。

## 五、与内置插件相同的规则

- 装配：每个扩展进程在装配里是一个插件，名字 `ext:<包名>/<扩展名>`，声明影响（system_prompt / tools / rewrite_result / exec / network），进 `ybase explain`。
- 开关：profile 里 `[[plugin]] name = "ext:…" enabled = …`，缺省关；包不替用户开。
- 信任：项目级包里的扩展只在项目受信时加载。
- 生命周期：进程随运行时启动、退出；崩溃时该扩展的层按上面的失败策略处理，并提示。

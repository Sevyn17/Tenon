# 14 - 网页服务（api-server）

> 状态：已实现第一版（`kernel/apps/server`，可执行文件 `ybase-server`）。协议沿用 [12 - 应用接口层](<12 - 应用接口层.md>) protocol 1，前端沿用 [13 - 桌面端与前端](<13 - 桌面端与前端.md>) 的共享前端（`web.Dist()` 嵌入）。

## 一、形态：应用，不是插件

[00 - 总体架构](<../00 - 总体架构.md>) 原写“api-server 插件”。实际做成应用 `kernel/apps/server`，和 `apps/desktop`、`apps/ybase` 并列，理由：

- `appapi.App` 在应用层构造（`boot.BuildApp`），插件装配时拿不到 App，也不应拿到（插件只经点位与宿主交互）。
- 插件不得 import 应用层与前端嵌入包（`core/runtime/deps_test.go` 的依赖规则）；做成应用可以直接复用 `apps/internal/boot` 与 `web`。
- 是否开网页服务是“以什么方式运行”的选择，不影响会话内容，按分界原则不需要做成 profile 插件。

## 二、启动

```
cd kernel
go build -o ybase-server.exe ./apps/server
ybase-server -dir <项目目录> [-addr 127.0.0.1:0] [其余同桌面端：-base -model -profile -mode -sandbox -mcp -max-steps -trust-project -project-hooks]
```

终端打印：

```
YBase 网页服务：<项目根>
  打开：http://127.0.0.1:<端口>/?token=<令牌>
  按 Ctrl+C 结束
```

点开即用。Ctrl+C / SIGTERM 时取消全部 WebSocket 连接，5 秒内优雅关闭。无信任记录的项目按不受信（同桌面端，没有终端可问）。

远程（不推荐）：`-addr 0.0.0.0:8443 -allow-remote -tls-cert c.pem -tls-key k.pem [-host my.lan]`。

## 三、路由

| 路径 | 作用 |
|---|---|
| `/ws`、`/api` | WebSocket。`/api` 是前端 `transport.ts` 在 `?token=` 下的缺省地址 |
| 其他 | 嵌入的前端静态文件（`GET` / `HEAD`） |

WebSocket 帧：请求 `{"id","cmd","args"}` → `App.Call` → 应答 `{"id","ok","result"|"error"}`；事件 `{"event": Envelope}`。每个连接独立订阅全部会话事件（`App.Events(ctx, bus.Filter{})`），慢订阅被总线断开后重订并推 `{"event":{"kind":"resync"}}`（同桌面端）。请求帧不合法回 `bad_request`。

## 四、安全

| 项 | 做法 |
|---|---|
| 监听 | 缺省 `127.0.0.1:0`。非回环地址拒绝启动，除非 `-allow-remote` 且给了 `-tls-cert` / `-tls-key` |
| 令牌 | 启动时 `crypto/rand` 32 字节，base64url 无填充（43 字符）；只打印到 stdout，不写文件、不进日志 |
| 校验 | 所有 HTTP 与 WebSocket 请求都要令牌：`?token=`、cookie `ybase_token` 或 `Authorization: Bearer`，`subtle.ConstantTimeCompare`；失败 401 |
| 令牌换 cookie | 带 `?token=<令牌>` 打开 `/` 时设 cookie（HttpOnly、SameSite=Strict，TLS 时 Secure），303 跳到 `/?token=`（空值，前端据此选 WebSocket 传输），令牌不留在地址栏 / 历史里 |
| Host | 只认 `127.0.0.1:端口`、`localhost:端口`、`[::1]:端口`（远程时另加监听 IP 与 `-host` 名），否则 403（防 DNS 重绑定） |
| Origin | WebSocket 必须带 `Origin`，且与 `Host` 同协议同 host:port，否则 403 |
| CORS | 不发任何 CORS 头 |
| 响应头 | 严格 CSP（`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self' ws://<Host>; object-src 'none'; base-uri 'none'; form-action 'none'; frame-src 'none'; frame-ancestors 'none'`），`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`、COOP / CORP same-origin |
| 拒绝体 | `appapi.Error{code:"unauthorized"}` 的 JSON |

## 五、约束值

| 约束 | 值 | 位置 |
|---|---|---|
| 单帧上限 | 4 MiB | `apps/server/server.go` `MaxFrame` |
| 每连接并发命令 | 16，满了暂停读帧 | `MaxInflight` |
| 单帧写超时 | 10 s，超时关闭连接 | `WriteTimeout` |
| 请求头读取超时 / 头大小 | 10 s / 64 KiB | `apps/server/main.go` |

均不影响会话内容，写死为常量。

## 六、实现与测试

- `apps/server/server.go`：`NewToken`、`LoopbackHosts`、`Config`、`Server.ServeHTTP`（Host → 安全头 → `/ws` `/api` 或静态）、`handleConn`、`events`。
- `apps/server/main.go`：参数、`checkAddr`、`allowedHosts`、TLS、信号关闭。
- WebSocket 库用已在 go.mod 的 `golang.org/x/net/websocket`，未新增依赖。
- `apps/server/server_test.go`：静态页令牌（缺失 / 错误 401，正确 303 + cookie，cookie 可取页面与 CSP 头）、Host 错误 403、WebSocket 令牌错误 401 / Origin 缺失或不同源 403、`hello` 往返、`session.open` + `session.send` 后收到 `turn_end` 与 `entry` 事件、`checkAddr`、令牌长度。

## 七、缺口

- 没有 auth 插件 / 多用户；远程只靠令牌 + TLS。
- 令牌每次启动重新生成，不支持固定令牌或写入只本人可读的文件。
- 前端未在真实浏览器里自动化走查（已用 Go 客户端对真进程验证 `hello` / `sessions.list`）。
- 未做 WebSocket ping 心跳；断线靠前端 1 秒重连 + `resync`。

# 插件包（外置插件第一档）

2026-11-01 第一版。设计来源：[00 - 总体架构](<../00 - 总体架构.md>) 第四节。

插件包是一个目录加一个清单文件 `ybase-plugin.toml`，把 MCP 服务、钩子、技能、提示词片段和内置插件的缺省配置打包在一起。放进目录、重启即用，不引入新协议，也不新增插件类型：包里的内容交给已有的内置插件（mcp、hooks、skills、prompt）去用。

## 一、位置与加载

| 级别 | 目录 | 加载条件 |
| --- | --- | --- |
| 用户级 | `<home>/plugins/<名字>/`，home = `$YBASE_HOME`，缺省 `~/.ybase` | 总是加载 |
| 项目级 | `<dir>/.ybase/plugins/<名字>/` | 只在项目受信时加载；未受信时跳过并提示“项目未受信，跳过项目插件包 …（ybase trust 可信任）” |

- 每个子目录一个包；以 `.` 开头的目录忽略；没有清单的目录跳过并提示。
- 同名包：项目级覆盖用户级，并提示。
- 顺序：用户级在前、项目级在后，各按名字排序。
- 项目里有 `.ybase/plugins/` 下的包，也算“项目有 .ybase 配置”，信任询问会照常触发。
- 清单写错（TOML 语法、未知字段、路径越界、文件不存在、配置项不认识等）启动直接报错，错误以 `插件包 <清单路径>：` 开头。

实现：`core/pkgs`（解析、校验、发现），`apps/internal/boot`（`LoadAll`：读包、叠 profile 层、把包列表作为服务 `service:packages` 注入装配）。各内置插件按 `?service:packages` 可选依赖读取，插件之间仍不互相 import。

## 二、清单格式

```toml
name = "demo"            # 必填，小写字母、数字、连字符；须与目录名相同
version = "0.1.0"
description = "示例包"

skills = "skills"        # 技能目录（相对包目录），格式同 ~/.ybase/skills：<名字>/SKILL.md 或 <名字>.md
prompt = ["prompt.md"]   # 提示词片段（相对包目录），按顺序拼成一个系统块

[[server]]               # MCP 服务，字段同 mcp.toml 的 [[server]]
name = "fs"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "${YBASE_PLUGIN_DIR}"]
trust = "readonly"       # ask / readonly / trusted
sandbox = ""             # 同 mcp.toml

[[hook]]                 # 钩子，字段同 hooks.toml 的 [[hook]]
event = "pre_tool_use"   # pre_tool_use / post_tool_use / stop
matcher = "shell"
command = "python ${YBASE_PLUGIN_DIR}/check.py"

[config.compact-basic]   # 内置插件的缺省配置
keep_ratio = 0.2
```

规则：

- 清单里的相对路径（`skills`、`prompt`、服务 `cwd`）以包目录为基准，不能是绝对路径，也不能用 `..` 跳出包目录。
- `${YBASE_PLUGIN_DIR}` 在服务的 command / args / env / cwd 和钩子 command 里替换为包目录的绝对路径；同名环境变量也会传给服务进程。服务 `cwd` 缺省为包目录。
- 服务名在全部包之间唯一，也不能和 mcp.toml 里的重名。
- `[config.<插件>]` 的插件必须已登记，键必须是该插件的配置项（解析时就按 Schema 校验，错误带清单路径）。

## 三、各部分怎么生效

| 内容 | 交给 | 效果 |
| --- | --- | --- |
| `[[server]]` | mcp | 追加在 mcp.toml 的服务之后，信任、沙箱、权限项规则与 mcp.toml 相同 |
| `[[hook]]` | hooks | 追加在用户与项目钩子之后，工作目录仍是项目目录 |
| `skills` | skills | 技能根目录追加在项目、用户目录之后；同名技能项目 / 用户优先 |
| `prompt` | prompt | 每个包一个系统块，顺序在基础提示词（0）之后、instructions（10）之前，来源记 `plugin:<名字>` |
| `[config.*]` | 装配 | 作为一层 profile 叠加 |

profile 层次（低 → 高）：内置 profile.toml < 插件包 `[config.*]` < `~/.ybase/profile.toml` < `<dir>/.ybase/profile.toml`（受信时）< `-profile`。项目级包和项目 profile 一样不能设 `models.base_url`、`models.catalog`、`store-sqlite.dir`，设了会被忽略并提示。

**包不替用户开插件。** mcp、hooks、skills 缺省关。包带了服务、钩子或技能而对应插件没开时，启动提示“插件包 X 的部分内容未生效：MCP 服务需开 mcp …”，用户自己在 profile.toml 里写 `[[plugin]] name = "mcp" enabled = true`。理由：mcp 与 hooks 会执行外部程序、访问网络，装一个目录就静默打开这些能力会越过用户的开关决定；提示足够让用户知道该开哪个。`[config.*]` 也因此只能改配置，不能写 `enabled`。

## 四、查看

- `ybase explain`：列出“插件包：”（名字、版本、级别、清单路径、内容摘要），由包设置的配置项来源显示为清单路径。
- `ybase plugin list`：只列信任状态、提示和插件包。
- `ybase plugin new <名字> [-project]`：在用户级（或项目级）目录生成骨架（清单 + `skills/` + `prompt.md`）。
- 对话中 `/plugins`：在插件开关后列出插件包。
- 应用接口层命令 `packages.list`：返回 `PackageInfo{name, version, description, scope, source, contents}` 数组。

# 13 - 桌面端与前端

桌面端 `kernel/apps/desktop`（Wails v3 v3.0.0）与共享前端 `kernel/web`（React + TypeScript + Vite）。前端只依赖应用接口层协议（[12 - 应用接口层](<12 - 应用接口层.md>)），api-server（WebSocket，[14 - 网页服务](<14 - 网页服务.md>)）原样复用。

## 一、结构

```
kernel/
  apps/internal/boot/      CLI 与桌面端共用的装配：信任、profile 叠加、Assemble、权限档位适配、Runtime / BuildApp
    trust.go assemble.go modes.go runtime.go profile.toml
  apps/ybase/              CLI（trust.go / assemble.go / appapi_adapt.go 改为 boot 的薄包装，行为不变）
  apps/desktop/
    main.go                参数解析 → boot.Start → BuildApp → Wails 应用（嵌入 web.Dist()）
    service.go             唯一绑定服务 Service.Call(cmd, args string) (string, error) + 事件转发
    service_test.go        用假模型驱动 Call 的测试；命令清单与 web/src/protocol.ts 一致性测试
  web/
    embed.go               package web：//go:embed all:dist，Dist() fs.FS
    package.json pnpm-lock.yaml tsconfig.json vite.config.ts index.html
    src/
      protocol.ts          协议类型（命令清单 COMMANDS、参数 / 结果、事件、会话条目）
      transport.ts         只导出 call(cmd, args) 与 onEvent(fn)；Wails / WebSocket 两种实现运行时选择
      App.tsx              外壳：会话列表、标签页（对话 / 权限 / 插件 / 统计）、提示、对话框
      Chat.tsx             流式对话、工具卡片、长会话分页、取消 / 插话 / 回退 / 压缩 / 分叉 / 最大步数
      Panels.tsx           会话列表（分页）、权限档位面板、插件面板（按 schema 生成表单）、统计
      Dialogs.tsx          人工确认、ask_user 提问、通用输入框
      Markdown.tsx         自写极简 Markdown → React 元素（不用 innerHTML）
      util.ts styles.css main.tsx
```

`core/runtime/deps_test.go` 放行 `web` 包（只被应用 import）；插件之间、core 与插件之间的依赖约束不变。

## 二、协议与传输

- 桌面端：前端动态 `import("/wails/runtime.js")`（Wails 资源服务器提供，不打包、不引 npm 依赖），`Call.ByName("main.Service.Call", cmd, JSON.stringify(args))`；结果是 JSON 文本。失败时 Go 端错误文本就是 `appapi.Error` 的 JSON（`{code, message, retry}`），前端解析成 `ApiError`。
- 事件：`Service.StartEvents` 订阅总线全部会话（`bus.Filter{}`），每条 `bus.Envelope` 以 Wails 事件 `ybase:event` 发出。慢订阅者被总线断开后自动重订，并先发一条 `kind = "resync"` 的信封，前端据此用 `session.entries` 重新拉取。
- WebSocket（api-server 用）：URL 带 `?ws=<地址>` 或 `?token=<令牌>`（同源 `/api`）时启用；请求帧 `{"id","cmd","args"}`，应答 `{"id","ok","result"|"error"}`，事件 `{"event": Envelope}`；断线发 `resync` 并 1 秒后重连。
- 命令名单一致性：`apps/desktop/service_test.go` 的 `TestProtocolCommands` 读 `web/src/protocol.ts` 的 `COMMANDS`，与 `appapi.Commands()` 比对。改命令时两边同步。

## 三、界面要点

- 会话列表：`sessions.list` 分页（游标 `next`，“更多”），“新会话”生成 `s-日期-时间-随机` 的 id。
- 对话：首屏 `session.open` + `session.entries{tail: 50}`；滚到顶部用 `from/to` 加载更早 50 条并保持视口；`text_delta`（后端已按 30ms 合批）累加到流式气泡，持久 `entry` 到达后以条目为准（同 idx 覆盖），`rewind{to}` 截断。运行中发送走 `session.steer`，回合恰好结束（`not_idle`）退回 `session.send`。
- 工具卡片：默认收起，展开显示参数与结果预览（超长截断，不显示全文）；无专用卡片时都用这个通用卡片。
- 人工确认：`human_requested` 弹框显示工具、原因、参数；允许一次 / 本会话内允许 / 拒绝，选“本会话”后显示 `session.confirm` 返回的生成规则。
- ask_user：`ask` 事件弹框，选项按钮 + 自由回答，`session.answer`。
- 权限：`mode.list`（放宽的档位显示放宽清单）、`mode.get`、`mode.set`（返回 `need_confirm` 时列出放宽项，确认后带 `confirm: true` 重试）、`mode.show` 取值表。
- 插件：`plugins.list`，按 `schema` 字段生成表单（bool → 复选框，数值 → 数字框，其余文本框，按 group 分组）；`plugins.set` 返回 `unsupported` 时表单转只读并显示原因。
- 统计：`session.stats`（命中率 < 0 显示“无数据”）。

## 四、构建与运行

```
cd kernel/web
pnpm install
pnpm build                     # 先 tsc --noEmit 再 vite build，产物 dist/
cd ..
go build -o %LOCALAPPDATA%\ybase\ybase-desktop.exe ./apps/desktop
%LOCALAPPDATA%\ybase\ybase-desktop.exe -dir <项目目录> [-profile x.toml] [-model m] [-mode ask] [-trust-project]
```

- 必须先构建前端：`web/embed.go` 嵌入 `dist/`，缺 dist 时 Go 编译失败。`dist/` 不入库（`.gitignore` 只留 `.keep`）。
- 其余参数：`-base`、`-sandbox`、`-mcp`、`-max-steps`、`-project-hooks`，含义同 CLI。
- 可执行文件放工作区外（`%LOCALAPPDATA%\ybase`），避免被工作区工具扫描或误提交。

## 五、安全选择

- 不开网络端口：Wails 资源与绑定都走 WebView2 内部通道。
- 严格 CSP（`index.html` meta）：`default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self' ws: wss:; object-src 'none'; base-uri 'none'; frame-src 'none'`，无 inline 脚本与 eval。
- Markdown 自写渲染，只产出 React 元素；原始 HTML 按文本显示；链接不可点击（只显示文字，悬停看地址）。
- 密钥只在后端（profile / 环境变量），前端拿不到。
- npm 依赖只有 react、react-dom 与构建工具，版本精确锁定（`pnpm-lock.yaml`）。
- 桌面端无终端：无信任记录的项目按不受信处理，需要时用 `-trust-project` 或 `ybase trust`。

## 六、缺口

- `plugins.set`、`artifact.get` 后端仍返回 unsupported，插件表单只读，大结果只能看预览。
- 长会话列表没有真正的虚拟滚动（分页加载 + 普通 DOM），上千条时可能变慢。
- 没有专用工具卡片（只有通用卡片）；Markdown 不支持表格。
- 前端没有自动化测试；Go 测试只覆盖绑定服务与命令清单。
- WebSocket 传输已用 Go 客户端对真实 `ybase-server` 进程验证 `hello` / `sessions.list`；尚未在真实浏览器里自动化走查。
- 没有用 wails3 CLI 打包（图标、安装包、签名）；直接 `go build`。

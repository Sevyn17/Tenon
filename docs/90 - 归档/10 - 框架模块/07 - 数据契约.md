## 3. 竞品对比

| 维度 | 本方案 | opencode | pi durable | DSH | Codex |
|---|---|---|---|---|---|
| 默认后端 | 见 D1 | SQLite（drizzle），`session`、`session_message`、`session_inbox`、`blob`、`blob_ref` 等表 | Memory / IndexedDB / SQLite / JSONL / Durable Object 多后端；README 明说 JSONL"整个历史也在内存里，长跑请用 SQLite" | 每会话一个仅追加 JSONL（默认 zstd 带校验和帧），格式 generation 不可变、撕裂尾部恢复 | rollout JSONL + 单独的 `state` crate（只看目录） |
| 原子提交 | checkpoint 一个事务 | 投影与事件同一事务；`event_sequence` 表按 aggregate 分配 seq | SQLite WAL + `synchronous=NORMAL`：进程崩溃不丢，断电可能丢最后一笔 | 写句柄 flush 是持久性屏障，检查点策略决定何时 flush | 未核实 |
| 收件表 | `session_inbox` 按 item id 幂等 | `session_inbox` 只存未消费项，同 id 重放幂等 | `submit` 带 `requestId` 幂等 | inbox 投影 | — |
| 内容寻址工件 | `blobs` + `blob_refs` | `blob` + `blob_ref` | — | 附件存储 | — |
| 格式演进 | `Entry.v` + R15 只读打开 | 存储事件解码处统一升级旧形状 | — | `session-format-v0→v4` 迁移包，读取时转换 | — |

可借鉴点：
1. **SQLite 是本地默认的共识**：opencode 直接用，pi 明确推荐长跑用 SQLite，Codex 也有独立 state 库。JSONL 适合"按会话一个文件、可人工查看"，但跨表原子提交（日志 + 头部 + 请求记录 + inbox 删除）在文件上要自己实现两阶段。
2. **WAL + `synchronous=NORMAL`**（pi）：进程崩溃安全、断电可能丢最后一笔；对本地 CLI 是合理取舍，作为默认值，可配置为 `FULL`。
3. **旧格式在解码处统一升级**（opencode、DSH）：与我们 `Entry.v` 一致；补一条规则"升级只发生在读取解码这一处"。
4. **导出可读文本**：DSH 的 `compression: none` 让日志可直接查看。我们用 SQLite 后，补一个 `ybase export <session>` 输出 JSONL，满足人工查看与轨迹导出。

## 4. 推荐方案

### 4.1 默认后端（D1）

本地默认 **单个 SQLite 文件**（`modernc.org/sqlite`，纯 Go，`agentrt/core/ybase-store` 已验证可用）：`<workdir>/.ybase/state.db`，四个存储插槽由同一个 `store-sqlite` 插件一次填满，checkpoint 是一个 SQLite 事务。BlobStore 默认是 `.ybase/blobs/<sha256>` 目录。

由此回改两处已定稿文档的措辞（语义不变）：
- session-host D2"inbox 存会话目录内" → 存 `session_inbox` 表；
- tool-hub K4"ToolResultStore 默认实现为会话目录内文件" → `tool_results` 表。

### 4.2 表结构（P0）

```sql
-- review-1（2026-10-28）修订：R1 请求记录结构化、R4 sync_seq、R5 session_shells、G1/G2 观测、会话形态、长会话
sessions(tenant, id PK, agent_id, agent_version, parent_id, origin, fork_upto,   -- origin: new / fork / side / subagent / member
         status, run_state, title, preview,
         header TEXT, shell_hash, log_len, next_sync_seq, updated_at, deleted_at)
session_shells(hash PK, body TEXT, created_at)             -- R5：system / tools / params 外壳，内容寻址（取代 session_configs）
session_entries(tenant, session_id, idx, id, turn, kind, summary, body TEXT, at, sync_seq,
                PRIMARY KEY(tenant, session_id, idx))      -- summary：宿主生成的一行预览；INDEX(session_id, turn)、(session_id, sync_seq)
session_entries_archive(tenant, session_id, idx, id, body TEXT, truncated_at, rewind_seq)
session_requests(tenant, session_id, request_id, shell_hash, prefix_base, prefix_end, compaction_view TEXT,
                 suffix TEXT, final_hash, composition TEXT, created_at,
                 PRIMARY KEY(tenant, session_id, request_id))  -- R1；composition：各类上下文 token 估算（G1）
session_inbox(tenant, session_id, item_id, kind, input TEXT, trust, created_at,
              PRIMARY KEY(tenant, session_id, item_id))
tool_results(tenant, session_id, call_id, status, kind, args_hash, decision,
             delivered TEXT, output TEXT, deadline, token_hash, created_at,
             PRIMARY KEY(tenant, session_id, call_id))
trace_spans(tenant, session_id, span_id PK, parent_span, kind, name, started_at, ended_at, status, attrs TEXT)
                                                           -- G2：turn / step / attempt / tool / layer / hook / compact；INDEX(session_id, started_at)
blobs(sha256 PK, size, mime, created_at, touched_at)
blob_refs(tenant, session_id, sha256, PRIMARY KEY(tenant, session_id, sha256))
definitions(tenant, kind, id, version, body TEXT, created_at, PRIMARY KEY(tenant, kind, id, version))
schema_versions(owner PK, version)
```

`tool_results` 的四处修正（tool-hub D4）：状态列统一叫 `status`（started / pending / delivered / done）；主键带 `session_id`；新增 `args_hash`（批准时锁定参数）；`delivered`（挂起结果已送达、未交内核）与 `output`（已完成）分列。

### 4.3 事务边界

| 操作 | 一个事务内写 |
|---|---|
| checkpoint | `session_entries` 追加（分配 `sync_seq`）/ 截断移入归档 + `sessions.header` 条件写（`WHERE log_len = 期望值`）+ 本次的 `session_requests` 行 + 被消费 inbox 项删除 + `session_shells`（新哈希时）+ 未提交的 `trace_spans` |
| Send / Note 准入 | `session_inbox` 插入（`ON CONFLICT DO NOTHING`，首次准入胜出） |
| 工具状态推进 | `tool_results` 单行条件更新 |
| 删除会话 | 置墓碑；随后清理（含各插件 `OnSessionDelete` 回调），完成后删墓碑 |

请求记录不再整体进 BlobStore（review-1 R1）：外壳进 `session_shells`，前缀只记区间，后缀与组成统计随行存。工件仍"先上传、再写引用"。

### 4.4 可靠读取（event-bus D1 的落点）

`Follow` 依赖存储提供按会话、按 `idx` 递增读取；每条事件的 `seq` 是会话级单调的 `sync_seq`（review-1 R4：撤销后不复用，`Follow(after)` 断点可靠）。轨迹导出 = `session_entries` ∪ `session_entries_archive` ∪ `session_requests` ∪ `tool_results` 的投影，不另存一份。

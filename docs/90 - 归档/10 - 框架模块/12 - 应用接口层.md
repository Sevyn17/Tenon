# 应用接口层（appapi）协议

> 状态：已实现（`kernel/core/appapi`，protocol 1）；CLI 已改走它的进程装配后半段、会话构造、事件流与 rewind / compact。`plugins.set`、`artifact.get` 暂返回 `unsupported`（见 §八）。CLI、桌面端（Wails v3）、api-server 都只调这一层，不直接碰 host / bus / store / 插件包。

## 一、位置与依赖

- 包：`kernel/core/appapi`。只依赖 core 包（host、bus、store/sqlite、session、plugin、runtime、toolhub）。
- 权限、压缩等插件能力经接口取用：appapi 定义小接口（如 `Modes`：列档位、切档位、mode show、会话规则），插件提供的服务对象实现它，应用从 `Asm.Value(...)` 取出后注入。appapi 不 import 任何插件包（`runtime/deps_test.go` 规则不变）。
- 一个进程一个 `appapi.App`：持有装配结果、Host、Bus、DB。实际做法：装配（信任判定、profile、插件 Start）仍由应用完成，应用把装好的部件交给 `appapi.New(Options{Host, Bus, DB, Builder, Model, Workdir, Trusted, Modes, Compactor, Profile, UI})`。`New` 负责：`DB.OnCommit` 接到 `Bus.Publish`（Follow 的实时部分）；用 `Builder` 设置 `Host.New` / `Host.Child`（顶层 / 子会话），并在 Builder 钩子上并入流式事件；包装 `Host.Hooks`（回合开始发档位变化 `notice`，回合结束先发完积压正文）；订阅 `human_requested` 记下待确认调用。应用自己的 `BeforeTurn` / `AfterTurn` 须在 `New` 之前设置。
- 插件适配接口：`Modes`（`List / Get / Set(session, mode, confirm) / Show / Notice / SessionRules / SessionAllow / AllowForSession / ExtKeys`）、`Compactor`（`Plan / At`，compact-basic 的 `*Compactor` 直接满足）。CLI 的适配在 `apps/ybase/appapi_adapt.go`（`permModes` 包 `*permission.Sessions`）。

## 二、传输形态

所有端看到的是同一套“命令 + 事件”：

| 端 | 命令 | 事件 |
|---|---|---|
| CLI | 进程内直接调用 Go 方法 | `App.Events(ctx, filter)` 返回 channel |
| 桌面端 | Wails 绑定（同进程，不开端口） | Wails 事件推送 |
| api-server | WebSocket 上的 JSON 帧 `{"id","cmd","args"}` → `{"id","ok","result"|"error"}` | 同一连接推 `{"event": Envelope}` |

前端传输层只有 `call(cmd, args)` 与 `onEvent(fn)` 两个函数，两端共用界面代码。TS 类型从 Go 类型生成，不手写。

## 三、命令

参数和返回都是 JSON 可序列化的结构体。会话类命令都带 `session`。

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `hello` | `{client, version}` | `{protocol, server, model, workdir, trusted}` | 握手，协商协议版本 |
| `sessions.list` | `{cursor?, limit?}` | `{items:[{id,title,preview,run_state,updated_at,origin,parent}], next}` | 按 updated_at 倒序分页 |
| `session.open` | `{session}` | `{id, run_state, log_len, base, mode}` | 不存在则新建 |
| `session.entries` | `{session, from?, to?, tail?}` | `{entries:[{idx,seq,entry}], base, log_len}` | 长会话分页；`tail` 取最近 n 条 |
| `session.send` | `{session, text, item_id?}` | `{}` | 空闲开回合，回合中等同排队 |
| `session.steer` | `{session, text}` | `{}` | 插话 |
| `session.cancel` | `{session}` | `{}` | |
| `session.confirm` | `{session, call_id, decision: "once"|"session"|"deny"}` | `{rules?}` | `session` = 本次会话内都允许，返回生成的规则 |
| `session.answer` | `{ask_id, text}` | `{}` | 回答 ask_user |
| `session.rewind` | `{session, turns}` | `{}` | 空闲时 |
| `session.compact` | `{session}` | `{summary}` | 空闲时 |
| `session.fork` | `{session, to}` | `{id}` | |
| `session.stats` | `{session}` | `Stats` | 用量、命中率、上下文组成 |
| `session.max_steps` | `{session, n?}` | `{n}` | |
| `mode.list` | `{}` | `[{id,label,builtin,project,widened}]` | |

| `mode.show` | `{mode}` | `[{item,title,value,source,bounded}]` | |

## 四、事件

信封沿用 `bus.Envelope{v, seq, at, session, kind, data}`。

- **持久事件**（`seq > 0`）：条目追加 `entry`（`{idx, entry}`）、回退 `rewind`（`{to}`）。可用 `Follow(after=seq)` 补齐，断线后按最后收到的 seq 续订，不漏不重。需要 sqlite 实现 `bus.Source.Replay`（`session_entries.sync_seq` 已有索引）。
- **易失事件**（`seq = 0`）：`turn_start`、`turn_end{reason}`、`turn_denied`、`text_delta{text}`（16–50 ms 批量）、`text_reset`、`tool_call{call_id,name,args}`、`tool_result{call_id,preview,error}`、`human_requested{call_id,tool,reason,args,session_rules,blocked}`、`ask{ask_id,question,options}`、`notice{text}`（如档位文件更新）。流式文本目前只走 `agent.Hooks`，由 appapi 转成易失事件。
- 规则：界面以持久事件为准，易失事件只用于“正在进行”的显示；收到 `entry` 后丢弃对应的增量。

## 五、错误

返回 `{code, message, retry}`：

| code | 含义 |
|---|---|
| `bad_request` | 参数不合法 |
| `not_found` | 会话 / 档位 / 工件不存在 |
| `busy` | 命令队列满（host.ErrBusy） |
| `not_idle` | 需空闲时使用的命令在回合中调用 |
| `conflict` | 会话被另一进程写入（sqlite.ErrConflict），本端转只读 |
| `unauthorized` | api-server 令牌 / Origin / Host 检查失败 |
| `unsupported` | 协议版本或能力不支持 |
| `internal` | 其他 |

## 六、版本

- `protocol` 为整数，当前 1。同版本只加字段和命令；改语义或删字段升版本。
- 客户端在 `hello` 里给出自己的版本；服务端不支持时返回 `unsupported`。
- 事件信封自身的 `v` 沿用 bus.Version。

## 七、安全

- 桌面端不开端口。
- api-server 缺省只监听 127.0.0.1，启动时生成随机令牌（打印到终端 / 写入只本人可读的文件），检查 `Origin` 与 `Host`，不允许 CORS 通配。
- 模型密钥不经过任何命令或事件。

## 八、实现说明（与上文的差异）

- 通用分发：`App.Call(ctx, cmd, args json.RawMessage) (any, error)`，桌面端与 api-server 共用；未知命令返回 `unsupported`，参数解析失败（含未知字段）返回 `bad_request`。`appapi.Commands()` 列出全部命令名。每条命令也有同名 Go 方法（如 `App.Send(ctx, SendArgs)`），CLI 直接调。
- 错误：`*appapi.Error{Code, Message, Retry}`，`AsError(err)` 把下层错误映射到码：`host.ErrBusy` → `busy`（retry）、`sqlite.ErrConflict` → `conflict`、`sqlite.ErrNotFound` / `host.ErrClosed` → `not_found`、`session.ErrState` 系 → `not_idle`，其余 `internal`。新增码 `need_confirm`：`mode.set` 切到放宽权限且未确认过的项目档位时返回，带 `confirm: true` 重发。
- 命令参数 / 返回的增补：`sessions.list` 多 `all`（含子会话），`cursor` 为上一页的 `next`（updated_at）；`session.entries` 行为 `{idx, entry}`（不带 seq，增量同步用 Follow）；`session.confirm` 可带 `tool` / `args`，缺省取 App 记下的 `human_requested` 内容；`session.rewind` 返回 `{to}`（`turns` 缺省 1）；`session.compact` 返回 `{summary, upto, tokens_before, tokens_after}`；`session.fork` 可带 `upto`、`origin`（缺省 `fork`）。
- 会话规则持久化与档位持久化都异步写顶层会话头（回合中同步 `SetExt` 会与正在等的确认死锁），失败发 `notice`（`[会话规则未能保存：…]` / `[档位未能保存：…]`）。
- `UI`：`appapi.NewUI(bus)` 实现 `runtime.UI`，`Print` / `Warn` 发 `notice`，`Ask` 发 `ask{ask_id, question, options}` 并等 `session.answer`。CLI 仍用终端自己的 UI。
- `text_delta` 按 30 ms 批量（`BatchInterval`），`tool_result.preview` 截 300 字（`PreviewLen`）。
- 未实现：`plugins.set`（返回 `unsupported`“请编辑 profile.toml 后重启”）、`artifact.get`（`unsupported`）、`unauthorized` 码由 api-server（`apps/server`，见 [14 - 网页服务](<14 - 网页服务.md>)）在令牌 / Host / Origin 检查失败时返回（HTTP 401 / 403 的响应体）。`hello` 的 `version` 大于 `Protocol` 时返回 `unsupported`。

# 内核 / 插件分界与插件开关方案（已执行，2026-10-31）

依据：kernel/docs/03 - 约束清单.md“内核与插件的分界原则”（用户定，2026-10-31）。判断标准只有一条：**影响会话内容的做成插件或配置项，不影响会话内容的系统优化可以直接做。**

## 1. 内核是什么

内核只提供机制，保证这些机制本身做好：可靠、可恢复、可观测。

| 包 | 职责 | 会进入会话的内容 |
| --- | --- | --- |
| session、reqlog | 会话状态机、日志、检查点、请求记录、rewind / fork | 无（只记录） |
| toolhub | 调用栈、层链、幂等记录、确认挂起、结果转存、取消 | 机制必需的状态文本（见 §1.1） |
| modelhub | 调度、重试、熔断、协议适配器（openai-chat / anthropic / responses） | 无 |
| bus、store/sqlite、host、agent | 事件、存储、宿主命令、驱动循环 | 无 |
| plugin、runtime | 装配、点位、服务注入、会话构造 | 无 |

内核里会影响会话内容的**参数**（单步工具调用数 16、单结果 1 MiB、转存阈值 32 KiB / 1000 行、确认期限 24 h、工具缺省超时 120 s、步数上限）不再写死，改为 profile 的 `[kernel]` 配置节，缺省值不变，统一登记在 ../03 - 约束清单.md。

### 1.1 内核生成文本

“工具调用在进程中断时已开始执行，结果未知”“用户拒绝了这次调用”“工具不存在”“批准记录与当前参数不一致”“结果已转存”等，只限机制必需的错误与状态说明。全部集中到 toolhub 的一个文件里，并登记在 ../03 - 约束清单.md 的“内核生成文本”一节。新增这类文本要先登记。

## 2. 插件是什么

凡是会改变模型所见内容的东西：系统提示词、工具及其说明、对工具结果的改写、注入的消息与指令，以及压缩。

### 2.1 缺省开关

| 插件 | 缺省 | 理由 |
| --- | --- | --- |
| store-sqlite（强制）、models | 开 | 没有就不能运行 |
| prompt（新，系统提示词） | 开 | 当前写死在 cmd/ybase/main.go，迁出；文本可由配置或文件覆盖 |
| compact-basic | 开 | 长会话没有它无法继续；阈值与比例改为配置项 |
| fs、shell、todo（含 ask_user） | 开 | 编程智能体的基本工具 |
| permission、sandbox | 开 | 安全底线，档位缺省“工作区自动”（用户定） |
| instructions（AGENTS.md） | 开（用户定，2026-10-31） | 插件；注入项目约定，并在读文件结果后追加子目录指令，可在 profile 里关 |
| skills | 关 | 注入技能目录 |
| redact | 关 | 改写工具结果，与磁盘内容不一致 |
| hooks、mcp | 关 | 会执行用户配置的外部程序 |
| web、subagent、workgroup、code-mode | 关 | 扩展能力，会增加工具、改变行为 |

### 2.2 插件内部原先写死的行为改为配置项

| 插件 | 配置项 | 缺省 |
| --- | --- | --- |
| shell | `strip_ansi`（去颜色码）、`deny_hint`（被拒时追加提示）、`intro`（工具说明，含 PowerShell 语法提醒） | true / true / 内置文本 |
| prompt | `text` 或 `file` | 内置文本 |
| compact-basic | `headroom`、`keep_ratio` | 16384 / 0.16 |
| redact | `patterns`（启用哪几类识别），写回保护（编辑或写文件的参数含占位符时拒绝） | 只启用高置信度几类 / 开 |

不影响会话内容的优化逐项判断：哈希规范化、死锁修复这类纯缺陷修复不设开关；沙箱缓存目录（GOCACHE 等）、超时、并发数这类有取值的，做成所在插件或 `[kernel]` 的配置项，缺省值不变并登记。

## 3. 开关机制

1. **profile 分层叠加**：内置 < 用户 `~/.ybase/profile.toml` < 项目 `<dir>/.ybase/profile.toml`（< `-profile` 指定的文件）。同名插件后者覆盖，`config` 按键合并。写 `enabled = true` 开启，`enabled = false` 关闭（兼容现有的 `disabled`）。强制插件不能关。
2. **可用插件与已开启插件分开**：插件登记时在 Meta 里声明 `Default`（缺省是否开启）。内置 profile 只写配置，不再罗列插件。
3. **项目信任（参照 Codex，2026-10-31 调研）**：
   - 参照：Codex 在用户级 `~/.codex/config.toml` 按目录记 `[projects."<路径>"] trust_level = "trusted" | "untrusted"`；未信任或未决定时**整个跳过**项目级 `.codex/` 层（项目配置、hooks、rules），用户级配置照常加载，并给出启动提示“要加载项目配置、hooks 与执行策略，请把 <路径> 设为受信项目”；TUI 首次进入目录时询问“Trust this folder?…Your trust decision will be saved.”，决定写回用户配置；信任键优先取 git 仓库根。即使受信，项目配置里也有一组键被忽略（端点 base_url、model_provider、notify、profile、otel 等），并提示。Claude Code 同样在 `~/.claude.json` 按项目路径记 `hasTrustDialogAccepted`，项目 `.mcp.json` 里的服务器还要单独批准。
   - 本方案照做：用户级 `~/.ybase/trust.toml` 记 `[projects."<路径>"] trust = "trusted" | "untrusted"`，键取 git 仓库根（没有则取工作目录），子目录继承。
   - 未信任 / 未决定：项目级 `<dir>/.ybase/` 下的 profile、permissions.toml、hooks.toml、mcp.toml 全部不加载（AGENTS.md 属于项目内容、不执行程序，照常由 instructions 读取），启动提示原因与授权办法。
   - 首次在有 `.ybase/` 项目配置的目录启动时，CLI 询问“信任此目录？项目配置可以开启插件、执行钩子与 MCP 程序”，选择写回 trust.toml；`-trust-project` 本次视为受信（不写回），`-project-hooks` 保留为它的别名。
   - 受信项目的配置也不能改：模型端点与凭据（models.base_url、密钥来源）、store-sqlite 目录；这些键被忽略并提示。
   - `ybase trust [--untrust] [目录]` 子命令手动设置；`explain` 显示当前目录的信任状态。
4. **影响声明**：Meta 增加 `Effects`，取值为 `system_prompt`、`tools`、`rewrite_result`、`exec`、`network`。`ybase explain` 列出所有可用插件的开关状态、来源文件和影响；启动横幅列出已开启的 `rewrite_result` 类插件，例如“脱敏已开启：工具结果中的密钥会被替换”。
5. **会话记录装配快照**：会话头部 Ext 记录开启的插件与配置哈希。恢复会话时发现与上次不同就提示，因为工具集或提示词变了，模型行为和缓存都会受影响。
6. **生效时机**：开关在启动时生效，回合中不热切换，因为切换会改变工具集、破坏缓存。会话内 `/plugins` 只用于查看。
7. **命令行参数**：`-mode`、`-sandbox`、`-mcp` 等继续作为对应插件的配置覆盖，行为不变。

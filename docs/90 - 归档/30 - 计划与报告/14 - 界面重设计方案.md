# 14 界面重设计方案

> 状态：**已完成（2026-11-08）**，实际分六批做完（见第七节）；第八节三个待定项已定。范围：`web/` 的 shell 与 ui 两层（工作台布局、会话、输入区、面板、视觉规范）。协议与后端不在本方案内，需要的后端配合单独列出。2026-11-10 从计划/移入归档并重编号（原计划/06）。

## 一、现状问题

来自 2026-11-08 桌面端试用的截图与反馈（"太丑""布局不合理""交互不够好"）。第一步已修的缺陷（会话标题显示 ID、首页没有输入框、面板标签截断、面板默认打开）不再列。

| # | 问题 | 原因 |
|---|---|---|
| 1 | 三栏 + 竖栏同时出现，对话区只剩一半宽 | 布局按"工作台"设计，把所有能力都摆出来 |
| 2 | 右侧图标竖栏与面板顶部标签重复，竖栏上的蓝色竖条看不懂 | 两套入口指向同一组面板；蓝条表示"面板有内容"，没有说明 |
| 3 | 技术细节直接给用户看：窗口标题是完整路径，左下角 `local` / `cli/deepseek-chat`，每条回复下一行 tokens 与缓存率，输入框里的 `2.0k` | 调试信息没有分级，全部放在一级界面 |
| 4 | 权限档位在顶栏和输入框各显示一次 | 两处各自实现 |
| 5 | 一条回复下面堆了四层：正文、操作按钮、统计行、追问建议 | 每个功能各自往消息下面加东西，没有统一的"回复页脚" |
| 6 | 正文排版是默认值：13px 正文、列表行距挤、标题字重过重、正文没有最大宽度 | 令牌按工具类桌面应用（Codex）取值，不适合大段阅读 |
| 7 | 侧栏的"全部 / 运行中 / 待处理"筛选占显眼位置，用处小 | 本地单人使用时同时运行的会话很少 |
| 8 | 首页空、冷：只有一句问候和三个按钮 | 没有设计首页 |

## 二、原则

1. **对话是主角**。缺省只有两栏：侧栏 + 对话。其他东西（面板、统计、档位细节）按需出现，用完消失。
2. **一件事只有一个入口**。同一个功能不在两处各放一个按钮。
3. **信息分三级**：
   - 一级（始终可见）：对话内容、输入框、当前会话标题、正在运行 / 需要你处理的状态。
   - 二级（悬停或展开可见）：消息操作、工具调用详情、模型名、档位名。
   - 三级（主动打开才可见）：tokens、缓存、每回合统计、工作目录全路径、连接身份。放进"用量"面板或设置页。
4. **为阅读而排版**。正文 15px、行高 1.7、最大宽度 720px 居中；代码与工具输出等宽、更小一号。
5. **安静的界面**。少用边框分隔，多用留白和底色深浅；强调色只用于"需要你操作"和主按钮。
6. **有自己的样子**。Claude 桌面端、ChatGPT 桌面端当体验质量的参照（层次、留白、响应速度），外观按 Tenon 自己的规范定，不照搬配色、字体与布局细节。

## 三、布局

### 3.1 窗口结构

```
┌──────────────┬──────────────────────────────────────────┐
│ 侧栏 260px   │ 顶栏：会话标题 ·····················  ⋯ ⊞ │
│              ├──────────────────────────────────────────┤
│ ＋ 新会话    │                                          │
│ 🔍 搜索      │          对话（最大 720px，居中）         │
│              │                                          │
│ 置顶         │                                          │
│  · 会话 A    │                                          │
│ 今天         │                                          │
│  · 会话 B ●  │       ┌──────────────────────────┐       │
│  · 会话 C    │       │ 输入框                    │       │
│ 更早         │       │ ＋ 📎        模型 ▾    ↑ │       │
│              │       └──────────────────────────┘       │
│ ─────────    │                                          │
│ ⚙ 设置       │                                          │
└──────────────┴──────────────────────────────────────────┘
```

- **去掉右侧图标竖栏**。面板入口收到顶栏右侧的一个"面板"按钮（⊞，`Mod+\`），点开是面板菜单：任务、改动、子会话、用量、工件。面板里有内容时按钮上显示一个小圆点（替代竖栏蓝条）。
- **面板打开时**从右侧滑入，缺省 380px，可拖宽；对话区相应收窄，但对话列宽保持 720px 上限居中。窗口宽度不足 1100px 时面板改为覆盖在对话上（抽屉）。
- **面板顶部标签**保留，只在同时开了两个以上面板时出现；只开一个面板时顶部只有标题和关闭按钮。
- **底部停靠区**（终端类面板）保留现有机制，缺省关闭，不放入口按钮到一级界面，从面板菜单打开。
- **窗口标题**只显示 `Tenon`；当前工作目录放进侧栏底部的项目名（只显示目录名，悬停看全路径）。

### 3.2 侧栏

- 顶部：品牌名 + 收起按钮；下面是"新会话"（主操作，`Mod+N`）和"搜索"（`Mod+K`，打开命令面板的会话搜索）。
- 列表按"置顶 / 今天 / 昨天 / 本周 / 更早"分组；每行只显示标题，一行截断。
  - 运行中：行首一个转动的小圈；需要你处理（有待确认的交互）：行首强调色圆点。不再用独立的筛选标签页。
  - 悬停时行尾出现"⋯"菜单（重命名、置顶、删除）；右键同样的菜单。
  - 当前会话用底色高亮，不加左边框。
- 底部：项目（工作目录名）+ 设置齿轮。去掉 `local` / 模型名的身份块；连接身份移到设置页"关于"。

### 3.3 顶栏

- 左：会话标题（点击可直接改名，回车保存）。
- 右：面板按钮 ⊞、更多菜单 ⋯（导出、复制会话链接、删除）。
- 去掉顶栏上的档位徽章（档位只在输入框里显示一次，见第五节）。
- 运行中不在顶栏重复显示状态（输入框里已有）。

## 四、对话

### 4.1 消息

- **用户消息**：右对齐的气泡，最大宽度 80%，浅底色，圆角 18px；悬停时下方出现"复制、编辑重发"。
- **助手消息**：不加气泡，正文直接排在对话列里，左对齐。
- **回复页脚**（统一一行，取代现在的四层）：
  - 悬停或最后一条回复时显示：复制、重试、👍 👎、⋯（⋯ 里有"查看用量""从这里分叉"）。
  - 不显示 tokens / 缓存 / 耗时。耗时与用量进"用量"面板，⋯ 里能跳过去。
- **追问建议**：只在最后一条回复下显示，最多 3 条，做成输入框上方的一排轻量文字按钮（不是描边卡片）；用户开始输入就收起。

### 4.2 工具调用与思考

采用**三级折叠**，默认只显示摘要行，逐级展开到列表、再到详情：

**级别 0（默认）**：一行摘要
- 格式：`[状态图标] 读了 3 个文件，运行了 1 条命令`
- 状态图标：✓ 成功（中性色）/ ⚠ 警告（警告色）/ ⨯ 失败（危险色）/ ⟳ 运行中（转动）
- 统计各类工具的调用次数，生成自然语言摘要
- 点击摘要行展开到级别 1

**级别 1**：工具列表
- 逐条显示：`[图标] 工具名 · 一句话说明`（如 `📄 Read · src/App.tsx`）
- 运行中的工具显示最后几行输出（最多 3 行）
- 点击某条工具展开到级别 2；点击摘要行或列表外收回级别 0

**级别 2**：单个工具详情
- 显示完整参数（JSON 可折叠）和完整输出（代码块，可复制）
- 顶部面包屑：`步骤 2 / 5 · Read`，可切换到其他工具
- 点击返回或详情外收回级别 1

**智能展开规则**：
- 运行中的工具：自动展开到级别 1，显示进度与最后几行输出；完成后如果所有工具都成功，自动收回级别 0
- 出错的工具：保持级别 1 展开，失败的那条用警告色高亮
- 用户手动展开的状态：在切换到其他消息或刷新前保持

**思考内容**（如果模型给）：
- 折叠成一行 `💭 思考了 8 秒`，点开显示全文（灰色背景，斜体）
- 用户可在设置 › 外观中选择"推理默认展开"

### 4.3 交互卡片（确认 / 提问 / 选择 / 表单）

- 需要你处理的卡片固定在输入框正上方，取代输入框的位置（现有 takeover 机制保留），用强调色细边框；不阻塞的卡片留在消息流里。
- 确认卡片的标题改成人话："要运行这条命令吗？" + 命令本身（等宽），下面是"允许 / 本会话都允许 / 拒绝"。原始参数 JSON 收进"详情"。

### 4.4 首页（没有选中会话）

- 输入框放在页面垂直居中略偏上的位置，宽度 640px；上方一句问候（品牌可配），下方 3–4 个示例作为轻量文字按钮。
- 侧栏有最近会话时，首页不再重复列出。
- 首次发送后输入框以动画移到底部，进入会话视图。

## 五、输入框

- 一个圆角 20px 的容器，底色比页面浅一级，无边框，聚焦时出现 1px 边框。
- 第一行：多行输入区（最少 1 行、最多 12 行，超出滚动）。
- 第二行工具条：
  - 左：`＋`（附件、命令、提及，合并成一个菜单）。
  - 右：权限档位（只显示图标 + 简称，如"🛡 工作区"，点开切换）、模型选择（只显示短名）、发送按钮。
  - 去掉上下文用量数字（`2.0k`）；上下文接近上限（超过 80%）时才在发送按钮旁出现一个小环提示，点开看用量面板。
- 运行中：发送按钮变成停止按钮；输入框仍可输入（插话），占位文字改为"补充说明，回合结束前送达"。

## 六、视觉规范

在 `ui/tokens.css` 上调整，令牌名保持不变，只改取值与补少量新令牌，组件改用新令牌。

### 6.1 字体与字号

| 用途 | 现在 | 改为 |
|---|---|---|
| 界面文字 | 13px | 14px |
| 次要文字（时间、说明） | 12px | 13px |
| 对话正文 | 13px / 1.65 | 15px / 1.7 |
| 代码与工具输出 | 继承 | 13px 等宽 / 1.55 |
| 正文标题 h1–h3 | 粗体 | 600 字重；17 / 16 / 15px，上间距大于下间距 |
| 首页问候 | 28px 粗体 | 26px，500 字重 |

- 字体栈调整为先中文后西文的系统字体：`"Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei UI", sans-serif`；等宽 `"Cascadia Code", "JetBrains Mono", Consolas, monospace`。
- 列表：项间距 4px，缩进 20px；段落间距 0.75em。

### 6.2 颜色

- 中性色从纯灰改为略带暖色的灰（取木色的方向，呼应"榫"），浅色主题的页面底色为极浅的暖白，侧栏比页面深一级。
- 强调色从蓝改为一个品牌色（候选：靛青或松绿，出两版色板让你选），只用于主按钮、需要处理的状态、链接。
- 状态色（成功、警告、危险）保持，降低饱和度。
- 深色主题同步调整；缺省主题跟随系统。

### 6.3 间距、圆角、阴影

- 对话列：消息之间 24px，同一回合内的工具摘要与正文之间 8px。
- 圆角：控件 8px、卡片 12px、输入框 20px、用户气泡 18px。
- 阴影只用于浮层（菜单、对话框、抽屉面板）；平铺区域一律不用阴影和边框，靠底色区分。

### 6.4 动效

- 面板滑入、菜单展开 150ms；流式文字不做逐字动画；运行中的转圈用 CSS 动画，`prefers-reduced-motion` 时停用（已有）。

## 八、待定项的结论

1. 强调色：四套都保留，可在设置里切换，缺省靛青（`web/src/shell/prefs.ts`）。
2. 缺省主题：跟随系统。
3. 工具调用：缺省折叠成摘要。一回合多于一个工具、且都成功时，结束后自动收回成一行摘要；出错时保持展开（`ui/conversation/messages.tsx` 的 `autoCollapse`）。推理内容缺省折叠，设置 › 外观"推理默认展开"可改。

## 二、设计缺口（不需要拍板，按建议补）

**存储与事务**

- 待回复表建错了地方：现有 `session_requests` 是模型请求记录表（`kernel/core/store/sqlite/schema.go:44-49`，存 shell_hash、prefix、composition），不是待回复表。另建 `session_pending(corr, session, expect_from, deadline, used_at, principal, caps, origin)`；后三列补上原请求那一轮的权限主体，回信轮据此沿用 `caps`（02:73、11:85 缺）。`session_requests` 归到追踪数据。D3 本身不变。
- 会话键：不带 key 存 NULL，部分唯一索引只覆盖 key 非空；常驻靠固定 id 保证唯一，删掉"常驻是 key 为空的特例"的说法（13:51–53、11:46/49、05:129、B19）。
- 外发信封、`corr` 签发、检查点不在同一事务，崩溃后会重发或漏发。加**发件箱**：一轮内产生的信封、待回复登记和检查点同一事务写入，之后由投递器搬运（02:123、05:59/80）。
- 按 key 查或建、跨会话投递超出单会话分区事务：`Store` 加 `FindOrCreateSession` 原语。
- 注入 key 的已发哈希单独存表，Rewind / Fork 后与历史对不上，`Store` 里也没有：改为从历史里的 `status` 条目推导，不另建表（05:130、12:99/110）。
- `Collection`：`Registrar.Collection` 返回句柄；`Get` / `Query` / `Delete` 带分区参数；定义 `Tx`、`Migration` 类型（04:40、05:89–100）。

**运行时**

- Fork / Rewind 和待回复表、信箱、子会话的交互没写：Fork 不复制待回复和信箱，子会话不跟随；Rewind 到某条目时，作废其后签发的 `corr`（02:47）。
- 休眠 / 唤醒"先写后查"在快照隔离下不保证：加周期性兜底扫描"有待处理信封但休眠"的会话（02:60）。
- 只有 `context` 信封排队时会话应能休眠，`context` 不触发唤醒（02:60、13:63）。
- 插入消息的确认时机：和本次调模型前的检查点同一事务确认（代码已是如此，文档补上，02:120）。
- 关闭会话时：未用的 `corr` 作废并给请求方回错，子会话按所属树策略处理，信箱剩余信封拒收（02:45）。
- 状态机补"预算挂起""已中断"，和 11:45、13:35 对齐。
- 压缩后重建：AGENTS.md、技能目录这类快照另写一条 L2 条目，不走 2k 的状态更新总预算，否则会被截断或丢掉（12:105/110）。
- `<msg from at>` 标签里的正文要转义，否则可伪造发送者（13:76）。

**安全**

- 联系守卫三处写法不同（13:36、08:27、02:51），统一到 08，并按 D4：`session:` 缺省只限同一所属树、创建者和 `corr` 回信；13:36 把 `human:` 的范围（触发者、成员）套到 `session:` 上，删掉。

- `hop` 规则补全：哪些投递加一跳、`reply` 不加、上限和截断后的回错（08:71）。
- `origin=scheduler` 不在枚举里（13:140），改为 `external`。
- `limit:"intersect"` 字段每轮按触发者重新求交（06:48/64）。

**接口**

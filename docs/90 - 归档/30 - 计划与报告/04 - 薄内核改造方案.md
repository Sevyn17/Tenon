# 薄内核改造方案（已执行，2026-10-31）

日期：2026-10-30。目标：内核只留机制，具体能力全部走插件、由 profile 装配；行为不变。

## 1. 现状

- 插件管理器 `plugin` 已有：Register / Setup / Start、拓扑装配、Requires / Provides、插槽、服务、`AddLayer`、通用点位 `Register(point, …)`、Scope、explain。
- 经插件装配的只有 store-sqlite、models、compact-basic（`builtin/default.toml`）。
- 其余能力全在 `cmd/ybase/main.go` 的 `chat()` / `mk()` 里手工 new、手工注册：内置工具、shell + 沙箱、web、todo / ask_user、技能、AGENTS.md 指令、权限、脱敏、hooks、MCP、run_code、子智能体、工作组。三种模型协议适配器写死在 models 插件里。
- 反向依赖：`tools → permission`、`tools → sandbox`、`permission → sandbox`。
- 旧路径未删：`agent` 的 `Tools` / `FromTools` 执行路径、`model` 包与 model-openai 插件、tools-builtin 插件与 `tools.Set`。

插件管理器现在缺的东西，是这些能力没法挂上去的原因：

1. 点位都是进程级的。工具和层很多是每会话一份（指令层记录本会话已装载的文件、run_code 要拿本会话的 hub、技能目录按会话扫描），需要“会话构造期”的点位。
2. 没有系统块点位（技能目录、AGENTS.md 要往系统提示里加块）。
3. 没有回合结束钩子点位（hooks 的 stop 事件现在直接挂在 `host.Hooks.AfterTurn`）。
4. 插件拿不到宿主、总线、存储、模型管理器这些内核对象，也拿不到界面提供的能力（ask_user 的提问、todo 的显示）。
5. Requires 没有可选依赖（shell 有沙箱就用、没有也能跑）。

## 2. 目标结构

### 2.1 内核（只留机制）

| 包 | 职责 |
|---|---|
| `session`、`reqlog` | 会话内核、请求记录 |
| `toolhub` | 调用栈、调度、记录、溢出、确认挂起；不含任何具体工具 |
| `modelhub` | 调度、重试、熔断、目录、适配器接口；不含具体协议 |
| `bus` | 事件总线 |
| `store/sqlite` | 存储（插槽默认实现） |
| `host`、`agent` | 会话宿主、回合驱动；`host` 只提供“派生会话”能力，不含子智能体工具 |
| `plugin` | 插件管理器 |
| `runtime`（新） | 按装配结果构造会话：建 hub、收集工具与层、拼系统块；现在 `mk()` 的逻辑搬到这里 |

### 2.2 插件（全部移到 `kernel/plugins/<名>/`）

| 插件 | 来源 | 挂的点位 / 提供 |
|---|---|---|
| fs | `tools` 读写、编辑、搜索、list_dir | 会话工具 |
| shell | `tools/shell.go` | 会话工具；可选依赖 `service:sandbox` |
| sandbox | `sandbox` | `service:sandbox`；工具层 Guard |
| permission | `permission` | 工具层 Guard；`service:permission`（档位、会话规则、档位对应的沙箱模式） |
| redact | `redact` | 工具层 Transform；before_compact |
| hooks | `hooks` | 工具层；after_turn |
| web | `tools/web.go` | 会话工具 |
| todo、ask-user | `tools/todo.go` | 会话工具；依赖 `service:ui` |
| skills、instructions | `tools/skills.go`、`agentsmd.go` | 会话工具 / 工具层；系统块 |
| mcp | `mcp` | Start 里连接；会话工具 |
| code-mode（run_code） | `ptc` | 会话工具（拿本会话 hub） |
| subagent | `host/subagent*.go` | 会话工具；依赖 `service:host` |
| workgroup | `workgroup` | 会话工具；依赖 `service:host`、存储；迁移 |
| adapter-openai-chat / adapter-anthropic / adapter-openai-responses | `modelhub/*.go` | `model_adapter` |
| store-sqlite、models、compact-basic | 已是插件 | 不变 |

命令行界面（`cmd/ybase`）只做三件事：选 profile 装配、提供 `service:ui`（提问、确认、计划显示、输出）、交互循环。

### 2.3 依赖规则

- 插件只 import 内核包，插件之间不 import，靠服务或工具属性通信。
- 加一个测试（`go list -deps` 检查）：内核包不得 import `plugins/...`，插件不得 import 别的插件。规则写进测试，以后不会再退化。
- “工作区内”“受沙箱约束”两个工具属性移到 `toolhub`（`toolhub.AttrWorkspace`、`toolhub.AttrSandboxed`），作为工具管理器定义的通用属性。
- 档位到沙箱模式的映射归 permission 插件，经 `service:permission` 给 sandbox 插件用；shell 经 `service:sandbox` 约束子进程，不再直接调用 `sandbox` 包。

## 3. 插件管理器要补的东西

| 补什么 | 形式 | 为什么现有点位不够 |
|---|---|---|
| 会话工具点位 `session_tools` | 登记 `func(*SessionCx) ([]*toolhub.Tool, error)` | 工具多数每会话一份 |
| 会话层点位 | 登记 `func(*SessionCx) (toolhub.Layer, error)` + LayerSpec | 指令层、权限层要按会话 |
| 系统块点位 `system_block` | 登记 `func(*SessionCx) (*session.SystemBlock, error)` | 技能目录、AGENTS.md |
| `after_turn` 钩子 | 登记函数 | 用户 hooks 的 stop 事件 |
| 内核服务注入 | 装配时预置 `service:host`、`service:bus`、`service:models`、`service:ui` 等 | 插件要用宿主、总线；界面能力由应用提供 |
| 可选依赖 | Requires 写 `?service:sandbox` | shell 有沙箱就用，没有也能跑 |

`SessionCx` 带：会话 id、工作目录、本会话 hub、会话作用域。点位新增按 ../10 - 框架模块/03 - 插件管理器.md §5.7 规则回填覆盖矩阵。

工具顺序要确定（按 profile 顺序，同插件内按登记顺序），否则工具列表变化会打掉一次缓存。

## 5. 需要你定的点

1. **目录**：插件移到 `kernel/plugins/<名>/`（建议，边界看得见、能用测试强制），还是包路径不动、只改装配方式。
2. **层顺序**：../10 - 框架模块/03 - 插件管理器.md §5.2 规定 Transform 一律在 Guard 外层。现在 hooks 的 post 层和指令层是 Transform，却排在权限 Guard 里面。按 §5.2 执行，这两层会移到权限外面：被拒的调用也会经过它们。我的建议是遵守 §5.2，并让这两层对被拒结果不做处理（看结果状态）；另一个选择是允许 Order 跨位置排序，但会破坏“Guard 在最内侧”的安全保证。
3. **插件粒度**：按上表一族一个插件（建议，profile 里可单独关掉 web、shell），还是合并成一个 tools-core。
4. **旧路径**：S5 删除旧执行路径和 `model` 包（建议）。删了以后，还依赖它们的测试要改写。

## 6. 风险

- 层顺序或工具顺序变了，会改行为或打掉缓存。S0 基线对照就是为了抓这个。
- 每会话构造的开销：现在也是每会话构造，不变。
- 改动面大，但不改功能、不改存储格式，不涉及数据迁移。

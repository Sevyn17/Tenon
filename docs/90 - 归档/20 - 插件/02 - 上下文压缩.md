# 压缩 basic（compact-basic，tasks 5.7）

## 结论

- 插件 `compact-basic`，默认 profile 启用；提供 `service:compactor`，开乙类点位 `before_compact`（登记 `compact.BeforeCompact`，返回错误即拒绝，摘要侧调用之前执行，被拒不花钱）。
- 位置：每次模型调用前在 agent 里决定（`Agent.Compactor.Plan`），先于 modelhub 全部层，等价"最外层 Transform"。其后的层与 R2 结构校验看到的已是压缩后的基础请求，不需要给 CheckShape 开例外。
- 阈值 `floor(min(W×0.8, W−O−B))`：W = 会话模型计划内最小窗口（摘要模型更小时取更小者，plugin-manager §5.2），O = 该模型 max_output，B = headroom 默认 16384。窗口未知不自动压缩。
- 切点：保留最近 `(W−O)×16%` token，取满足保留量的最大合法 upto（不落在调用-结果区间内；步边界也合法，`validateUpto` 改为按调用数计数）。下界是最近一次压缩条目之后，旧摘要因此在被总结范围内，被合并而不是照抄。
- 摘要请求：与正式请求同一外壳与消息前缀（命中前缀缓存）+ 一条结构化指令（目标与用户意图 / 关键技术概念 / 文件与代码 / 错误与修复 / 未完成的事项 / 当前工作 / 下一步 / 关键上下文）。只取文本。结果包 `<compacted-summary>`；不比被替换部分短 → 拒绝。
- 落地：`Core.Compact`（等待中则暂存，步边界或回合结束落条目）+ 本步按 `BuildWithCompaction` 视图发出，请求记录带视图，崩溃重发同一请求。meta：source=compact-basic、summary_model、tokens_before、tokens_after。
- 上下文超限（CONTEXT_WINDOW_EXCEEDED）：强制压缩一次后重发（DSH maxOverflowRetries=1）。
- 压缩失败不挡模型调用（失败开放），只记 `compact` span。
- `/compact`：同一插件，force；保留量不够切时整段压缩到末尾。

## 对照

| 项 | DSH dsh-compaction-basic | pi-mono | Codex | 本实现 |
|---|---|---|---|---|
| 阈值 | min(W×0.8, W−O−65536) | W−16384 | 按模型自动上限 | min(W×0.8, W−O−16384) |
| 保留 | 最近 16% (W−O) | 20000 token | 用户消息 ≤20000 | 最近 16% (W−O) |
| 摘要请求 | 同前缀 + 指令（缓存热） | 独立请求 | 独立 prompt | 同前缀 + 指令 |
| 超限重试 | 1 次 | — | — | 1 次 |

headroom 取 16384 而非 65536：DeepSeek 128K 窗口下 65536 会让阈值降到约 55K，压缩过于频繁。

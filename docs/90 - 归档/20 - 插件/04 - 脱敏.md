# 脱敏（redact）一页调研

状态：P0 实现（6.2，安全项，单独复审）

## 参考
- Codex `codex-rs/secrets/src/sanitizer.rs` `redact_secrets`：四条正则（`sk-…`、`AKIA…`、`Bearer …`、`api_key/token/secret/password = …` 保留键名），替换为 `[REDACTED_SECRET]`，尽力而为。
- DSH `dsh-client-ui-secret-mask`：只在界面层遮罩，日志与模型上下文不处理。
- ../10 - 框架模块/05 - 模型管理器.md:157：side_call 结果若落库，必须过落库扫描；../10 - 框架模块/04 - 工具管理器.md:205：redact 是工具 Transform。

## 结论
- 包 `kernel/plugins/redact`：`Redactor` = 已知值 + 模式两类规则。
  - 已知值：进程环境里名字含 KEY/TOKEN/SECRET/PASSWORD/PASSWD/CREDENTIAL 的变量值，长度 ≥ 8，精确替换，长的先换（`FromEnv` / `Default`）。比纯正则多挡住本机真实密钥（例如 `YBASE_API_KEY`）。
  - 模式：PEM 私钥块、`Bearer` 令牌、前缀型密钥（`sk-`、`AKIA`、`ghp_/gho_/…`、`github_pat_`、`xox?-`、`AIza`）、赋值形式（键名含 api_key/token/secret/password，值 ≥ 8 字符，保留键名与引号）。
  - 只处理文本片段；媒体与结构化数据不动。
- 工具 Transform `redact.Layer`：调用栈最外层，结果在落库（FinishTool）、溢出产物、回模型之前脱敏；确认后重跑的结果同样经过。超时 2s；失败 FailOpen=false：宁可拒绝本次结果，也不把未脱敏文本写进日志。
- 落库扫描：压缩摘要是侧调用生成并落库的，`compact.Compactor.Redact` 在落库前过一遍同一个 Redactor。
- 缺省关闭（plugin-switch-plan，2026-10-31）：要用在 profile 里写 `[[plugin]] name = "redact"` `enabled = true`。开启后 explain / 横幅会标出“改写结果”。
- 赋值规则收窄（2026-10-31）：值不带引号、看起来像代码（含括号 / 运算符，或是纯标识符 / 成员访问，如 `createToken(user)`、`process.env.TOKEN`）时不替换。这样模型读到的源码就和磁盘一致。
- 写回守卫 `WriteGuard`（Guard）：带 `toolhub.AttrWorkspace` 的写文件工具（edit / write_file）参数里出现占位符 `[REDACTED_SECRET]` 时拒绝。这样可以防止把脱敏后的文本写回文件、毁掉真实密钥。

## 已知缺口（复审点）
- 尽力而为，不是安全边界：不认识的密钥格式、拆开或编码过的密钥挡不住。
- 用户自己输入的消息与模型输出不脱敏（用户有意贴入；模型只看到已脱敏的工具结果）。
- 工具参数（模型写出的命令行）不脱敏。
- 前端遮罩不做（P0 无前端）。
- 占位符只有一个、不可还原：模型想改含密钥的那一行时，只能让用户自己改（编号占位符 + 文件工具还原，暂缓）。

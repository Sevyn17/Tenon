# 精确编辑（M5.1 一页调研）

## 竞品

| 来源 | 做法 |
|---|---|
| pi-mono `edit` | `path` + `edits[]{oldText,newText}`；每个 oldText 在**原文件**中必须唯一、互不重叠；先精确匹配，失败再做规范化匹配（NFKC、行尾空白、智能引号、各种破折号与特殊空格）；去 BOM、按 LF 匹配、写回时恢复原换行；兼容模型把 edits 发成 JSON 字符串或单个对象 |
| Codex `apply_patch` | 自定义补丁格式（`*** Begin Patch` / `*** Update File` / `@@` 上下文）；`seek_sequence` 逐级放宽匹配：精确 → 去行尾空白 → 去首尾空白 → Unicode 标点规范化；可一次改多个文件、增删改名；GPT 系列对该格式专门训练过 |
| DSH | `edit` 精确替换为主，失败时返回可操作的错误（未找到 / 多处匹配并给出行号） |

## 结论

1. **P0 只做 `edit`（str_replace 族）**，形状照 pi-mono：`{path, edits:[{old_text,new_text}]}`，每处在原文件上匹配，互不重叠，一次调用原子写入（任何一处失败整体不写）。
   理由：所有模型都能稳定使用；错误可以精确定位；与 DeepSeek / Anthropic 的工具习惯一致。
2. **匹配两级**：精确 → 逐行去行尾空白并规范化 Unicode 标点/空格（Codex seek_sequence 的前两级 + pi-mono 的字符表）。只在唯一命中时替换；多处命中报行号让模型补上下文。规范化命中时**只改命中的行**，其余字节原样保留。
3. **保真**：保留 BOM 与原换行（CRLF / LF），按 LF 匹配；`new_text` 中的换行按原文件风格写回。
4. **`old_text` 为空 = 新建文件**（文件已存在则报错，覆盖走 `write_file`）。
5. **结果**：返回每处替换的起止行号与统一 diff 摘要（最多 40 行，超出走工件预览），便于模型自检。
6. **风险档 Write**：走权限 Guard（ask 档需确认；auto 档工作区内放行，见 05 - 权限.md），不随回合取消中止（tool-hub D3）。
7. **不做（推迟）**：`apply_patch` 格式。M6.7 接 openai-responses 后，GPT 系列再以插件形式提供 `apply_patch`（复用同一匹配器），工具集按模型族选择。

# 子智能体（M6.5）

参考：DSH `dsh-subagent`（spawn / fork-in-process，结果经完成通知回交，`maxDepth` 默认 1，`maxActiveSubagents` 默认 8）；Codex `spawn_agent`；opencode `task` 工具（同步返回子会话最终文本）。

## 结论

1. 子会话是普通会话：会话行 `parent_id = 父 id`、`origin = subagent`（`agent.OpenAs`）。持久，可用 `-session <子 id>` 单独打开查看、续聊。
2. 模型面工具 `subagent {task, session?}`（`host.SubagentTool`）：**同步**驱动子会话一个回合，返回最后一条助手文本，前缀 `[子会话 <id>]`。子会话 id = `<父 id>/sub-<调用 id 末 8 位>`；传 `session` 续用，必须是本会话的子智能体。
3. 深度 1：子会话用不带 `subagent` 工具的工厂构造。
4. 级联取消：父回合取消 → 工具 ctx 取消 → 子会话收到 Cancel。默认超时 30 分钟。
5. `Cx.ChildSessionID` 写入 tool span 的 `child_session_id`，可从父会话跳转。
6. 确认上交：子会话的 `human_requested` 事件带子会话 id 发到总线；CLI 不过滤这类事件，确认命令按事件里的 session 路由回子会话。单一确认路径不变。
7. 崩溃恢复：父会话按原调用 id 重放 → toolhub 幂等记录为 `started` → 回"结果未知"；子会话本身已持久，可续用同一 session 追问。
8. Risk = Write（子智能体可写文件，权限仍逐个工具检查），不并行。

## 与清单的差异（决策日志 6.5）

- **inbox 回交推迟**：P0 用同步工具结果回交，不走 inbox 完成通知。理由：同步返回不需要后台调度、完成通知格式和父会话唤醒；opencode 同样同步。后台委派（DSH 式立即返回 id + 完成通知经 inbox）在需要并发子任务时作为插件加入，inbox Note 已能承载。
- **fork 式子智能体推迟**：继承父上下文的 fork 子智能体需要复制父前缀到子会话（`Host.Fork` 已有），但父回合进行中不能 fork（来源须 Idle）。等后台委派一起做。
- 未做：并发上限、按 agent 预设选模型 / 工具集。

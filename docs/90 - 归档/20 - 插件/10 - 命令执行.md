# shell 工具（M5.3 调研一页）

## 参考

- **pi-mono** `bash.ts` / `powershell.ts`：每次新进程，无默认超时（可选 timeout 秒，有上限）；输出保留**尾部** 2000 行 / 50KB，截断时完整输出落临时文件；PowerShell 前缀 `[Console]::OutputEncoding=UTF8` 解决乱码。
- **Codex** unified exec（`shell_spec.rs`）：PTY 持久进程 + `session_id` + `write_stdin` + `yield_time_ms`；命令在 yield 时间内未结束就返回会话 id，模型后续轮询。能力最强，但依赖 PTY（Windows ConPTY），进程状态无法跨崩溃恢复。
- **DSH**：`ops_bash` 每次新 shell + `run_in_background` 返回 job id，`job_output`（可 wait）/ `job_kill` 收取与终止；超时后转后台而不是杀掉。
- **opencode / goose**：每次新进程 + 超时 + 输出截断；goose 另有后台进程管理。

## 结论

1. **每次调用新进程，不做持久 shell 会话**。理由：持久会话的 cwd / 环境变量是隐藏状态，崩溃恢复后无法重建（违背“一个事实一处”）；Windows 无 PTY 依赖更稳。需要的场景（dev server、长编译）由后台 job 覆盖。清单写的“持久会话”以此替代，记入决策日志。
2. **`shell {command, timeout?, background?}`**：Windows 用 `pwsh`（没有则 `powershell`），前缀强制 UTF-8 输出（修 M1 验收的 GBK 乱码）；其他系统 `bash`（没有则 `sh`）。默认超时 120s，上限 600s；超时杀**整个进程树**（Windows `taskkill /T /F`，Unix 进程组）。
3. **输出**：stdout+stderr 合并，末尾注明退出码；超出工件阈值由 tool-hub 落工件、按 **tail** 预览（D7，Attrs preview=tail）。非零退出码回 `ToolError`。
4. **后台 job**：`background:true` 立即返回 job id；`job_output {id, wait?, timeout?}` 返回自上次读取以来的新输出（每 job 内存保留尾部 1MB）与状态；`job_kill {id}`。job 属于进程内存，进程退出时全部终止；重启后查询旧 id 回“job 不存在（进程重启后后台任务已丢失）”。
5. **风险档**：shell = Dangerous（需确认，回合取消时等 finish_grace 再杀）；job_output = Read；job_kill = Write。
6. **不做（推迟）**：stdin 交互（write_stdin）、PTY；沙箱在 M6.1 以 Guard / 执行器包装接入。

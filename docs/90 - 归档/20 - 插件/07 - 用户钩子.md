# 用户脚本钩子（M6.4）

## 参考
- Codex `codex-rs/hooks`：事件 PreToolUse / PermissionRequest / PostToolUse / PreCompact / PostCompact / SessionStart / SessionEnd / UserPromptSubmit / Stop 等；command 处理器 stdin 收 JSON；退出码 0 时 stdout 可选 JSON（`decision:"block"` + `reason`、`hookSpecificOutput.permissionDecision`、`additionalContext`、`systemMessage`）；退出码 2 = 阻止，理由取 stderr；`decision:block` 无 reason 视为钩子失败；默认超时 600s；异步钩子并发上限 8。
- Claude Code hooks：同一协议（Codex 是兼容实现）。
- 我们的定稿 session-host D5：不进宿主，做成插件，挂工具 Guard（工具前）、工具 Transform 返回侧（工具后）、after_turn（回合结束）。

## 结论
1. 包 `kernel/plugins/hooks`，P0 只支持三个事件：`pre_tool_use`、`post_tool_use`、`stop`。协议取 Claude Code / Codex 兼容子集，现有脚本可直接用。
2. 配置 TOML：`[[hook]] event / matcher（工具名正则，完整匹配）/ command / timeout（秒）`。用户级 `~/.ybase/hooks.toml` 总是加载；项目级 `<dir>/.ybase/hooks.toml` 只在 `-project-hooks` 时加载，因为它会执行仓库里写的命令（同 MCP 的信任问题）。
3. 执行：每个钩子一个新进程（Windows PowerShell，其余 bash/sh），stdin 是 JSON（`session_id / hook_event_name / cwd / tool_name / tool_use_id / tool_input / tool_response / tool_status / end_reason`），环境加 `YBASE_HOOK_EVENT`、`YBASE_SESSION_ID`。stdout / stderr 各留 64KiB。默认超时 60s（Codex 600s 偏长，钩子挡在工具前）。
4. 结果：退出码 0 + JSON → `decision:block`（必须有 reason，否则告警忽略）或 `permissionDecision:deny` 阻止；`additionalContext` 追加给模型。退出码 2 → 阻止，理由取 stderr（空则告警忽略）。其他非零、超时、无法启动 → 只告警，不阻止（钩子自身故障不应卡死工具）。同一事件按配置顺序执行，第一个阻止的即停。
5. 层：`hooks-pre` 是 Guard（失败关闭），被阻止时返回工具错误"被用户钩子阻止：…"，回合继续；`hooks-post` 是 Transform（FailOpen），把反馈 / 说明追加到工具结果末尾。层超时 = 该事件全部钩子超时之和 + 5s，不会早于钩子自己超时。位置在权限层之后（被拒的调用不触发钩子）、脱敏层之内（钩子追加的文字也被脱敏）。
6. `stop` 只通知（挂宿主 `AfterTurn`）。P0 不支持 Codex 的 stop 续跑（block → 续一轮），因为它要在宿主里开新回合，属于新机制。

## 缺口
- 不支持 UserPromptSubmit / SessionStart / PreCompact / PermissionRequest、异步钩子、prompt / agent 类型处理器、`updatedInput` 改写参数（改写会让幂等记录的参数哈希失配，需另行设计）。
- 钩子进程进沙箱：每条钩子可写 `sandbox = "read-only" | "workspace-write" | "danger-full-access"`，缺省 workspace-write（项目级钩子来自仓库，不应默认拿到用户全部权限）。无法放进沙箱时告警、不执行。沙箱插件未启用时不加沙箱。
- `stop` 钩子在宿主 actor 里同步执行，慢钩子会推迟下一回合开始（受超时约束）。

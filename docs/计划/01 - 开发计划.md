> 状态：生效（2026-11-01，同日按计划审查修订）。本篇是唯一的排期与进度文档。每步做什么、验收什么写在 [框架设计/09 - 演进与验收](<../框架设计/09 - 演进与验收.md>)；本篇只管顺序、拆分、完成标志和进度。旧计划（路线图、任务总清单、P0 开发计划、待办清单）已归档到 [90 - 归档](<../90 - 归档/>)。

## 一、每步的完成标志

一步算做完，要同时满足：

1. 现有测试全部通过（`go vet ./...`、`go test ./...`）。
2. 回归快照无差异：T1a 的单会话快照（`kernel/runtime/host/testdata/snapshot_requests.json`），T1b-0 之后再加真实装配快照。有差异时逐条在决策日志里说明。
3. 09 里该步的验收用例全部有测试并通过。
4. 框架设计对应篇有"现状差距"一节的，更新该节；没有的，在决策日志那一行写"不适用"。文档与代码一致。
5. 在 [02 - 决策日志](<02 - 决策日志.md>) 记一行，单独一个 git 提交。

- **T1b-0 先行**：T1a 的快照只挂一个 `echo` 工具，不经过 `runtime.Builder` 和插件；T1b-1 改的正是插件装配，没有真实装配快照就证明不了"行为不变"。
- **T1b-1 拆三步**：按风险从低到高。1a 是机械替换；1b 只加 SQL 出口和 `Registrar` 改名，不动工具；1c 才落 `Component` / `*Ctx` 并动全部工具插件（10 个文件、22 处会话点登记），风险最大放最后。租户条件属于纯存储改动（单机恒为 `local`，不改行为），并入 1a。
- **T2b 在 T2a 前、两者串行**：两步都改每轮主循环（`runtime/host/host.go` 的 turn、`runtime/agent/agent.go`），并行会冲突。
- **T2a 拆三步**；`wake` 信封合并插入和 Rewind 作废 `corr` 依赖 T3 的信封和 `session_pending`，移到 T3。

## 三、v1 整体验收

T3 完成后做一次，全部满足才算 v1：

1. T1a–T3 各步验收用例汇总后全部通过（用 `ybasetest` 写的部分在 SQLite 和内存两种存储上都过）。
2. 端到端演示（真实模型，人工）：桌面端单聊；主会话调子智能体；工作组组长派活给成员并收回结果；中途杀进程后重启续跑；低权限智能体调高权限智能体被守卫拦下，`explain <trace>` 能看到原因。
3. 两种回归快照无未说明的差异。
4. 框架设计 00–13 与代码一致，"现状差距"只剩 T4 之后的内容。

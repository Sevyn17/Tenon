# 01 开发计划

> 状态：生效（2026-11-01）。本篇是唯一的排期与进度文档。每步做什么、验收什么写在 [框架设计/09 - 演进与验收](<../框架设计/09 - 演进与验收.md>)；本篇只管顺序、拆分、完成标志和进度。旧计划（路线图、任务总清单、P0 开发计划、待办清单）已归档到 [90 - 归档](<../90 - 归档/>)。

## 一、每步的完成标志

一步算做完，要同时满足：

1. 现有测试全部通过（`go vet ./...`、`go test ./...`）。
2. 回归快照（`kernel/core/host/testdata/snapshot_requests.json`）无差异；有差异时逐条在决策日志里说明。
3. 09 里该步的验收用例全部有测试并通过。
4. 框架设计对应篇的"现状差距"已更新，文档与代码一致。
5. 在 [02 - 决策日志](<02 - 决策日志.md>) 记一行，单独一个 git 提交。

## 三、T1a 实际交付（与 09 9.2 的出入）

- 已做：S1 补全（schema v3，v2 带数据升级测试）；`store.Store` 接口、SQLite 与内存两个实现、`storetest` 一致性测试（14 项，两个实现都过）；回归快照基线；`core/agentdef` 定义加载（三个命名空间、内容哈希、`resident = true` 报未支持）。
- 与 09 的出入：
  - `ybasetest` 没做，只做了存储层的 `storetest`。`ybasetest` 要 `ybase.New` 才能写，移到 T1b-2。
  - `Store` 是扁平接口，按子存储拆分（`Sessions()` 等）放到 T1b-1 跟组件骨架一起做；`Collection` 仍在 T4。
  - 回归快照录的是完整模型请求（字节比较），不是 09 写的"工具列表、条目序列"；更严，保留。
  - 用户层目录放在租户下（`user/<租户>/<用户>/<名字>`），文件内容哈希对无 NUL 文件做 CRLF→LF，已补进框架设计 03 3.4、3.5。

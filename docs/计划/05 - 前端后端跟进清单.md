# 05 前端需要后端配合的跟进清单

> 状态：待办（2026-11-06）。来源：前端体系重做（`web/` 第 1–8 步）。这些能力前端已留好位置：入口按"停用 + 原因"显示，或渲染器已写好、只差后端数据。做完一项就在本篇划掉并在 [06 应用协议契约](<../06 - 应用协议契约.md>) 补上对应命令或字段。

| # | 能力 | 前端现状 | 后端要做 |
|---|---|---|---|
| F1 | 会话重命名、删除、置顶 | 会话行菜单留了 `session.row.menu` 位置，没有内置项 | 新命令（如 `session.rename` / `session.delete` / 置顶标记），`sessions.changed` 带上变化 |
| F2 | 切换模型 | 输入框工具栏留了插槽，没有入口 | `session.settings` 加 `model`，`hello` 或新命令列出可选模型 |
| F3 | `plugins.set` | 设置 › 插件的配置表单只读，并说明"需编辑 profile.toml 后重启" | 实现 `plugins.set`（按 revision 写，冲突时返回 `conflict`），前端改成可写 |
| F4 | 列工作区文件（`@` 文件） | `MentionProvider` 只有内置的"会话"来源 | 新命令列文件 / 模糊搜索，前端再加一个提及来源 |
| F5 | 大附件上传 | 超过 2 MiB（`MaxArtifactPut`）直接提示 | `POST /api/artifacts`（10.9 已写），Wails 下宿主提供同等入口 |
| F6 | 工件存储 | 网页服务没有工件存储时 `artifact.put` / `get` 返回 unsupported，附件与工件面板不可用 | 网页服务与桌面端默认装配工件存储 |
| F7 | 交互的更多种类 | `InteractionCard` 只实做 approval / question，其余 kind 走通用卡 | wire `Interaction` 加 `schema` 与 choice / form / confirm / review 载荷；`Response.value` 走通；后端插件发起非工具交互的入口；交互声明是否阻塞（决定接管输入框还是内联） |
| F8 | 反馈存储 | 👍 👎 只留了消息操作位置 | 存反馈的命令与存储 |
| F9 | 后续建议来源 | 回合尾巴有 `FollowupProvider` 注册表，没有内置来源 | 模型输出建议块的约定或单独命令 |
| F10 | 后端插件的前端贡献 | `DeclarativeView` 与插槽的 `view` 字段已就绪，只能本地 JSON 贡献 | 插件 manifest 加 `client` 段（插槽位置 + 声明式 UI + 数据来源），经 `hello` 或 `plugins.list` 下发 |
| F11 | 插件市场、用户账号 | 菜单区预留 `nav.primary`，没有内置项 | 另立设计 |
| F12 | 工具实时输出 | 步骤行进行中只显示计时 | `tool.progress` 带最后几行输出（shell 等长输出工具） |

# 04 设计质量审查（2026-11-04）

> 范围：`runtime/` 全部包、`modules/` 全部 22 个组件、SDK（模块根 `ybase`）、`ybasetest`、`apps/internal/boot`。6 路并行审查（只读），每条结论给 `文件:行号`；最关键的条目由主会话复核（标 ✔复核），其中 Rewind、PowerShell 退出码用真实代码 / 命令复现。上一轮（[03](<03 - v1 收口全面审查（2026-11-02）.md>)）已修项不重复。
> 定位与命名另见 [05 - 定位与命名方案](<../05 - 定位与命名方案.md>)。

## 结论

骨架是对的，不需要推倒：会话纯状态机、检查点单事务、租约纪元 fencing、发件箱至少一次、工具幂等记录、装配期拓扑与依赖声明，这些都扎实。问题集中在四类：

1. **写了但没生效**：自动压缩、定义里的 `prompt` 和 `model` 都没接上；`Minimal()` 起不了会话；`/rewind` 在普通会话上必失败。
2. **调度语义**：子会话被唤醒后丢掉"子"身份；control 投递同步等整个回合；Idle 命令被信箱积压饿死；只有 context 信件的会话永远睡不着。
3. **可扩展性**：投递、翻页、注入都在做 O(日志长度) 的全量加载或序列化；单连接 SQLite；休眠扫描饥饿。
4. **扩展模型偏弱**：两套层系统（一套没人用）、字符串服务键加 `any`、死插槽、SDK 与 boot 两条装配路径、SDK 直接转出内核类型。

总计：高 21 条，中 约 60 条，低 约 80 条。下面按优先级分组；完整明细保留在各节的表里。

## 做得好的地方（不要动）

1. **会话纯状态机**：无 IO、时钟和 id 可注入、命令要么生效要么报错；`BuildRequest` 与 `BuildWithCompaction` 共用一条构造路径，"假设压缩"和"真压缩"逐字节一致。
2. **检查点单事务**：截断归档、追加条目、外壳、请求记录、inbox 消费、span、发件箱、头部条件写同一事务；纪元先于 log_len 校验；`WithoutCancel` 保证取消不影响落库。
3. **至少一次 + 幂等**：发件箱 `UPDATE … RETURNING` 原子认领、期限、尝试次数、死信；inbox 按信封 id 幂等；工具记录 started / pending / delivered / done 推进清楚。
4. **守卫与权限的语义细节**：`intersectCaps` 严格区分 nil 和空集；`Deliver` 入口重置内核字段；公共规则禁止 allow；定义上限两边各判取更严；档位名写错按 read-only。
5. **路径与网络安全**：fs 自己逐段解析 junction（`EvalSymlinks` 不跟 junction）；web_fetch 在 `Dialer.Control` 按实际 IP 校验，防 DNS 重绑定。
6. **装配可预测**：拓扑排序 + 字典序；Setup 后核对 Provides；插件只能 Use 自己声明的键；`deps_test.go` 强制内核不依赖模块、模块之间不互相依赖。
7. **迁移与存储**：按 owner 分版本只追加、事务内重读版本、BUSY 退避；storetest 一套用例跑两个实现。

# 07 框架与客户端边界迁移方案

> 状态：四个阶段都已完成（2026-11-08）。不改行为，只调整代码归属与公开接口。
>
> 阶段一与方案的出入：网页传输的包路径是 `tenon/transport/web`、包名 `web`，和前端嵌入包 `tenon/web` 同名，网页服务里把后者别名为 `webui`。令牌文件的写入（`WriteTokenFile`）进了框架，`-token-file` 参数的解析留在客户端。框架的 `apphost` 保留一份只写强制插件的缺省 profile，客户端不传 `BaseProfile` 时用它。

## 一、问题

目录上已经分成两个 Go 模块：`framework/`（模块 `tenon`）和 `client/`（模块 `client`）。但边界划错了两处：

1. **两条装配路径。** SDK 的 `tenon.New` 用代码配置组件、`WithStore` 注入存储，对外只有 `Ask` / `History`；三个客户端走 `client/internal/boot`：读 profile、项目信任、插件包，装 store-sqlite，接上完整的应用协议。两边各自维护，插件缺省开关都不一致（04 模块清单里 redact、sandbox 两条注释就是这个原因）。
2. **对接协议的通用代码在客户端的 internal 包里。** 模型列表、权限档位、插件开关、追问建议、自动标题、文件列表的协议适配，profile 分层加载，项目信任，工作区管理，网页服务的传输层，全部在 `client/` 下，其中大部分在 `internal/`。用框架做别的产品的人引用不到，只能重写。SDK 的 `App.Start` 里虽然建了 `appapi.App`，但没有存下来，SDK 用户也接不上框架自带的前端。

## 二、判断标准

一段代码归框架还是归客户端，问一句：**换一个产品（客服机器人、运维助手、别人的编程智能体），还需要它吗？**

- 需要，而且做法一样 → 框架。
- 需要，但每个产品做法不同（名字、缺省配置、窗口、终端交互、示例提示）→ 客户端，框架提供可替换的缺省或扩展点。
- 只有我们需要 → 客户端。

## 三、逐文件归属

### client/internal/boot（约 1430 行，不含测试）

| 文件 | 内容 | 去向 |
|---|---|---|
| `runtime.go` | 读信任 → 读 profile → 装配 → 接协议（`Start` / `BuildApp`），`Flags`、`Overrides` | 框架 `apphost`；`Flags` 改名为 `Options`，命令行解析留在客户端 |
| `assemble.go` | 按 profile 装配、空 import 全部插件 | 框架 `apphost`；"装哪些插件"由调用方决定（见第五节阶段三） |
| `trust.go` | 项目信任读写、`ResolveTrust`、profile 分层加载、项目配置禁改键、`Home` | 框架 `apphost`；内嵌的缺省 profile 内容留在客户端，作为参数传入 |
| `profile.toml` | 内置 profile（强制插件等） | 客户端（产品的缺省配置） |
| `profiles.go` | `plugins.set` 的文件侧 | 框架 `apphost` |
| `models.go`、`modes.go` | 模型目录、权限档位到协议的适配 | 框架 `apphost` |
| `followups.go`、`titles.go` | 追问建议、自动标题（模型侧调用） | 框架 `apphost`；提示词作为可替换的缺省 |
| `workspace.go`、`legacy.go` | 工作区管理器、旧项目库并入 | 框架 `apphost` |

### client/server（约 680 行）

| 内容 | 去向 |
|---|---|
| `server.go`：令牌鉴权、Host / Origin 检查、CSP、WebSocket 帧、心跳、背压、上传入口、热换 App | 框架 `transport/web`（`http.Handler`） |
| `tokenfile*.go`：令牌文件（只本人可读） | 框架 `transport/web`（Windows / 其他平台的权限设置是通用的） |
| `main.go`：命令行参数、监听、TLS、打印地址 | 客户端 |

### client/desktop（约 230 行）

| 内容 | 去向 |
|---|---|
| `service.go` 的 `Service`：`Call(cmd, args)` 字符串进出、事件转发、热换 App | 框架 `transport/bind`（不依赖 Wails，任何"绑定一个方法 + 推事件"的宿主都能用） |
| `service.go` 的 `uploadMiddleware`（Wails 的中间件类型） | 客户端（Wails 胶水） |
| `main.go`：窗口、Wails 应用 | 客户端 |

框架的 go.mod 已经有 `golang.org/x/net`、`golang.org/x/sys`，搬过去不新增依赖；Wails 只留在客户端。

### client/tenon（命令行，约 1180 行）

全部留在客户端：终端界面、首次信任询问、子命令（`mode`、`plugin`、`trust`）、启动横幅。它对 boot 的调用改为对 `apphost` 的调用。

### 前端 framework/web

基本已经对：四层都在框架里，品牌和示例提示通过 `createShell({brand})` 传入，工作区切换按后端能力显示。唯一的产品内容是入口 `src/main.tsx` 里写的问候语和三个示例提示，以及 `embed.go` 嵌进二进制的就是这个入口的构建产物。见第五节阶段四。

## 四、目标结构

```
framework/（模块 tenon，可分发）
  runtime/        内核（不变）
  modules/        插件（不变）
  appapi/         应用协议（不变）
  web/            前端 L0–L3（不变）
  tenon.go …      SDK：新增 App.API()，阶段三支持 profile 装配
  apphost/        新：应用宿主——profile 与信任、装配、协议适配器、工作区管理、旧库并入
  transport/web/  新：网页传输（http.Handler：WebSocket + 上传 + 令牌）
  transport/bind/ 新：绑定式传输（Call + 事件，桌面端等用）

client/（模块 client，我们的产品）
  tenon/          命令行：参数、终端界面、子命令
  server/         网页服务：参数、监听、TLS、打印地址
  desktop/        桌面端：Wails 窗口与胶水
  product/        新：产品配置——内置 profile.toml、品牌、追问 / 标题提示词（若要定制）
```

`apphost` 放在模块根下、与 SDK 同级，不放进 `runtime/`：它要 import 插件包（权限、文件），而核心包不能依赖 `modules/`（04 模块清单第一节）。

## 五、分阶段

每个阶段单独提交，结束时 Go 测试、前端测试全绿，浏览器里验证一遍网页端。

### 阶段一：搬家，不改逻辑（最先做，风险最低）

1. 建 `framework/apphost`，把 boot 的文件连同测试搬过去，包名改为 `apphost`。
2. 内置 profile 改为参数：`apphost.LoadAll(base string, extra, root string, trusted bool)`，客户端把自己的 `profile.toml` 传进去。
3. 建 `framework/transport/web`，搬 `server.go`、`tokenfile*.go` 和测试；`Config` 不变。
4. 建 `framework/transport/bind`，搬 `Service`（不含 Wails 中间件）和测试。
5. 三个客户端改 import；`client/internal/boot` 删除。
6. `TestProtocolCommands`（校验前端命令表与后端一致）随 `Service` 搬到框架，读 `web/src/client/commands.ts` 的相对路径变短。
7. 更新 `scripts/serve-web.sh`、`bin/run-server.sh` 里涉及的路径（只有构建命令，路径不变）和 04 模块清单的分层图。

改动量：约 2300 行代码与测试换位置，三个客户端各改十几行 import 与调用。

### 阶段二：SDK 能接协议

1. `App` 存下 `appapi.App`，新增 `App.API() *appapi.App`；`Start` 之前调用返回 nil。
2. `apphost` 的协议适配器做成可单独使用的构造函数：`apphost.Adapters(models, perms, …) appapi.Options` 的一部分，SDK 用户自己装配时也能接上模型列表、档位等。
3. 示例：`examples/web-server`，二十行左右用 SDK + `transport/web` 起一个带工作台的网页服务。示例本身就是这一阶段的验收。

> 阶段二实际做法：协议适配器单独成包 `tenon/adapters`（`Fill(&appapi.Options, Parts)`），不放在 `apphost` 里——阶段三 `apphost` 要建在 SDK 上，SDK 再 import `apphost` 会成环。档位确认记录改成接口 `adapters.ModeApprovals`，`apphost` 的实现记在 trust.toml，SDK 缺省不记（每次确认）。另加了两个选项：`WithProtocolUI()`（提问经协议回答；缺省界面仍是丢弃输出、提问报错，`Ask` 的行为不变）和 `WithConfig(组件, 键值)`（示例要设 models 的 base_url，SDK 原先没法配组件）。`hello.trusted` 改为反映 `WithProjectTrust`，原先写死 true。示例 `examples/web-server` 用真实模型验证过：读文件工具、回答、自动标题、追问建议都正常。
>
> 留到阶段三：SDK 的会话不记工作区（`Host.Workspace` 为空），和 `apphost` 共用一个库时会看到别的工作区的会话，示例因此用自己的库文件；SDK 不报 `upload` 能力，附件走 `artifact.put`。

### 阶段三：合成一条装配路径

目标：`apphost` 建在 SDK 上，不再自己调 `assemble.Wire` 和 `appapi.New`。

1. SDK 新增 `WithProfile(p *component.Profile)`：按 profile 选组件（`Meta.Default` + 开关 + 强制项），与现有的 `Default()` / `Minimal()` 预设二选一。
2. 存储：profile 里有提供 `service:db` 的插件时不再要求 `WithStore`。顺带把强制项从"必须是 store-sqlite"改为"必须有插件提供 `service:db`"。
3. SDK 新增注入点：`WithService(key, v)`（工作目录、界面、信任、插件包这几个应用预置服务），`WithHost(h)` 或等价的宿主参数。
4. `apphost.Start` 改为：读信任与 profile → `tenon.New(WithProfile, WithService…)` → `Start` → `App.API()`。
5. 两种入口的插件缺省统一：以插件自己声明的 `Meta.Default` 为准，`Default()` 预设只是"按 Meta.Default 再显式打开 redact、sandbox"的写法，在文档里写清楚，而不是两套各自的清单。

这一阶段改动最大，会碰到装配顺序、插件实例、存储生命周期，单独排期。

> 阶段三实际做法：`apphost.Start` 现在是 读信任与 profile → `tenon.New(WithProfile, WithWorkdir, WithProjectTrust, WithWorkspace, WithService(插件包), WithModeApprovals, WithProtocolOptions, WithConfig(命令行覆盖)…)` → `App.Open`；`BuildApp` 是 `App.Start`。`assemble.Wire` 与 `appapi.New` 只剩 SDK 里一处调用。真实装配快照（`TestAssembledSnapshot`）不改就通过：经 SDK 装出来的工具、系统提示词、请求与原来一致。
>
> 与方案的出入：
> - 没有 `WithHost`：宿主还是 SDK 自己建，`WithWorkspace` 设工作区键（顺带补上阶段二留下的"SDK 会话不记工作区"）。
> - SDK 的启动拆成 `Open`（只启动组件、打开存储）与 `Start`（接线、协议层、ready、后台循环）：命令行的 explain / 查轨迹只要 `Open`，不起后台循环，与原来一致。
> - 会话钩子、上传、工作区切换这些原先在 `BuildApp` 时才给，现在要在装配时给：`apphost.StartOptions` 加了 `App AppOptions`，`BuildApp()` 不再带参数；`StartOptions.UI` 直接给界面，nil = 协议界面。
> - ready 点位的错误：SDK 缺省让 `Start` 失败，`apphost` 用 `WithReadyErrors` 收下当提示显示（与原来一致）；点位在 `BuildApp` 里就跑了，`Built.Ready` 只交出错误。
> - 第 5 条原文写的"Default() = Meta.Default 再加 redact、sandbox"不对：`Default()` 实际是全部标准组件（存储除外），比 Meta.Default 多了技能、钩子、MCP、待办、网页、子智能体、工作组、code-mode。改成以这条为准，`presets_internal_test.go` 强制两边不分叉。
> - 强制项：两份内置 profile 去掉了 `mandatory = ["store-sqlite"]`；按 profile 装配时没有提供 `service:db` 的组件就报错，`plugins.set` 拒绝关掉最后一个存储插件。
> - SDK 的 `Upload` 能力由应用经 `WithProtocolOptions` 打开（apphost 打开；示例没挂上传入口，不打开）。

### 阶段四：前端的产品内容归位

两种做法，建议选 A：

- **A. 前端也像 SDK 一样被引用。** `framework/web` 作为包（pnpm workspace 内的 `@tenon/web`），`client/web` 是我们产品的前端入口：写品牌、示例、产品自己的贡献包，自己构建、自己嵌进三个客户端。`framework/web` 保留陈列页和一个中性的缺省入口。
- **B. 品牌由后端下发。** 前端入口不变，问候语和示例从后端取（比如静态的 `/brand.json`）。改动小，但"产品前端"没有自己的地方放贡献包，以后加产品专属面板还得回到 A。

> 阶段四实际做法（选 A）：`framework/web` 的包名改为 `@tenon/web`，`exports` 按层给出源码入口（`./client`、`./client/react`、`./ui`、`./shell`、`./shell/embed`），不预先打包；缺省入口 `src/main.tsx` 改成中性品牌（没有示例提示），SDK 示例嵌的就是它。`client/web` 是产品前端：`link:` 引用 `@tenon/web`（没有用 pnpm workspace，两个目录各自安装，框架保持可单独分发），入口只写品牌和示例，`vite` 用 `resolve.dedupe` 保证 React 只有一份；`client/web/embed.go` 把构建产物嵌进网页服务与桌面端。`serve-web.sh` 改为：检查框架前端 → 构建产品前端 → 重建网页服务。

## 六、哪些会变成公开接口

搬出 `internal` 就是对外承诺。阶段一结束时逐个过一遍要导出的名字，没把握的先不导出：

- `apphost`：`Open / Options / Workspace / WorkspaceManager / LoadAll / ResolveTrust / Trust 读写 / Adapters`。`Overrides`、`importLegacy` 这类细节不导出。
- `transport/web`：`New(Config) http.Handler`、`NewToken`、`LoopbackHosts`、令牌文件。
- `transport/bind`：`Service` 的 `Call / StartEvents / StopEvents / SwapAPI`。

在 05 定位与命名方案里标为 v0：可以改，但要写进决策日志。

## 七、风险

| 风险 | 应对 |
|---|---|
| 搬家时漏改路径，测试里的相对路径（读前端命令表、testdata）失效 | 阶段一每搬一个包就跑它的测试 |
| 阶段三改了装配顺序，插件启动失败或缺省开关变化 | 现有的装配快照测试（`snapshot_test.go`）先随阶段一搬过去，阶段三前后对比快照 |
| 公开接口过早定型 | 第六节逐个过；标 v0 |
| 前端打包方式变化（阶段四 A）影响三个客户端的构建 | 阶段四单独做；`serve-web.sh` 同步改 |

## D 组 · 存储两实现不一致与数据卫生（中/低）——已修

- sqlite `DeleteSession` 漏删 `session_pending`、`session_outbox`、`trace_events`（`sqlite/delete.go:30`）✔；memstore 会删。
- memstore 重复会话 id/key 不包 `ErrConflict`，`envelope.go:92` 的并发按 key 建会话重试在 memstore 上永不触发。
- memstore 标记已发即删行，同 id 可重新入队；sqlite 保留行、`DO NOTHING`。
- 墓碑：sqlite `SessionStatus` 返回 `deleted`，memstore 返回 ErrNotFound，`envelope.go:124` 的判断只在 sqlite 生效。
- memstore `TraceEvents` 不按 At 排序；`FindSessionByKey("")` 两实现结果不同；`Replay`/`SetSessionStatus`/`MarkOutbox` 对未知 id 的错误类型不同（sqlite `Replay` 直接漏出 `sql.ErrNoRows`）。
- 无清理、无限增长：`trace_events`、`session_pending`（已用行）、`session_outbox`（已发行）、`session_entries_archive`、`session_shells`、`trace_spans`。
- 租户条件缺口：`session_shells`、`trace_events` 无 tenant 列；若干索引不带 tenant；`session_inbox` 缺排空查询的覆盖索引。
- 会话核心小缺陷：厂商 wire id 不去重（`core.go:743`，同一回复两个 `call_0` 后 Restore 拒绝）；注入「已清除」的键会复活，每次调模型都多一条 `<status-update>`（`inject.go:120`）；`SetExt` 超限仍保留新值（`core.go:545`）；崩溃恢复的 done 记录丢失取消状态（`exec.go:408`）。
- 确认 corr 的期限写死 24 h，不认 `[kernel] confirm_deadline`（`host.go:1050`）。

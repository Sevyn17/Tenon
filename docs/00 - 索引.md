# 文档索引

## 零、先分清：框架与产品

这个仓库是**框架**（SDK），不是产品。两个仓库分工不同，看文档前先确认你要找的是哪边。

| | 本仓库（tenon） | 产品仓库（Mortise） |
|---|---|---|
| 是什么 | 智能体框架 / SDK，Go 库 | 通用智能体产品，建在框架上 |
| 给谁用 | 写应用的人 | 用产品的人 |
| 有什么 | 内核、模块、应用协议、插件机制、协议客户端 `@tenon/client` | 命令行、桌面端、网页端、工作台界面、品牌与内置配置 |
| 文档入口 | 本篇 | `Mortise/docs/01 - 产品说明.md` |

**边界怎么划**：框架给「会话、工具、插件、权限、应用协议」；产品给「入口、界面、配置、品牌」。

几个容易搞混的点：

- **前端界面不在框架**。框架只提供协议客户端 `@tenon/client`（约 2000 行，不依赖 React）；
  工作台、组件库、hooks 都在产品仓库 `Mortise/client/web`。理由见 [web/README.md](<../web/README.md>)。
- **框架的遗留清单**是本仓库 [16 - 待办与遗留事项](<02 - 开发管理/16 - 待办与遗留事项.md>)；
  产品的遗留是另一份，别混。
- **产品要接手时**，先看 [19 - 框架侧交付与验收交接](<02 - 开发管理/19 - 框架侧交付与验收交接.md>)，
  它写清了这一轮框架改了什么、验证了什么、产品要跟着做什么。

文档按阶段分目录。每个阶段目录里是该阶段的文档，编号与原来一致。

仓库根另有 [CHANGELOG.md](<../CHANGELOG.md>)：按版本记变更，破坏性变更单独成节。
发版判据与版本规则见 [07 - SDK 接口](<01 - 设计文档/框架设计/07 - SDK 接口.md>) 7.4 / 7.4.1。

# 第二轮审查 D1–D8 拍板结果（用户 2026-11-01 "全部按建议"）

D1 定义的内核字段（封闭面）= ID、Description、Model、Prompt、Tools、Resident 共 6 个。Use、X 是扩展槽；Format、Version、Files 由底座填写。权限不是内核字段，放进 `[use.permission]`，由 permission 组件管理，经 Guard 交给守卫做交集。标识字段统一叫 `id`（不用 name）。版本 = 整包内容哈希。

D2 信封字段只认 11 这一份表，01、05 引用它不再各写。删掉 `reply_to`（回信靠 corr 反查请求会话）。权限字段名 `caps`，类型 = 解析后的具体工具集合（如 [fs_read, shell]），不含通配。`from`、`origin`、`hop`、`caps`、`budget_ref`、`trace` 由内核在投递时写入，调用方传入的值一律忽略。05 信箱表补齐 kind、trace、caps、deadline 等列（现有 kind 列取值映射到 request/reply/notify/control，trust→origin）。

D3 `corr` 由内核在发出请求时生成，不可猜的随机值；落"待回复表"（扩展现有 session_requests）：所属会话、预期回复方、deadline、是否已用。回信到达依次核对：corr 存在、未过期、未用过、发送者 = 预期回复方；只收第一条，其余拒绝并记 guard.denied。`Respond` 另核对 ctx 用户就是被问的那个人（Answer 带 corr）。

D4 守卫放行口：
- GuardRule 返回 Deny / Allow / Abstain；任一 Deny 即拒绝；Allow 只能放开"往 session: 投递"的缺省限制，不能放开联系名单、预算、租户边界。
- 删除"定义的创建者默认可联系"（如需要由定义来源填 owner，模型改不了）。
- `human:` 缺省只能联系本会话的创建者、本轮触发者和成员。
- 会话之间互投 `session:` 缺省只允许同一所属树（父子/派生链），不按定义名放行；跨用户、跨租户须成员组件规则显式放开（仍受 Allow 范围限制）。

D5 一轮只合并同一发送者且同一 budget_ref 的信封；不同发送者分成多轮串行处理。回信（reply）触发的那一轮，caps 沿用原请求那一轮，不被回信方压低；origin 仍合并（任一 external → 本轮 external）。每轮一个主触发者：`Trigger()` 返回主触发者，另加 `Envelopes()` 列出本轮合并的全部信封。记账按主触发者的 budget_ref。

D6 常驻由定义声明 `resident = true`：每个租户只有一个该智能体的会话，不回收，重启后自动恢复。发往 `agent:<名字>` 时内核按固定 id `resident:<租户>/<名字>` 查找，存在就投进去，不存在就创建。常驻会话允许休眠，只是不回收；重启后有待处理信封才唤醒。会话上不再单独放 resident 字段（可派生只读属性）。07 去掉"第一次调用时才启动"，统一要求显式 `Start`。

D7 用户层定义放独立命名空间 `user/<用户>/<名字>`，不能与平台/租户定义同名、不覆盖平台定义，只对本人可见。用户新建定义时 caps 按创建者自己的有效权限截断，运行时再与本轮触发者求交。Resident、预算等 limit 字段同样受租户和用户上限约束。写定义的接口由应用鉴权，模型不能直接调用（结构保证：Registrar 不暴露 SpecStore）。SpecSource 需要能表达用户层。

D8 配置拆成两条链：
| 链 | 顺序 | 何时生效 | 能改什么 |
| 组件配置（运维） | 代码缺省 < ybase.toml < 环境变量 | 启动时（hot 字段除外） | 地址、密钥引用、容量；定义和用户都改不了 |
| 使用配置 [use.*] | 组件缺省 < 定义 < 租户 < 用户 | 创建会话时算好，存进会话 | 这个智能体怎么用组件 |
用户层取会话创建者，不取本轮触发者。例外：标 `limit` 的限制类字段（预算、并发等）守卫每轮按本轮触发者再取最小值。`*Ctx` 加 `Config()` 读取已算好的使用配置。06 示例换掉 memory 组件自带 DSN 的写法（违背"组件不自己连数据库"）。
